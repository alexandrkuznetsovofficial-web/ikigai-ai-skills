# 🏠 НОВОСЕЛЬЕ — твой второй мозг переезжает на сервер

> Этот набор файлов — пошаговый переезд: у тебя уже накоплены MD-файлы (память, наработки, скиллы) на ноутбуке. Появился сервер. Задача — **правильно перенести**, чтобы бот и мозг работали **24/7 без ноутбука**, ты мог делать всё через бота, **и при этом было безопасно**.

## Что важно понять про рамку
Мы не «ставим бота на сервер». Мы **переселяем мозг в новый дом, в который можно зайти откуда угодно** — с ноутбука, с планшета, с телефона. Дом в три этажа:
1. **Этаж 1 — фундамент:** мозг (твои MD) и бот живут на сервере и работают сами, 24/7.
2. **Этаж 2 — дверь:** ты безопасно заходишь на сервер откуда угодно (даже с iPad через браузер).
3. **Этаж 3 — замки:** сервер защищён, но **ты сам себя не запираешь снаружи**.

## 🎯 3 инварианта (должны выполниться у каждого, какая бы ни была система)
1. **Автономность** — мозг + бот работают 24/7 без твоего ноутбука.
2. **Доступ** — заходишь на сервер с ноута И с планшета/телефона.
3. **Безопасность без самоблокировки** — закрыт от чужих, но ты сам всегда внутри (есть «аварийный люк»).

Урок не считается сделанным, пока не выполнены все три.

## Как этим пользоваться (Claude Code или Codex в VS Code)
Ты не делаешь это руками в терминале. Ты **открываешь Claude Code (или Codex) в VS Code** и даёшь ему файл-инструкцию — он сам определит твою среду и сделает шаги. Главный принцип кита — **detect-then-branch**: агент сначала смотрит, что у тебя (Mac/Windows, Claude/Codex, где лежат MD, как запущен бот), говорит «вижу: {твоя среда}», и дальше идёт по правильной ветке. Не предполагает «как у соседа».

## Слои (важно): База → Надстройки (ставятся поверх, не переламывая)
- 🟩 **БАЗА (всем):** заходишь на сервер **с компьютера**, мозг перенесён, **Telegram-бот работает 24/7**. Этого достаточно, чтобы делать задачи через бота.
- 🟦 **НАДСТРОЙКА 1 (рекомендуется):** безопасный доступ (Tailscale) — ставится поверх базы.
- 🟦 **НАДСТРОЙКА 2 (кому нужно):** вход в VS Code **с телефона/планшета** через туннель — отдельный стил, ставится поверх, ничего не ломает.

Принцип: каждая надстройка **добавляется**, а не заставляет перестраивать всё заново. Не нужна — не ставишь.

## ✅ Совместимость (проверено)
- **Windows и Mac — оба ок.** Агент работает по detect-then-branch: сам определяет ОС и берёт правильный путь (авто-коммит: launchd на Mac / Планировщик задач на Windows / cron на Linux). Единственное различие при входе на сервер: на Mac/Linux — `ssh`/`sshpass`; на **Windows** — встроенный `ssh` (OpenSSH в PowerShell) или WSL. Агенту это сказано, он подставит нужное.
- **Claude Code и Codex — оба ок.** Инструкции написаны «для агента» — он выполняет shell-шаги, поэтому не зависят от того, Claude у тебя или Codex. Различается только: (1) какой ключ/логин у провайдера, (2) как ты запускаешь агента (`claude` или `codex`). Сами шаги переезда идентичны.
- **Сервер x86_64 и ARM** — учтено (агент берёт правильный бинарь по `uname -m`).

## 🔒 4 правила безопасности — заучить ДО переезда (дорого куплены)
1. **Ключи и пароли — НИКОГДА в коде и НИКОГДА в файлах памяти.** Только в `~/.config/<твоё>/` или в `.env` с правами `600`. (Если токен лежит в MD-памяти — он попадёт в бэкап, в git, в RAG. Это утечка.)
2. **Если делаешь эндпоинт, который зовёт платную модель наружу — ставь «турникет»** (проверка origin + лимит запросов + дневной потолок). Открытый AI-эндпоинт = скрипт за ночь сожжёт всю твою подписку.
3. **Доступ к данным — только из проверенной сессии,** не из того, что прислал клиент в запросе (никаких «кто я» из параметра `?username=`).
4. **Не запирай себя:** жёсткий хардненинг (бан-машина + смена порта) уже залочивал людей наглухо. Мы идём через **Tailscale** (доступ без открытых портов) + держим **VNC-люк хостера** как страховку.

## Философия (почему так)
Это в духе подхода Карпаты: **своё, минимальное, хакабельное, под твоим контролем**. Не арендованная платформа, которая завтра поднимет цену или закроется, — а твой дом, твой мозг, твои данные, к которым ты сам имеешь ключ. Сервер + агент = твоя личная «ОС», которая работает на тебя 24/7.
