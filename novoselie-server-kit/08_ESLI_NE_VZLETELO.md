# 🆘 Если не взлетело — симптом → причина → что сделать

> Открой, если что-то застряло. Большинство затыков — из этого списка. Начни с двух команд: скажи Claude *«Запусти brain-link status»* — он покажет состояние синка, бота и сервера. Потом найди свой симптом ниже и дай агенту нужную строку.

## Файл доступа

**Симптом: агент просит IP или пароль прямо в чат.**
→ Причина: агент не знает про Файл доступа (например, начали с середины кита).
→ Фикс: ответь: *«Не проси данные в чат. Возьми их из моего Файла доступа: Mac — `~/.config/brain/server_access`, Windows — `%USERPROFILE%\.config\brain\server_access`. Если файла нет — создай по модулю 01, открой мне, дождись „готово“ и проверь значения.»*

**Симптом: brain-link предупреждает про «старые ключи» или старый путь.**
→ Причина: файл заполнен по старому шаблону (`IP`, `LOGIN`, `PORT`, `CLAUDE_TOKEN`) или лежит в `%USERPROFILE%\.secrets\brain\server_access.txt`.
→ Фикс: скажи *«перенеси мой Файл доступа на новые ключи SERVER_IP / SERVER_USER / SERVER_PORT / BOT_TOKEN / USER_ID / PASSWORD и в новое место; строку CLAUDE_TOKEN не переноси и удали»*. Токен подписки больше в файле не хранится — его выпускает `brain-link put-token claude`.

**Симптом: «значения не проходят проверку».**
→ Причина: поля после `=` пустые, остались угловые скобки `<...>` или вписан пример.
→ Фикс: вставь настоящие значения из письма хостера сразу после `=`. Пароль — целиком и как есть, любые символы в нём нормальны. Сохрани (Cmd+S / Ctrl+S) и напиши «готово».

## Подключение к серверу

**Симптом: на шаге `keys` после ввода пароля — `Permission denied`.**
→ Причина: лишний пробел или неполностью скопированный пароль.
→ Фикс: скопируй пароль root из менеджера паролей заново и введи команду ещё раз. При вводе пароль не виден — это нормально.

**Симптом: соединение висит или «connection refused».**
→ Причина: сервер выключен, не тот IP или порт.
→ Фикс: проверь в личном кабинете хостера, что сервер запущен, сверь `SERVER_IP` и `SERVER_PORT` (обычно 22) в Файле доступа.

**Симптом: brain-link пишет, что «сменился ключ сервера», и останавливается.**
→ Причина: на этот адрес отвечает другая машина. Чаще всего ты сам переустановил сервер или хостер выдал новый на том же адресе. Реже — кто-то подменил сервер, именно от этого защищает закреплённый ключ.
→ Фикс: **переустанавливал сервер сам** — скажи Claude: *«Я переустанавливал сервер, закрепи новый ключ»*, он повторит шаг `keys`. **Не переустанавливал** — ничего не подтверждай, напиши в чат потока.

**Симптом: на Windows `ssh` «не является внутренней или внешней командой».**
→ Причина: не включён встроенный клиент OpenSSH.
→ Фикс: попроси Claude: *«Включи мне встроенный клиент OpenSSH в Windows и проверь `ssh -V`»*.

## Синк (`brain-sync`)

| Симптом | Причина | Что делать |
|---|---|---|
| «Запомни» не приехало, правки не уезжают, в `brain-link status` — **пауза** | синк поставлен на паузу (`brain-sync pause`) перед массовой правкой и не включён обратно | скажи Claude: *«brain-sync resume, потом brain-sync run»* |
| **Mac:** в журнале синка `Operation not permitted`, расписание стоит, а синк не идёт | macOS не даёт фоновым задачам читать папку `Documents` (и `Desktop`, `Downloads`) | 1) «Системные настройки» → «Конфиденциальность и безопасность» → «Полный доступ к диску» → добавь `python3`, которым запускается синк (путь скажет Claude); **или** 2) перенеси папку второго мозга из `Documents`, например в `~/SecondBrain`, и повтори шаг `schedule` |
| **Windows:** синк не идёт по расписанию | задача `Ikigai brain-sync` не создана, отключена или компьютер был выключен | скажи Claude: *«Проверь задачу Ikigai brain-sync в Планировщике и запусти brain-sync run вручную»*. 🧪 Путь Windows пока по документации — идём медленнее и сверяемся |
| Рядом с заметкой файл `….conflict-server-…` или `….conflict-local…` | одну заметку поменяли с двух сторон | ничего не потеряно: обе версии на месте. Разбор — модуль [04](04_ISTINA_I_BEKAPY.md), Часть 2 |
| Синк остановился: «**слишком много удалений**» | за один прогон больше 25 удалений или больше 10 % папки | удалял случайно — верни файлы из локальной истории git (модуль 04, Часть 4). Удалял осознанно — *«brain-sync run --allow-mass-delete»* |
| Предупреждение «**часы расходятся**» | время на сервере уехало, чаще всего после «заморозки» сервера у хостера | скажи Claude: *«Выполни на сервере `sudo brain-admin timesync-restart` и проверь часы»*. Данные не страдают: синк сравнивает содержимое, а не время |
| Уведомление на рабочем столе «синк не прошёл 3 раза подряд» | нет интернета, сервер недоступен или одна из причин выше | `brain-link status` → найди причину в этой таблице |
| Бот пишет «синка не было больше суток» | компьютер был выключен или синк сломан | включи компьютер или найди причину в этой таблице; заметки из бота дождутся на сервере |

## Бот

**Симптом: бот молчит совсем.**
→ Причина: сервис не запущен, пустой `USER_ID` (бот без владельца не запускается) или лимит памяти.
→ Фикс: *«Запусти brain-link status и покажи, что с ботом и последние строки его журнала»*. Перезапуск бота — `sudo brain-admin restart-bot`, его журнал — `sudo brain-admin logs`.

**Симптом: в журнале `Conflict: terminated by other getUpdates`.**
→ Причина: тот же бот запущен где-то ещё — старая копия на ноутбуке или старый сервис на сервере.
→ Фикс: найди и выключи второй экземпляр. Старый бот на сервере шаг `bot` должен был отключить — запусти шаг `bot` ещё раз.

**Симптом: бот отвечает «в общем», не из памяти.**
→ Причина: копия памяти не доехала (синк на паузе или сломан) или нужное лежит в исключённой папке (`personal/`, `private/` боту не видны — так и задумано).
→ Фикс: проверь `/status` (когда был синк) и раздел «Синк» выше.

**Симптом: «мозг недоступен» / ошибка входа в подписку.**
→ Причина: токен подписки на сервере протух или отозван.
→ Фикс: заново `brain-link put-token claude` — сам, в своём терминале (модуль 02, Шаг 3). Токен в чат не присылай. `ANTHROPIC_API_KEY` не ставь: это платный счётчик.

**Симптом: «Credit balance is too low».**
→ Причина: где-то появился `ANTHROPIC_API_KEY`, и он перебил подписку. Это не поломка подписки — бот ушёл на платный счётчик.
→ Фикс: *«Найди ANTHROPIC_API_KEY на сервере и на компьютере, покажи где и убери»*, потом `brain-link verify` (пункт 6).

## Лимиты подписки (429)

**Симптом: бот или Claude отвечают «лимит», «429», «rate limit».**
→ Причина: кончился лимит подписки на текущее окно. **Подписка одна, входа два**: Claude на компьютере и бот на сервере тратят один и тот же лимит. Opus тратит его быстрее, особенно на тарифе Pro.
→ Фикс: подожди, пока лимит восстановится; реже пользуйся `/deep` (Opus) в боте; тяжёлую работу на компьютере не совмещай с длинными разговорами в боте. У бота есть свой предохранитель — не больше 30 вызовов в час.
→ Если 429 идут постоянно, даже после паузы, — проверь, что твои собственные скрипты зовут модель через `claude -p`, а не напрямую через API с токеном подписки. Такой путь не поддерживается и отдаёт 429 всегда.

## Доступ / самоблокировка

**Симптом: после `lockdown` или правки файрвола не можешь зайти на сервер.**
→ Причина: вход по ключу не сработал, а пароль уже закрыт. Обычно `lockdown` сам откатывает настройки, если новый вход не прошёл. Если всё же заперся:
→ Фикс: открой **VNC-консоль** в личном кабинете хостера (работает, даже когда ssh закрыт), войди как `root` с паролем из менеджера паролей и попроси Claude продиктовать по одной команды, чтобы вернуть настройки из копии `.bak`. На будущее: `lockdown` — только при открытом втором терминале и проверенном VNC.

**Симптом: страница входа (GitHub, Claude, Microsoft) не открывается.**
→ Причина: сетевое ограничение у тебя или у сервиса.
→ Фикс: проверь, открывается ли страница в обычном браузере; не открывается — напиши в чат потока, разберём на уроке. Обходить региональные ограничения сервисов мы не учим.

## GitHub

**Симптом: `git push` из папки мозга падает или замок `pre-push` пишет `[guard] СТОП`.**
→ Это защита сработала. Память (`memory/`, `personal/`, `sessions/`, диалоги) в GitHub не отправляется никогда. Убери у папки мозга облачный адрес (`git remote remove origin`). Бэкап памяти — локальная история git (модуль 04).
→ Отправляешь код или скиллы (без памяти) из отдельной папки — вход `gh auth login --web`, через браузер. Пароль GitHub и коды 2FA агенту не присылай.

**Симптом: имена файлов с кириллицей ломаются (Windows / git / архив).**
→ Фикс: попроси агента переименовать на латиницу, русское название — первой строкой файла.

## Агент «сказал готово», а ничего нет

→ Причина: агент не проверил результат или упёрся в лимит контекста.
→ Фикс: требуй доказательство — пусть вставит реальный вывод `brain-link status` или `brain-link verify`, а не пересказ «по памяти». Кончился контекст — начни новый чат, дай ему этот файл и скажи, на каком шаге остановились.

## Куда писать, если совсем застрял

Не починилось за 2 попытки — не сиди в одиночку. Напиши в чат потока с пометкой `#застрял`: симптом, на каком шаге, вывод `brain-link status` (без IP, токенов и паролей).
