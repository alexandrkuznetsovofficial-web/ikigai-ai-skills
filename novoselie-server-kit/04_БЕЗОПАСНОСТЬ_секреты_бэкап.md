# 🔒 Этаж 3 — Замки: секреты, бэкап, не запереть себя

> Замки ставим ПОСЛЕ того, как нашёл аварийный VNC-люк (файл `03`, часть C). Сначала страховка — потом замки. Даёшь файл агенту.

## 1. Секреты — где можно и где нельзя
**Правило:** ключ/токен/пароль живёт ТОЛЬКО в одном из двух мест:
- `.env` рядом с ботом, права `600`, исключён из git;
- `~/.config/<твоё>/` или `/opt/brain/.secrets/`, права `600`/`700`.

❌ **Нельзя:** хардкодить в `.py`/`.js`; писать в MD-файлы памяти; коммитить в git; вставлять в чат.
> Почему серьёзно: токен в коде или в памяти попадает в git-историю, в бэкап и в RAG-индекс — и остаётся там навсегда, даже если потом удалить строку. Тогда единственное лекарство — **ротация** (сменить ключ), что больно. Проще сразу не пускать.

**Проверка (через агента):**
```
grep -rIuln -e 'sk-' -e 'token *=' -e 'password *=' -e '[0-9]\{8,\}:[A-Za-z0-9_-]\{30,\}' /opt/brain --include=*.py --include=*.md
```
Нашёл реальный секрет в коде/MD → вынеси в `.env`, замени в коде на чтение из окружения, при сомнении — **смени (ротируй) этот ключ**.

## 2. Файрвол — мягко (без самоблокировки)
С Tailscale публичный SSH вообще не нужен:
- `ufw default deny incoming; ufw default allow outgoing`
- `ufw allow in on tailscale0` (доступ только через свою Tailscale-сеть)
- если есть веб-сайт: `ufw allow 80,443/tcp`
- **НЕ делай** агрессивный fail2ban + смену порта + whitelist по IP на нетехническом сервере — это и есть то, что запирает людей. Tailscale решает доступ без этого.
- `ufw enable` — **только убедившись, что Tailscale-вход уже работает И VNC-люк проверен** (файл 03).
- **Чек-точка:** после `ufw enable` ты всё ещё заходишь через Tailscale; VNC-люк на месте.

## 3. Бэкап — правило «3 копии, 1 вне сервера»
- Память: уже в git + приватный GitHub (файл `02`, шаг 6) = копия вне сервера. ✅
- База/состояние бота (если есть `.db`/`.session`): ежедневный дамп + копия в облако.
  - Просто: `restic` в облачный бакет, или `rclone copy` на Я.Диск/Google Drive.
  - Минимум: `cron` → `cp` в `/opt/backups/` + `git push` отдельного приватного репо бэкапов (БЕЗ секретов) или `rclone`.
- **Правило «бэкап, который не восстанавливали — не бэкап»:** раз в месяц скачай последний бэкап на ноут и проверь, что разворачивается.
- **Чек-точка:** есть свежий бэкап вне сервера И ты однажды успешно его развернул на тест-копии.

## 4. Если делаешь AI-эндпоинт наружу — «турникет» (anti-token-drain)
Открытый эндпоинт, который зовёт платную модель за каждый вызов = скрипт за ночь сожжёт твою подписку (а подписка — единая точка отказа всего). Минимум 4 уровня:
1. **Origin/Referer** — принимать только со своей страницы.
2. **Валидация ввода** — мусор отсекать ДО вызова модели.
3. **No-data-skip** — нечего обрабатывать → не звать модель (0 токенов впустую).
4. **Rate-limit по IP + дневной потолок** генераций.
- Тест на масштаб: «10 000 вызовов за ночь скриптом — исчерпаю подписку?» Если да — турникет не поставлен.

## 5. Доступ к данным — только из проверенной сессии
Любой эндпоинт, отдающий/меняющий данные пользователя, берёт «кто я» из **аутентифицированной сессии**, а не из `?username=`/тела запроса. Иначе любой подставит чужой id и получит/испортит чужое.

## 6. Сам себя не запирай (свод)
- Сначала рабочий Tailscale-вход + проверенный VNC-люк → потом любые замки.
- Меняешь что-то в SSH/файрволе — держи **вторую открытую сессию** как страховку, проверь новый вход ДО закрытия старого.
