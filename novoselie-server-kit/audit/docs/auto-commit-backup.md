# 🛡 Авто-коммиты: страховка твоего второго мозга

> **Файл-установщик для Claude. Участник ничего не делает руками — просто загрузи этот файл в чат VS Code и напиши: «Настрой мне авто-коммиты по этому гайду».**
>
> **Что нового в версии 2.0.** Память теперь хранится только у тебя: снимки делаются на компьютере, а в GitHub память не отправляется никогда — это держат правила git и проверка перед отправкой. GitHub остаётся только для кода и скиллов, вход через браузер. Если ты ставил версию 1.0 — скилл сам найдёт старые настройки и предложит, что поправить (Шаг 1).

---

## Зачем это нужно (прочитай, это важно)

Сейчас у тебя **одна копия** твоего второго мозга — на одном ноутбуке, без истории версий. Это значит:

- Claude в эксперименте перезапишет файл — старая версия исчезнет навсегда
- Страшно экспериментировать, потому что «сломаю и не починю»

Этот скилл решает это одной установкой: **каждые 30 минут компьютер сам делает снимок (commit) всех твоих рабочих папок**. Так работает система Александра — теперь будет и у тебя. Любую поломку можно откатить одной фразой: *«Откати последний коммит, верни рабочую версию»*.

**Почему память не уходит в облако.** Во втором мозге — заметки о тебе, твоих людях, деньгах, здоровье, диалоги с Claude. Приватный репозиторий на GitHub однажды открывают по ошибке, а из истории git отправленное почти невозможно вычистить. Поэтому правило потока такое же, как у Александра: **память — только дома, GitHub — только для кода и скиллов.** От потери ноутбука защищает штатный бэкап компьютера (Time Machine на Mac, «История файлов» на Windows), а у тех, кто перенёс мозг на сервер, — снимки на сервере и ночное зеркало сервер → компьютер (кит «Новоселье», модуль 04).

## ИНСТРУКЦИЯ ДЛЯ CLAUDE

Ты — установщик системы автоматических коммитов. Выполни шаги по порядку. Работай сам, у пользователя спрашивай только то, что указано. Пользователь не использует терминал — все команды выполняешь ты.

> 🧭 **Формула бэкапа kit 2.0 (одна на весь набор):** у мозга облака нет; локальный git хранит всё,
> включая `personal/`; в облако не пускает хук `pre-push`; `.gitignore` мозга — только секреты и мусор.

> 🔴 **Три правила на всю работу скилла — и во всех будущих сессиях:**
> 1. **Память в GitHub не отправляется никогда.** Ни `memory/`, ни `personal/`, ни диалоги, ни карточки людей — ни в публичный, ни в приватный репозиторий. У папки второго мозга нет облачного адреса (`remote`).
> 2. **Пароли, email вместе с паролем, коды восстановления двухфакторки (2FA) и скриншоты экрана входа ты не просишь, не принимаешь и не сохраняешь.** Вход в GitHub — только `gh auth login --web`: человек сам входит в браузере, модель его данных не видит. Если человек всё же прислал такое в чат — не сохраняй, не повторяй в ответе и сразу предложи блок «Если ты уже присылал пароль» (Шаг 1.4).
> 3. **Ничего необратимого сам.** Удаление репозиториев, переписывание истории git, смена паролей, удаление файлов — только по явному «да» человека, после того как ты показал, что именно произойдёт.

### Шаг 0. Определи окружение

1. **Прочитай профиль компьютера** — `~/.claude/ikigai_env.json` (его пишет скилл `ikigai-preflight`).
   Файла нет или он старше 30 дней — запусти `bash ~/.claude/skills/ikigai-preflight/scripts/probe.sh`.
   **Пробника тоже нет** (у многих участников его нет) — определи систему сам: `uname -s` (`Darwin` → mac, `Linux` → linux, `MINGW…` / `MSYS…` → windows).
   Поле `os_branch` (`mac` / `windows` / `linux`) определяет, какую колонку команд брать дальше.
   🔴 На Windows человеку не показывай команды с `chmod`, `bash`, `~`, `brew`, `launchctl` — он решит, что сломался он.

| Что | Mac | Windows (Claude Code выполняет команды через Git Bash) |
|---|---|---|
| Установить git | `xcode-select --install` (выскочит окно — нажать «Установить») | `winget install --id Git.Git -e --source winget`, потом перезапустить сессию |

| Права на файлы хуков | `chmod +x` | не нужно |
| Бэкап всего компьютера | Time Machine | «История файлов» |

Команды `git …` одинаковые на обеих системах.

2. Проверь, установлен ли git (`git --version`). Нет — поставь по таблице.
3. **Всегда** проверь настройку git (даже если git давно установлен — он может быть ни разу не настроен, тогда все коммиты будут молча падать):
   ```
   git config --global user.name
   git config --global user.email
   ```
   Если что-то пустое — настрой:
   ```
   git config --global user.name "<имя пользователя>"
   git config --global user.email "<username>@local"
   ```
   Имя возьми из контекста (CLAUDE.md, memory) или спроси. Для локальных снимков настоящий email не нужен — `username@local` достаточно.

### Шаг 1. Если скилл уже стоял раньше (версия 1.0) — сначала проверка

Признаки старой установки: есть `~/scripts/auto_commit_backup.sh` (Windows: `%USERPROFILE%\scripts\auto_commit_backup.ps1`), задача расписания со **старым** именем из таблицы выше (Mac — `com.user.auto-commit-backup`, Windows — `AutoCommitBackup`), в скрипте есть строка `git push`, есть файл `~/.secrets/github_credentials.md` (Windows: `%USERPROFILE%\.secrets\github_credentials.md`). Ничего из этого нет — переходи к Шагу 2.

**1.1. Поставь расписание на паузу**, пока идёт проверка, — иначе фоновый коммит или отправка унесут промежуточное состояние:

| Mac | Windows |
|---|---|
| `launchctl unload ~/Library/LaunchAgents/com.user.auto-commit-backup.plist` | `powershell -NoProfile -Command "Disable-ScheduledTask -TaskName 'AutoCommitBackup'"` |

Старая задача на паузе до конца проверки. Новая (с именем `com.ikigai.auto-commit-backup` / `Ikigai auto-commit-backup`)
ставится в Шаге 5, а старая убирается в Шаге 6, пункт 5а, — **только после того, как новая проверена**. Не забудь — это часть миграции.

**1.2. Есть ли у папок второго мозга облачный адрес.** В каждой папке из старого скрипта: `git remote -v`.
- Пусто — облака не было, хорошо.
- Есть адрес — покажи его человеку и объясни: «С этой папки снимки уходили в GitHub. В новой версии память в облако не отправляется. Предлагаю убрать облачный адрес у этой папки: на компьютере ничего не удалится, в GitHub тоже — просто отсюда больше ничего не уйдёт. Убираем?» По «да» — `git remote remove origin`. Потом — проверка 1.3.

**1.3. Как проверить, что в истории GitHub нет памяти.** Только для папок, у которых в 1.2 был облачный адрес. Пока адрес ещё на месте (или по адресу, который ты показал человеку), проверь, что лежит в облаке:
```
git fetch origin
git log --remotes --oneline -- memory/ personal/ sessions/ dialogues/ .secrets/ | head -20
```
Вместе с локальной историей это же показывает `git log --all --oneline -- memory/` — локальные снимки памяти там нормальны, важна именно облачная часть (`--remotes`).
- Пусто — в облаке памяти нет. Запиши человеку: «проверено, в GitHub памяти нет».
- Есть строки — память уже в GitHub. **Ничего не удаляй сам.** Сначала узнай, приватный ли репозиторий: `gh repo view <владелец>/<имя> --json visibility` (нужен вход из Шага 7.2; без него — попроси человека открыть страницу репозитория в браузере и сказать, есть ли рядом с именем надпись «Private»). Публичный — скажи это первой строкой, это срочно. Затем предложи выбор:
  - **а) Удалить облачный репозиторий целиком** (проще и надёжнее). Делает человек сам на сайте: репозиторий → Settings → внизу «Delete this repository». Локальная история на компьютере остаётся. Облачный адрес у папки мозга уже убран (1.2), поэтому старая история в облако не вернётся. Если человеку нужен GitHub для скиллов — для них заводим **новый** репозиторий в отдельной папке (Шаг 7), а не в папке мозга.
  - **б) Переписать историю** — только для тех, кто уверенно работает с git и понимает, что это необратимо. Ты не делаешь это сам, а показываешь, что потребуется, и ждёшь отдельного «да» на каждую команду.
  - **в) Оставить как есть**, если репозиторий приватный и человек осознанно так решил. Запиши его решение в `memory/MEMORY.md` одной строкой с датой.

**1.4. Если ты уже присылал пароль.** Признаки: есть файл `~/.secrets/github_credentials.md` или человек вспоминает, что отправлял в чат пароль, коды восстановления 2FA или скриншоты. **Файл не открывай и содержимое не выводи.** Скажи человеку:

> «Раньше этот скилл просил прислать пароль GitHub и коды 2FA в чат. Так больше не делаем: всё, что прошло через чат, сохранилось в расшифровках диалогов на компьютере и побывало у провайдера модели. Давай обезопасим аккаунт — это 10 минут, всё делаешь ты сам в браузере, мне ничего присылать не нужно:
> 1. **Перевыпусти коды 2FA:** github.com → Settings → Password and authentication → Recovery codes → «Generate new recovery codes». Старые перестанут работать. Новые сохрани в менеджере паролей или распечатай — **не присылай мне и не клади в папку второго мозга**.
> 2. **Смени пароль GitHub:** там же, раздел «Change password». Если этот пароль стоял ещё где-то — смени и там.
> 3. **Удалим старый файл с доступами** на компьютере — скажи «да», и я его удалю.
> 4. **По желанию — почистим старые диалоги**, где пароль упоминался: найду их и покажу список файлов (без содержимого), удалю только по твоему «да».»

По «да» на пункт 3: Mac — `rm ~/.secrets/github_credentials.md`; Windows — `Remove-Item "$env:USERPROFILE\.secrets\github_credentials.md"` (через `powershell -NoProfile -Command`). По «да» на пункт 4: найди файлы диалогов, где встречается логин GitHub человека (`grep -l` по `~/.claude/projects/*/*.jsonl`), покажи **только имена файлов и даты**, удаляй по одному после подтверждения.

### Шаг 3. Подготовь каждую папку (КРИТИЧНО — безопасность)

Для каждой папки из списка:

1. Если git-репозиторий не инициализирован — `git init`.
2. **Обязательно** создай или дополни `.gitignore` — до первого коммита. Не перезаписывай чужие строки, только добавь недостающие.
   По формуле kit 2.0 в `.gitignore` мозга — **только секреты и мусор**. Память и личное сюда не пишутся: их хранит локальная история, а в облако не пускает `pre-push`.
   ```
   # секреты — не в git вообще, даже локально
   .env
   *.env
   *.session
   .secrets/
   # служебное и тяжёлое — пересобирается само
   __pycache__/
   node_modules/
   logs/
   *.log
   rag_db/
   brain-rag/
   *.bak*
   .DS_Store
   ```
   Остальная память (`memory/`, включая `personal/`, `sessions/`, `dialogues/`, `insights/profiles/`, `raw/`) **остаётся в локальных снимках** — ради неё всё и затевается. В облако она не уйдёт: это держит хук из пункта 6.
   Если в старом `.gitignore` мозга стоят строки `memory/`, `personal/` и т. п. (так советовала версия 1.0) — личное сейчас **не попадает даже в локальные снимки**. Покажи эти строки человеку и предложи убрать: «бэкап должен хранить и личное — в облако его не пустит замок на отправку». Убирай только по «да».
3. **Если `.gitignore` правился в уже существующем репозитории** — git продолжает следить за файлами, которые попали в историю раньше. Сними их с учёта (файлы остаются на диске):
   ```
   git rm -r --cached --ignore-unmatch .secrets rag_db brain-rag
   git ls-files | grep -i -E '(^|/)\.secrets/|(^|/)rag_db/|(^|/)brain-rag/|\.bak|\.env$|\.session$'
   ```
   Вторая команда должна вывести **пусто**. Найдены `.bak`-файлы — сними их так же, по одному: `git rm --cached -- "<файл>"`.
   🔴 Не проверяй это через `git check-ignore` на несуществующем файле — такая проверка всегда «зелёная» и ничего не доказывает.
4. **Скан на секреты** перед первым коммитом:
   ```
   grep -rlE "sk-ant-|[0-9]{8,10}:AA[A-Za-z0-9_-]{30,}|password\s*[:=]" . --exclude-dir=.git
   ```
   Найдены файлы с реальными ключами вне `.env` — покажи человеку **список файлов** (не содержимое) и спроси, что с ними делать (перенести в `.env` / в `.gitignore`). НЕ коммить, пока не решено.
5. Сделай первый коммит: `git add -A && git commit -m "initial backup"`. Ответ «nothing to commit» (папка уже была чистым репозиторием) — норма, иди дальше.
6. **Поставь замок на отправку** — хук `pre-push`. Он запрещает отправлять куда-либо снимки, в которых есть память или личное. Даже если когда-нибудь у папки появится облачный адрес, память не уйдёт.

   Файл `.git/hooks/pre-push` в этой папке. Если там **уже есть свой файл** без строки `ikigai guard` — не затирай: покажи человеку и спроси. Содержимое (одно и то же для Mac и Windows — Git для Windows сам запускает такие файлы, окончания строк должны быть LF):
   ```sh
   #!/bin/sh
   # ikigai guard v2.0 — pre-push: память и личное не уходят в облако
   PAT='(^|/)(memory|personal|personal_notes|private|secrets?|\.secrets|sessions|dialogues|family|health|finance|finances|rag_db|brain-rag|raw|\.claude/projects)(/|$)|(^|/)insights/profiles(/|$)|\.bak|\.env$|\.session$|(Л|л)(И|и)(Ч|ч)(Н|н)|(С|с)(Е|е)(М|м)(Ь|ь)|(З|з)(Д|д)(О|о)(Р|р)(О|о)(В|в)|(Ф|ф)(И|и)(Н|н)(А|а)(Н|н)(С|с)'
   BAD=""
   while read -r lref lsha rref rsha; do
     case "$lsha" in *[!0]*) ;; *) continue ;; esac
     case "$rsha" in *[!0]*) range="$rsha..$lsha" ;; *) range="$lsha" ;; esac
     B=$( { git -c core.quotepath=off log --name-only --format= $range 2>/dev/null
            git -c core.quotepath=off ls-tree -r --name-only "$lsha"; } | grep -i -E "$PAT" | sort -u )
     [ -n "$B" ] && BAD="$BAD$B
   "
   done
   if [ -n "$BAD" ]; then
     echo "[guard] СТОП: в отправке есть память или личное. В облако это не уходит:" >&2
     printf '%s' "$BAD" | head -20 >&2
     exit 1
   fi
   exit 0
   ```
   Mac: `chmod +x .git/hooks/pre-push`. Windows: ничего не нужно.

   Про шаблон `PAT`: он ловит английские папки (`memory`, `personal`, `personal_notes`, `private`, `family`, `health`, `finance` …) без учёта регистра (`grep -i`) и русские корни «личн», «семь», «здоров», «финанс» в **любом** регистре — `ЛИЧНОЕ/`, `Семья/`, `здоровье/`. Русские буквы записаны парами `(Л|л)`, а не через `-i`: в Git для Windows и в фоновых задачах `grep -i` кириллицу не сравнивает без учёта регистра, а пара работает в любой системе.

   Почему здесь замок на **отправку**, а не на коммит: локальные снимки памяти — это и есть бэкап, их блокировать нельзя. Запрещено только одно — вынести их за пределы компьютера.

> **🔒 Железное правило (запомни и соблюдай во всех будущих сессиях):** у папки второго мозга нет облачного адреса. В GitHub никогда не попадают память, личное, диалоги, карточки людей, пароли, API-ключи, `.env`, персональные данные клиентов и других людей.

### Шаг 4. Создай скрипт авто-коммита

Скрипт только делает снимки. **Отправки в облако в нём нет.** Если ставишь поверх версии 1.0 — сохрани старый скрипт рядом с окончанием `.v1` (не удаляй) и запиши новый.

**macOS** — файл `~/scripts/auto_commit_backup.sh`:

```bash
#!/bin/bash
# Авто-коммит рабочих папок каждые 30 минут. Только локально — без отправки в облако.
export GIT_TERMINAL_PROMPT=0   # фоновый git никогда не спрашивает логин — иначе зависнет
FOLDERS=(
  "<папка 1>"
  "<папка 2>"
)
LOG="$HOME/Library/Logs/auto_commit_backup.log"

for DIR in "${FOLDERS[@]}"; do
  [ -d "$DIR/.git" ] || continue
  cd "$DIR" || continue
  git add -A
  if ! git diff --cached --quiet; then
    git commit -m "auto-backup $(date '+%Y-%m-%d %H:%M')" >> "$LOG" 2>&1
  fi
  # сторож: у папки мозга не должно быть облачного адреса
  git remote | grep -q . && echo "[$(date '+%F %T')] ВНИМАНИЕ: у $DIR есть облачный адрес — проверь по скиллу auto-commit-backup, Шаг 1" >> "$LOG"
done
echo "[$(date '+%Y-%m-%d %H:%M:%S')] done" >> "$LOG"
```

Сделай исполняемым: `chmod +x ~/scripts/auto_commit_backup.sh`.

**Windows** — файл `%USERPROFILE%\scripts\auto_commit_backup.ps1`:

```powershell
# Авто-коммит рабочих папок каждые 30 минут. Только локально — без отправки в облако.
$env:GIT_TERMINAL_PROMPT = "0"   # фоновый git никогда не спрашивает логин — иначе зависнет
$folders = @(
  "<папка 1>",
  "<папка 2>"
)
$log = "$env:USERPROFILE\auto_commit_backup.log"

foreach ($dir in $folders) {
  if (-not (Test-Path "$dir\.git")) { continue }
  Set-Location $dir
  git add -A
  $changes = git diff --cached --name-only
  if ($changes) {
    git commit -m "auto-backup $(Get-Date -Format 'yyyy-MM-dd HH:mm')" *>> $log
  }
  # сторож: у папки мозга не должно быть облачного адреса
  if (git remote) { Add-Content $log "[$(Get-Date -Format 'yyyy-MM-dd HH:mm:ss')] ВНИМАНИЕ: у $dir есть облачный адрес — проверь по скиллу auto-commit-backup, Шаг 1" }
}
Add-Content $log "[$(Get-Date -Format 'yyyy-MM-dd HH:mm:ss')] done"
```

Подставь реальные пути папок из Шага 2 вместо `<папка 1>` / `<папка 2>`.

🔴 **Windows: `.ps1` — только UTF-8 с BOM.** Windows PowerShell 5.1 читает файл без BOM в кодировке ANSI:
русские комментарии, сообщения в журнале и путь `C:\Users\Иван\Документы\…` превращаются в кракозябры,
скрипт молча не находит папку и снимков нет. Инструмент записи файлов пишет без BOM — поэтому сразу после
записи пересохрани файл с BOM (то же для любого `.ps1` этого скилла):

```bash
powershell -NoProfile -Command '$p = "$env:USERPROFILE\scripts\auto_commit_backup.ps1"; $t = [IO.File]::ReadAllText($p); [IO.File]::WriteAllText($p, $t, (New-Object Text.UTF8Encoding $true))'
```

Признак: `head -c 3 ~/scripts/auto_commit_backup.ps1 | od -An -tx1` показывает `ef bb bf`.

**Windows** — задача `Ikigai auto-commit-backup` в Планировщике. Три правила, иначе шаг не встанет:
- `schtasks` и сложный PowerShell **не вызывай одной строкой из bash** — Git Bash переписывает аргументы со слешем и кавычки. Пиши команды в файл `.ps1` и запускай файл;
- файл `.ps1` — **UTF-8 с BOM** (как в Шаге 4), иначе путь с кириллицей сломается;
- настройки задачи задаются через `New-ScheduledTaskSettingsSet` с тремя флагами: `-StartWhenAvailable` (компьютер спал — задача догонит после пробуждения), `-AllowStartIfOnBatteries` и `-DontStopIfGoingOnBatteries` (без них ноутбук от батареи снимков не делает). Если задача **уже есть** — не пересоздавай её с нуля, а включи эти три флага в её текущих настройках: остальное, что человек там менял, сохранится.

Создай файл `~/scripts/install_auto_commit_backup.ps1`, пересохрани его с BOM (команда из Шага 4, другой путь) и запусти:

```powershell
$name   = "Ikigai auto-commit-backup"
$script = "$env:USERPROFILE\scripts\auto_commit_backup.ps1"
$task   = Get-ScheduledTask -TaskName $name -ErrorAction SilentlyContinue
if ($task) {
  # задача уже стоит — меняем только три флага, прочие настройки человека не трогаем
  $s = $task.Settings
  $s.StartWhenAvailable = $true
  $s.DisallowStartIfOnBatteries = $false
  $s.StopIfGoingOnBatteries = $false
  Set-ScheduledTask -TaskName $name -Settings $s | Out-Null
} else {
  $action   = New-ScheduledTaskAction -Execute "powershell.exe" -Argument "-NoProfile -WindowStyle Hidden -ExecutionPolicy Bypass -File `"$script`""
  $trigger  = New-ScheduledTaskTrigger -Once -At (Get-Date).AddMinutes(1) -RepetitionInterval (New-TimeSpan -Minutes 30)
  $settings = New-ScheduledTaskSettingsSet -StartWhenAvailable -AllowStartIfOnBatteries -DontStopIfGoingOnBatteries -ExecutionTimeLimit (New-TimeSpan -Minutes 10) -MultipleInstances IgnoreNew
  Register-ScheduledTask -TaskName $name -Action $action -Trigger $trigger -Settings $settings | Out-Null
}
$t = Get-ScheduledTask -TaskName $name
"{0} | StartWhenAvailable={1} | Battery start={2} | Battery stop={3}" -f $t.TaskName, $t.Settings.StartWhenAvailable, (-not $t.Settings.DisallowStartIfOnBatteries), $t.Settings.StopIfGoingOnBatteries
```

```bash

```

Признак: строка `Ikigai auto-commit-backup | StartWhenAvailable=True | Battery start=True | Battery stop=False`.
Если `New-ScheduledTaskTrigger` ругается на `RepetitionDuration` (старые сборки Windows 10) — добавь в триггер
`-RepetitionDuration (New-TimeSpan -Days 3650)`. `python3` на Windows может называться `py -3`.

**Linux / VPS-сервер** — если пользователь работает на виртуальном сервере (или хочет защитить и его):
1. Тот же bash-скрипт, что для macOS, положи в `/opt/scripts/auto_commit_backup.sh` (лог — в `/var/log/auto_commit_backup.log`), `chmod +x`. Хук `pre-push` из Шага 3.6 поставь и в папку мозга на сервере.
2. Расписание через cron (сервер не спит, cron здесь допустим):
   ```
   crontab -l > /tmp/cron_before_$$.txt 2>/dev/null || : ; BEFORE=$(wc -l < /tmp/cron_before_$$.txt)
   grep -q "auto_commit_backup" /tmp/cron_before_$$.txt && echo "УЖЕ СТОИТ — второй раз не добавляем" || {
     cp /tmp/cron_before_$$.txt /tmp/cron_new_$$.txt
     echo "*/30 * * * * /opt/scripts/auto_commit_backup.sh >> /var/log/auto_commit_backup.log 2>&1" >> /tmp/cron_new_$$.txt
     AFTER=$(wc -l < /tmp/cron_new_$$.txt)
     [ "$AFTER" -gt "$BEFORE" ] && crontab /tmp/cron_new_$$.txt || echo "СТОП: новый файл не больше старого, не ставим"
   }
   crontab -l | wc -l   # должно быть на 1 больше, чем BEFORE
   ```
   🔴 Никогда не ставь расписание конструкцией `(crontab -l; echo …) | crontab -`: если `crontab -l`
   отдаст пусто по любой причине, в таблице останется одна строка, а все прежние задачи человека исчезнут.
3. Проверь `git config user.name` на сервере — если пусто, настрой.

> **Важно про VPS:** сервер — это НЕ бэкап, это просто другой компьютер. Хостер может удалить машину, диск может умереть. Копия вне сервера для памяти — **не GitHub**, а **ночное зеркало сервер → твой компьютер** (кит «Новоселье», модуль 04): каждую ночь компьютер сам забирает копию мозга, а штатный бэкап компьютера увозит её дальше.
>
> **Если мозг живёт и на ноутбуке, и на сервере:** истина — в одном месте (у кита «Новоселье» — на сервере), второе место получает копию зеркалом и только читает. Не правь один и тот же файл в двух местах. И помни правило «удалённое возвращается»: удалил что-то в одном месте — проверь и второе.

### Шаг 6. Проверь, что работает

1. Запусти скрипт вручную один раз (Mac — `bash ~/scripts/auto_commit_backup.sh`; Windows — `powershell -NoProfile -ExecutionPolicy Bypass -File "$HOME/scripts/auto_commit_backup.ps1"`).
2. Проверь `git log --oneline -3` в каждой папке — должен появиться коммит `auto-backup ...` (или «initial backup», если изменений с тех пор не было).
3. **Облачного адреса нет:** `git remote -v` в каждой папке мозга выводит пусто.
4. **Замок на отправку работает** — проверь настоящей попыткой отправки во временную папку (в облако ничего не уходит):
   ```
   T=$(mktemp -d) && git init -q --bare "$T/test.git" && git push "$T/test.git" HEAD; echo "код: $?"; rm -rf "$T"
   ```
   Признак: в выводе строка `[guard] СТОП` и `код: 1` (в папке мозга есть память — отправка запрещена). Если в папке мозга отправка прошла — хук не сработал: проверь, что файл `.git/hooks/pre-push` на месте (на Mac — что он исполняемый). В папке без памяти и личного (например, код бота) отправка во временную папку пройдёт — это нормально, там проверяй только, что файл хука на месте.
5. Расписание на месте. Mac: `launchctl list | grep com.ikigai.auto-commit-backup`. Windows: `powershell -NoProfile -Command "Get-ScheduledTask -TaskName 'Ikigai auto-commit-backup' | Select-Object TaskName, State"`.
   Признак для человека: покажи ему строку вывода с именем задачи. Пока строки нет — расписание не встало,
   и говорить «настроено» нельзя.

   **5а. Миграция со старого имени** (если в Шаге 1 нашлась версия 1.0). Только когда новая задача есть в списке
   и ручной запуск из пункта 1 дал коммит, скажи человеку: «Новая задача работает. Убираю старую

   | Mac | Windows |
   |---|---|

### Шаг 7 (по желанию). GitHub — только для кода и скиллов

Облако нужно не памяти, а тому, чем ты делишься или что пишешь как код: свои скиллы, бот, сайт. Спроси человека: **«Хочешь хранить в GitHub свои скиллы или код? Память туда не пойдёт — только они».** Нет — пропусти шаг.

#### 7.1. Отдельная папка, а не папка мозга

1. Облачный репозиторий заводится только для **отдельной папки** с кодом или скиллами (например, папка бота или копия папки скиллов). Не для рабочей папки с `CLAUDE.md` и `memory/` и не внутри неё.
2. Проверь папку перед подключением: в ней нет `memory/`, `personal/`, `sessions/`, `.secrets/`, нет `CLAUDE.md` второго мозга. Есть — **стоп**, объясни человеку и выбери другую папку.

#### 7.2. Аккаунт и вход — человек всё делает сам в браузере

1. Аккаунта нет — открой https://github.com/signup (Mac: `open <ссылка>`; Windows: `start <ссылка>`). Человек регистрируется сам. Подскажи только одно: **«Придумай новый пароль, не от почты, и сохрани в менеджере паролей. Мне его присылать не нужно — я его не прошу и не храню. Включишь двухфакторку — коды восстановления тоже держи в менеджере паролей или распечатай, не в чате и не в папке мозга».**
2. Поставь `gh` (таблица в Шаге 0) и запусти вход через браузер:
   ```
   gh auth login --web --hostname github.com --git-protocol https
   ```
   `gh` покажет одноразовый код и откроет страницу GitHub — человек вводит код в браузере сам. Если команда ждёт нажатия Enter, попроси человека запустить её в терминале VS Code (Mac: Ctrl+\` → вставить → Enter; Windows: так же).
   Признак: `gh auth status` пишет `Logged in to github.com`.

#### 7.3. Замки в облачной папке

1. `.gitignore` облачной папки — всё из Шага 3.2 плюс память и личное:
   ```
   memory/
   personal/
   personal_notes/
   private/
   family/
   health/
   finance/
   sessions/
   dialogues/
   insights/profiles/
   raw/
   rag_db/
   brain-rag/
   .secrets/
   *.bak*
   .env
   *.env
   *.session
   ```
2. Хук `pre-push` — тот же, что в Шаге 3.6.
3. Хук `pre-commit` — снимает память и личное с коммита, а остальное пропускает (автобэкап не падает целиком). Файл `.git/hooks/pre-commit`, правила те же: чужой файл не затирать, окончания строк LF, на Mac `chmod +x`:
   ```sh
   #!/bin/sh
   # ikigai guard v2.1 — pre-commit: снимает память и личное с коммита облачной папки
   PAT='(^|/)(memory|personal|personal_notes|private|secrets?|\.secrets|sessions|dialogues|family|health|finance|finances|rag_db|brain-rag|raw|\.claude/projects)(/|$)|(^|/)insights/profiles(/|$)|\.bak|\.env$|\.session$|(Л|л)(И|и)(Ч|ч)(Н|н)|(С|с)(Е|е)(М|м)(Ь|ь)|(З|з)(Д|д)(О|о)(Р|р)(О|о)(В|в)|(Ф|ф)(И|и)(Н|н)(А|а)(Н|н)(С|с)'
   TAB=$(printf '\t')
   LIST=$(git -c core.quotepath=off diff --cached --name-status --diff-filter=ACMR)
   [ -z "$LIST" ] && exit 0
   HIT=""
   while IFS="$TAB" read -r st p1 p2; do
     [ -z "$st" ] && continue
     case "$st" in
       A*|C*) f="$p2"; [ -z "$f" ] && f="$p1"
              printf '%s\n' "$f" | grep -q -i -E "$PAT" || continue
              git rm -q --cached --ignore-unmatch -- "$f"   # новый файл: убрать из индекса, на диске остаётся
              HIT="$HIT$f
   " ;;
       M*)    printf '%s\n' "$p1" | grep -q -i -E "$PAT" || continue
              git reset -q HEAD -- "$p1"                     # изменённый: вернуть индекс к прошлому снимку, файл не удаляется
              HIT="$HIT$p1
   " ;;
       R*)    printf '%s\n' "$p2" | grep -q -i -E "$PAT" || continue
              git rm -q --cached --ignore-unmatch -- "$p2"  # переименование в личное: новое имя убрать,
              git reset -q HEAD -- "$p1"                     # старое вернуть в индекс как было
              HIT="$HIT$p2
   " ;;
     esac
   done <<EOF
   $LIST
   EOF
   [ -z "$HIT" ] && exit 0
   echo "[guard] сняты с коммита (память и личное в облако не уходят):" >&2
   printf '%s' "$HIT" | head -20 >&2
   git diff --cached --quiet && { echo "[guard] после этого коммитить нечего" >&2; exit 1; }
   exit 0
   ```
   🔴 Почему по-разному. **Новый** файл (`A`) снимается с учёта: `git rm --cached` — файл на диске остаётся, в снимок не идёт.
   **Изменённый** (`M`) так снимать нельзя: `git rm --cached` записал бы в коммит **удаление** этого файла из облачной папки.
   Для него `git reset HEAD -- <файл>` — индекс возвращается к прошлому снимку, правка остаётся на диске и в коммит не попадает.
   Шаблон тот же, что в `pre-push`: английские папки без учёта регистра и русские корни «личн», «семь», «здоров», «финанс» в любом регистре.

4. **Проверь замок настоящим файлом** (на несуществующем файле проверка ничего не доказывает):
   ```
   mkdir -p personal && echo test > personal/_guard_test.md
   git add -f personal/_guard_test.md && git commit -m "guard test"
   git ls-files personal | wc -l
   rm -f personal/_guard_test.md && rmdir personal 2>/dev/null
   ```
   Признак: в выводе строка `[guard] сняты с коммита`, а `git ls-files personal | wc -l` показывает `0`.

#### 7.4. Подключаем и отправляем

1. Создай приватный репозиторий без отправки: `gh repo create <имя-папки> --private --source=. --remote=origin`.
2. **До первой отправки** проверь, что в снимке нет личного:
   ```
   git -c core.quotepath=off ls-tree -r --name-only HEAD | grep -i -E 'memory/|personal/|private/|sessions/|dialogues/|insights/profiles/|\.secrets/|\.env$|\.bak'
   ```
   Должно быть **пусто**. Повтори скан секретов из Шага 3.4.
3. Отправь: `git push -u origin HEAD`.
4. Проверь, что репозиторий приватный: `gh repo view --json visibility` → `PRIVATE`.
5. Для следующих отправок: `git diff --name-only @{u}..HEAD` — посмотреть, что уйдёт, затем `git push`. Хук `pre-push` проверит ещё раз.
6. Хук `pre-push` сказал `[guard] СТОП` — личное попало в один из ещё не отправленных коммитов. Хук смотрит всю историю отправки, поэтому просто удалить файл новым коммитом мало. Ничего не переписывай сам: покажи человеку список файлов из сообщения хука и предложи пересобрать неотправленные коммиты — `git reset --soft @{u}` (изменения остаются, коммиты собираются заново, уже без личного: хук `pre-commit` его снимет). Делай только по его «да».

Скрипт авто-коммита облачную папку может снимать локально, но **в облако не отправляет**: отправка кода — осознанное действие по фразе человека «отправь скиллы в GitHub».

### Шаг 8. Финальный отчёт пользователю

Покажи коротко:
- ✅ Какие папки под защитой
- ✅ Расписание: каждые 30 минут
- ✅ Память: только на этом компьютере, облачного адреса у папки мозга нет, замок на отправку проверен
- ✅ Копия вне компьютера: штатный бэкап (Time Machine / История файлов) включён / пока нет
- ✅ GitHub для кода и скиллов: подключён / не нужен
- 🔐 Если была старая установка: что нашли и что сделали (облачный адрес убран, в истории GitHub памяти нет / есть и что выбрал человек, шаги по паролю и 2FA пройдены / отложены)

## Частые вопросы

**Это заменяет ручные коммиты?** Для страховки — да. Но привычка говорить «сделай commit» после законченного куска работы остаётся полезной: такие коммиты имеют осмысленные описания, по ним легче откатываться.

**Сколько места это съест?** Git хранит только изменения. Текстовые файлы второго мозга — это мегабайты. Годы бэкапов < одного фильма.

**А если я работаю в момент коммита?** Ничего страшного: коммит просто зафиксирует текущее состояние. Конфликтов не будет — всё происходит локально на твоём компьютере.

**А если ноутбук потеряется?** Локальные снимки защищают от «Claude перезаписал» и «сам сломал». От потери ноутбука защищает штатный бэкап компьютера (Шаг 6.7) или, если мозг на сервере, ночное зеркало сервер → компьютер. GitHub для этого не нужен.

**Почему раньше советовали GitHub для памяти, а теперь нет?** Потому что облако — лишняя дверь к самому личному. Приватный репозиторий открывают по ошибке, аккаунт взламывают, а из истории git отправленное почти не вычистить. Мы закрыли эту дверь и у себя, и в ките.

**Безопасно ли это?** Скрипт ничего не отправляет в сеть. Ключи (`.env`, `.secrets/`) исключены из снимков через `.gitignore`, а замок `pre-push` не даст вынести память, даже если кто-то по ошибке подключит облако.
