## 🔴 Отмена прежнего совета — прочти, если собирал бота до сентября

В `telegram-bot-setup.md`, раздел **«Гигиена системного промпта»**, сказано: меняющееся
(время, календарь) ставь **вниз** промпта. Совет верный по смыслу, но **его недостаточно**,
и выполнив его дословно ты не увидишь изменений.

**Почему.** Если `system` уходит в модель **одним текстовым блоком**, кэш ломается не позицией
строки внутри него, а тем, что весь блок изменился. Порядок строк тут ни при чём.

**Что делать вместо.** Разрезать `system` на **два блока** и пометить кэшированием только
стабильный — пункт 2 ниже. Проверяется замером из пункта 1: если после правки `cache_write`
всё ещё не ноль на повторном вопросе, значит в стабильную часть протекло что-то меняющееся.

Я сам выполнял свой же совет и месяц был уверен, что починил. Пока не поставил прибор.

## Почему это отдельный файл

Я собрал личного бота и полтора года был уверен, что он работает нормально. Потом поставил прибор
и увидел: **бот отвечал на трети своих знаний и платил двойную цену за каждое сообщение.**
Ни одного сообщения об ошибке при этом не было — всё «работало».

Четыре правила ниже стоят двадцати минут при сборке и экономят месяцы.

## 1. Прибор ставится в момент сборки, а не «когда потолстеет»

Без трёх чисел в логе любые советы по оптимизации — вера. Добавь это сразу после вызова модели:

```python
u = response.usage
log.info(
    f"[USAGE] input={u.input_tokens} "
    f"cache_read={getattr(u, 'cache_read_input_tokens', 0)} "
    f"cache_write={getattr(u, 'cache_creation_input_tokens', 0)}"
)
```

**Что означают числа:**
- `cache_read` — прочитано из кэша, стоит примерно **0,1×** обычного ввода
- `cache_write` — записано в кэш, стоит **1,25×** при кэше на 5 минут и **2×** при часовом
- `input` — обработано по полной цене

Если `cache_read` всегда ноль при повторных вопросах — кэш не работает, и ты платишь дважды.

## 2. Кэш ломает не длина промпта, а любая мелочь, которая меняется

Классическая ловушка: в системный промпт подставляют текущее время. Промпт меняется каждую минуту,
и точка кэширования **не срабатывает никогда**.

🔴 Совет «ставь меняющееся вниз промпта» **недостаточен**. Если `system` уходит одним текстовым
блоком, кэш ломается не позицией строки, а тем, что весь блок изменился.

**Нужен разрез на два блока:**

```python
MARKER = "<<<CACHE_SPLIT>>>"

if MARKER in system_text:
    stable, volatile = system_text.split(MARKER, 1)
    system = [
        {"type": "text", "text": stable.rstrip(),
         "cache_control": {"type": "ephemeral", "ttl": "1h"}},
        {"type": "text", "text": volatile.lstrip()},          # без кэша
    ]
else:
    log.warning("маркер потерян — идём одним блоком")          # fallback обязателен
    system = [{"type": "text", "text": system_text,
               "cache_control": {"type": "ephemeral", "ttl": "1h"}}]
```

Выше маркера — инструкции, память, справочники. Ниже — время, календарь, всё живое.

**Мой замер до и после:**

| | было | стало |
|---|---:|---:|
| `cache_read` | 21 610 | **67 421** |
| `cache_write` | 36 937 | **0** |

Это на каждом сообщении.

### Как проверить, что получилось

Задай боту **один и тот же вопрос дважды с паузой БОЛЬШЕ минуты** и посмотри в лог.
Минута принципиальна: именно смену минуты старый вариант не переживал.

- на втором вызове `cache_read` большой, `cache_write` около нуля → работает
- `cache_write` на каждом сообщении → не работает, ищи, что меняется в стабильной части

⚠️ Минимальный кэшируемый префикс зависит от модели (у Haiku 4.5 — 4 096 токенов).
Короче — кэш молча не создастся, ошибки не будет.

## 3. Поднял лимит ответа — ставь троттлинг

Как только увеличишь `max_tokens`, длинные ответы начнут биться на 3–5 сообщений подряд.
Они летят вплотную, упираются в ограничение частоты, и **середина ответа исчезает молча**.

```python
_last_send = 0.0

def safe_send(chat_id, text, min_gap=0.35):
    global _last_send
    gap = time.time() - _last_send
    if gap < min_gap:
        time.sleep(min_gap - gap)
    try:
        r = bot.send_message(chat_id, text)
        _last_send = time.time()
        return True
    except RateLimitError as e:
        time.sleep(getattr(e, "retry_after", 3))
        r = bot.send_message(chat_id, text)      # один повтор
        _last_send = time.time()
        return True
    except Exception:
        return False        # ← и ОБЯЗАТЕЛЬНО проверяй результат у вызывающего кода
```

Ответ с невидимой дырой посередине хуже обрезанного: обрезанный видно.

## 4. Master Prompt — то, что твой агент знает о тебе всегда

Самая недооценённая часть. У меня агент полгода знал обо мне **250 слов** — и переспрашивал
очевидное на каждой задаче.

Норма по методологии Тиаго Форте — **1 000–2 000 слов**. Это «руководство пользователя» на тебя:

- кто ты и чем занимаешься
- куда идёшь — цель и текущие фокусы
- **как ты принимаешь решения** — твои фильтры, через которые проходит входящее
- что считаешь хорошей работой
- чего не делать никогда
- **твои известные слабые места** — да, это тоже, и это работает
- как с тобой разговаривать

🔑 **Не сочиняй его с нуля.** Он у тебя уже написан — размазан по твоим поправкам агенту за
последние месяцы. Я собрал свой дистилляцией **210** накопленных файлов с правилами:
получилось 1 256 слов вместо 250.

Промпт для сборки:

```
Прочитай все файлы, где я тебя поправлял и задавал правила.
Собери из них один документ 1 000–2 000 слов по структуре:
кто я · куда иду · как принимаю решения · что считаю хорошей работой ·
чего не делать никогда · мои слабые места · как со мной разговаривать.
Только то, что НЕ меняется от задачи к задаче. Операционные протоколы не тащи —
они остаются в своих файлах. Ничего не выдумывай: если чего-то нет в источниках, спроси меня.
```

Дальше этот файл грузится **всегда** — и в бота, и в редактор. Если он живёт только в одном
месте, во втором агент будет каждый раз собирать контекст заново.

## 5. Тот же токен: через консоль — старшая модель, через API — лимиты

Развилка, которая не гуглится и стоила мне месяца.

Если у тебя есть подписка, агент может ходить в модель **не по ключу API, а как консольный
процесс под тем же логином**. Замер на моём сервере: осмысленный ответ по файлам памяти
за **7,1 секунды, сверху 0 ₽**.

```bash
claude -p "вопрос" --model opus \
  --allowed-tools "Read,Grep,Glob" \
  --max-turns 12 --settings "{}" --strict-mcp-config
```

🔴 **Две засады, обе стоили времени:**
1. Если в окружении лежит ключ API — консоль уйдёт на него и упрётся в пустой баланс.
   Ключ надо убрать **именно для этого процесса**.
2. Нужен токен подписки в окружении, иначе ответ будет `Not logged in`.

**Архитектура «два мозга»:** быстрые ответы (календарь, «запомни», короткие вопросы) —
через обычный API на младшей модели, 2–3 секунды. Глубокие («почему», «разбери», «посчитай») —
через консоль на старшей. Триггеры выбирай сам.

## 6. Если ставишь поиск по памяти (RAG) — две вещи сразу

Не обязательно сегодня, но когда дойдёшь — сэкономит месяц.

**Нарезай файлы на куски.** У меня в индекс шли только первые 2 000 знаков каждого файла.
Из 12,25 млн знаков памяти индексировалось 29% — **71% текста не попадал в индекс никогда.**
Модель при этом читает ещё меньше: у маленьких моделей окно ~256 токенов ≈ 500 знаков русского.
Итого от файла в 10 000 знаков модель видела ~5%, и почти всё — служебная шапка.

Режь тело на куски **600 знаков с перехлёстом 150** (шаг 450 меньше окна модели — тогда между
кусками нет слепых зон). Шапку файла в индекс не клади.

**Добавь буквальный поиск рядом с семантическим.** Имена, аббревиатуры, даты — «Иванов», «SOK»,
«сентябрь» — не нужно *понимать*, их достаточно *найти*. Англоцентричные модели эмбеддингов
на русских именах собственных бессильны. Слей два списка через RRF:

```python
def rrf(lists, k=10, weights=None):
    weights = weights or [1.0] * len(lists)
    fused = {}
    for lst, w in zip(lists, weights):
        for rank, item in enumerate(lst, 1):
            fused[item] = fused.get(item, 0.0) + w / (k + rank)
    return fused
```

`k=10`, а не канонические 60: канон рассчитан на списки в тысячи позиций, у нас десятки.
Лексике вес 1.2 — она точнее на именах.

**Мой замер:** запрос, составленный из слов конкретного файла, до правки не находил этот файл
даже в топ-10. После — файл на первом месте.

## Чек-лист: что должно быть верно, когда закончишь

- [ ] В логе на каждый вызов три числа: `input`, `cache_read`, `cache_write`
- [ ] Два одинаковых вопроса с паузой больше минуты → на втором `cache_read` большой, `cache_write` ≈ 0
- [ ] Системный промпт разрезан на два блока, у стабильного — `cache_control`, fallback при потере маркера
- [ ] Между частями длинного ответа есть пауза, при ошибке частоты — повтор
- [ ] Вызывающий код **проверяет** результат отправки, а не идёт дальше вслепую
- [ ] Master Prompt на 1 000+ слов существует и грузится **везде**, где работает агент
- [ ] Голосовые распознаются локально, а не платным сервисом
- [ ] В промпте нет справочников и каталогов — они достаются инструментом по запросу

агент сказал «у тебя 113 навыков и ни один не вызывался, давай свернём». Я почти свернул.
Оказалось — у функции загрузки навыка просто не было строчки логирования. Вызовы были,
счётчика не было.
