# 📖 Глоссарий и тексты для VS Code / Claude Code

### Справочник всех промптов кита «Новоселье» в одном месте

---

## Как этим пользоваться

Здесь собраны **все** ключевые тексты-промпты, которые ты по ходу кита вставляешь в свой Claude Code (в терминале или внутри VS Code). Один справочник — чтобы не искать по модулям.

**Правила на всё время (агенту они уже прописаны в каждом промпте, но знай их и ты):**

- 🔒 Секреты (пароли, токены, приватные ключи) хранятся **по стандарту твоей ОС** (все три варианта равноценны — «по стандарту»): **Windows** — `%USERPROFILE%\.secrets\<имя-сервиса>\` (доступ только владельцу) или Windows Credential Manager; **macOS** — `~/.config/<имя-сервиса>/` (chmod 600) или Keychain; **Linux** — `~/.config/<имя-сервиса>/` (chmod 600). Общий принцип: **не в чат, не в код, не в git.**
- 🚫 Агент **никогда** не пишет секреты в чат и не «зашивает» их в код. Если он вдруг показал токен — останови: «выведи только путь, не значение».
- 🏠 Личные данные (**здоровье, семья, финансы**) на сервер **не переносим**. Сервер — рабочий контур.
- 🧩 Везде плейсхолдеры: `<IP>` — адрес сервера, `<SERVER>` — имя/хост, `<TOKEN>` — токен бота, `<name>` / `<имя-сервиса>` — короткое имя твоего сервиса. Подставляй своё **на своей машине**, не пиши реальные значения в общие документы.

**Мини-словарь терминов:**

| Термин | Простыми словами |
|--------|------------------|
| **VPS / сервер** | Твой компьютер «в облаке», который всегда включён и на связи. |
| **SSH** | Защищённый способ подключиться к серверу из терминала. |
| **Claude Code** | Твой AI-агент, который делает всю техническую работу. |
| **Agent SDK** | «Движок», на котором Claude Code работает автономно на сервере. |
| **Истина на сервере** | Главная копия второго мозга лежит на VPS; ПК и телефон — окна к нему. |
| **Бэкап** | Резервная копия. У нас идёт **с сервера на твой ПК**. |
| **Токен бота** | Секретный ключ Telegram-бота. Хранится в `~/.config/`, не в коде. |
| **systemd / launchd / Планировщик / cron** | Способ сказать системе «запускай это само и держи запущенным». |
| **chmod 600** | Права на файл «читать/писать может только владелец». Для секретов. |
| **pruf** | Явный признак «шаг удался». После каждого промпта смотри на него. |

> Порядок промптов ниже совпадает с порядком кита: аудит → установка → переезд → бот → бэкап → безопасность → QA.

## Шаг 0 — Аудит: агент определяет твою ситуацию и ветку

**Что делает:** исследует твой компьютер (и сервер, если есть), понимает ОС, наличие VPS, бота, где «истина», где секреты — и выдаёт персональный план + ветку A/B. Ничего не меняет.

> Полная версия этого промпта — в модуле `00_СТАРТ_И_АУДИТ.md`. Здесь дублируется для удобства.

```text
Ты — мой технический помощник. Мы готовимся к «переезду второго мозга на сервер»:
цель — чтобы Claude Code (Agent SDK) жил на VPS и работал 24/7, а мой компьютер и телефон
были окнами к нему. Сейчас нужен АУДИТ моей ситуации. Ничего не меняй — только исследуй.

Правила безопасности (соблюдай всегда): секреты не выводи в чат (только путь к файлу);
секреты храни по стандарту ОС — Windows: %USERPROFILE%\.secrets\<имя-сервиса>\ (доступ только
владельцу) или Windows Credential Manager; macOS: ~/.config/<имя-сервиса>/ (chmod 600) или
Keychain; Linux: ~/.config/<имя-сервиса>/ (chmod 600). Общий принцип: не в чат, не в код,
не в git. Личное (здоровье/семья/финансы) на сервер не переносим.

Проверь и дай короткий факт по каждому пункту:
1. ОС и версия, оболочка терминала.
2. Claude Code: установлен ли, версия, как аутентифицирован (подписка/API-ключ).
3. VPS: есть ли сервер (глянь ~/.ssh/config и следы SSH); если есть — ОС, что запущено,
   настроен ли там Claude Code. Если нет — скажи «VPS не обнаружен».
4. Telegram-бот: есть ли, как называется, что умеет, где код и где токен (путь, не токен),
   где запущен (ПК/сервер).
5. Где сейчас «истина» (второй мозг): на ПК или на сервере; есть ли синхронизация/бэкапы.
6. Сервисы/инструменты: MCP, скрипты, cron/Планировщик — что уже настроено.
7. Секреты: где хранятся ключи (код/.env/~/.config/env-переменные), безопасно ли —
   но НЕ показывай значения.

Вывод:
A) Ветка A (VPS нет — строим с нуля) или Ветка B (VPS есть — донастраиваем). Обе → один результат.
B) Персональный план шагов под мою ситуацию + какие модули кита 00–06 мне актуальны.
C) Не более 3 уточняющих вопросов, только если без них план не собрать.

Пиши тёпло, без жаргона. Я предприниматель, не технарь.
```

> ✅ **Получилось, если:** агент назвал твою ОС, чётко сказал «Ветка A» или «Ветка B», выдал список шагов под тебя, и ни один секрет не всплыл в чате.

## Шаг 1 — Заказ и первичная проверка VPS *(ветка A)*

**Что делает:** помогает выбрать и заказать сервер простыми словами, а после заказа — проверить, что к нему есть доступ.

```text
Мне нужно завести VPS для того, чтобы мой AI-мозг (Claude Code / Agent SDK) работал 24/7.
Я не технарь — объясни по-человечески.

1. Порекомендуй минимальные разумные характеристики VPS под Claude Code, работающий постоянно
   (сколько RAM, CPU, диска), и на какой ОС остановиться по умолчанию (например, свежий
   Ubuntu LTS) — с объяснением, почему.
2. Дай пошаговый чек-лист заказа у типичного хостинг-провайдера: что выбрать, что НЕ нужно,
   на что не купиться (лишние апселлы).
3. Объясни, что мне после заказа пришлют (IP-адрес <IP>, root-доступ или пароль) и куда это
   безопасно записать — напомни, что пароль/ключ кладём по стандарту моей ОС (macOS/Linux —
   ~/.config/<имя-сервиса>/ с правами 600; на Windows — %USERPROFILE%\.secrets\<имя-сервиса>\
   с доступом только для владельца или в Credential Manager), и никогда не в переписки и не в код.

Когда сервер у меня будет, я вернусь — поможешь сделать первый безопасный вход.
```

> ✅ **Получилось, если:** у тебя на руках IP-адрес сервера `<IP>` и способ входа (ключ или пароль), а сами данные лежат в защищённом файле, не в заметках и не в чате.

## Шаг 2 — Первый вход и базовая настройка сервера

**Что делает:** первый безопасный вход на VPS, обновления системы, создание рабочего пользователя (не работать под root), подготовка к установке Claude Code.

```text
У меня есть VPS. Данные доступа: адрес <IP>, вход по <SSH-ключу или паролю> — они лежат
у меня по стандарту моей ОС (macOS/Linux — ~/.config/<имя-сервиса>/; на Windows —
%USERPROFILE%\.secrets\<имя-сервиса>\ или Credential Manager; в чат я их не пишу).

Проведи меня за руку по безопасной базовой настройке, объясняя каждый шаг простыми словами:
1. Помоги подключиться к серверу по SSH (я на <моя ОС> — дай точную команду под неё).
2. Обнови систему до актуального состояния.
3. Заведи отдельного НЕ-root пользователя для повседневной работы и объясни, почему под
   root постоянно работать не стоит.
4. Настрой вход по SSH-ключу вместо пароля (сгенерируй ключ, если нужно; приватный ключ
   остаётся на моём компьютере, публичный — на сервере). Секреты — только в ~/.config/,
   права 600, в чат не выводи.
5. Ничего необратимого (менять порт SSH, выключать вход по паролю, ставить фаервол) не делай
   без моего явного «да» — сначала объясни последствия и как откатить.

После каждого пункта скажи, по какому признаку я пойму, что он выполнен успешно.
```

> ✅ **Получилось, если:** ты зашёл на сервер, увидел приглашение командной строки от **своего пользователя** (не root), система обновлена, а приватный ключ остался у тебя на ПК.

## Шаг 3 — Установка Claude Code на сервер

**Что делает:** ставит Claude Code на VPS и подключает его по твоей подписке (движок из подписки, без сюрпризов по расходам). Здесь различий по ОС **твоего** компьютера нет — работаем внутри сервера (Linux).

```text
На моём VPS нужно установить Claude Code и подключить его по моей ПОДПИСКЕ (не по API-ключу),
чтобы он работал автономно.

1. Установи Claude Code на сервер актуальным официальным способом, объясняя шаги.
2. Подключи его к моей подписке через setup-token (я авторизуюсь сам, когда попросишь).
   Токен/учётные данные положи в ~/.config/<имя-сервиса>/ с правами 600, в чат не выводи.
3. Проверь, что всё встало: покажи версию (claude --version) и сделай короткий тестовый
   запрос, чтобы убедиться, что агент отвечает.
4. Напомни мне выключить трату кредитов/овердрафт, чтобы расходы имели жёсткий потолок
   и не было неожиданных списаний (объясни, где это переключается).

Секреты — только в ~/.config/, права 600. Ничего в чат не печатай из чувствительного.
```

> ✅ **Получилось, если:** `claude --version` на сервере показал номер версии, тестовый запрос получил ответ, а учётные данные лежат в `~/.config/<имя-сервиса>/` с правами 600.

## Шаг 4 — Переезд «мозга»: истина теперь на сервере

**Что делает:** переносит рабочий второй мозг (заметки, память, конфиги агента) с ПК на сервер так, чтобы главной копией стал сервер. Личное **не** переносит.

```text
Переносим мой второй мозг на сервер так, чтобы ИСТИНА жила на сервере, а ПК и телефон
были окнами к нему.

Очень важно (контур):
- Переносим ТОЛЬКО рабочий контур: проекты, рабочие заметки, память агента, конфиги.
- НЕ переносим личное: здоровье, семью, финансы. Если сомневаешься по конкретной папке/файлу —
  спроси меня, а не переноси.

Сделай так:
1. Сначала покажи ПЛАН: что именно предлагаешь перенести (список папок/файлов) и что
   осознанно оставляешь на ПК как личное. Дождись моего «да».
2. Перед переносом сделай резервную копию текущего состояния (и на ПК, и на сервере).
3. Перенеси одобренное на сервер по защищённому каналу (SSH/rsync). Секреты и токены не
   складывай в общие папки мозга — им место в ~/.config/<имя-сервиса>/ с правами 600.
4. После переноса убедись, что серверная копия полная и читается, и объясни мне, как теперь
   выглядит рабочий процесс: я обращаюсь к агенту на сервере, ПК — окно.

После каждого этапа скажи признак успеха. Ничего не удаляй с ПК без моего явного подтверждения.
```

> ✅ **Получилось, если:** агент показал план и ты его одобрил; рабочие файлы читаются **на сервере**; личные папки остались **на ПК**; исходники на ПК пока никто не удалял (удаляем только осознанно, после бэкапа).

## Шаг 5 — Интеграция существующего Telegram-бота

**Что делает:** подключает твой **уже существующий** бот к серверному мозгу. Новый бот не создаём. Токен бота переезжает в защищённое хранилище.

```text
У меня уже есть Telegram-бот (по данным аудита: <название/что умеет>). НОВОГО бота не создаём —
интегрируем существующий, чтобы он стал окном к моему AI-мозгу на сервере и отвечал 24/7.

Сделай так:
1. Найди текущий код бота и где лежит его токен. Перенеси токен в ~/.config/<name>/ с правами
   600 (значение <TOKEN> в чат не выводи — работай с ним как с секретом).
2. Подключи бота к серверному Claude Code так, чтобы мои сообщения в бот попадали к агенту,
   а ответы возвращались мне в Telegram.
3. Сделай так, чтобы бот держался запущенным сам и переживал перезагрузку сервера — через
   systemd-сервис на VPS (Linux). Покажи мне, как проверить его статус и логи.
4. Если у бота уже были функции — сохрани их, не ломай. Сначала покажи план изменений.

Проверь end-to-end: я напишу боту тестовое сообщение — убедись, что пришёл осмысленный ответ
от серверного агента. Секреты не логируй и не печатай в чат.
```

> ✅ **Получилось, если:** ты написал боту с телефона и получил ответ от серверного агента; бот запускается сам после перезагрузки сервера; токен лежит в `~/.config/<name>/` (chmod 600), а не в коде.

## Шаг 5-бис — 🎙️ Чтобы бот слышал голосовые *(по желанию)*

**Что делает:** учит бота понимать голосовые сообщения. Расшифровка идёт **локально на сервере** (без внешних платных сервисов), а полученный текст обрабатывается как обычное сообщение — через тот же разговорный путь к мозгу. Модель — faster-whisper «small» (int8, CPU), подходит для скромного сервера (2 ядра / 4 ГБ) и коротких голосовых. Полный разбор — в модуле `03_ИНТЕГРАЦИЯ_БОТА.md`.

```text
Хочу научить моего бота понимать голосовые сообщения. Расшифровку делаем ЛОКАЛЬНО
на этом сервере (никаких внешних платных сервисов), а дальше голос обрабатываем как
обычный текст — через тот же разговорный путь, что уже подключён к мозгу.

1. Поставь зависимости на сервере: пакет faster-whisper (через pip) и ffmpeg. Покажи
   команды и подтверди, что оба встали.
2. В обработчик голосовых добавь: скачать присланный voice/audio-файл (обычно .ogg) во
   временный файл → расшифровать локально моделью faster-whisper размера "small",
   compute_type="int8", device="cpu" → полученный текст передать ДАЛЬШЕ в тот же
   разговорный путь, что и обычный текст (переиспользуй существующую логику ответа) →
   временный аудиофайл удалить.
3. Модель загружай ЛЕНИВО и ОДИН раз (создать при первом голосовом и переиспользовать),
   чтобы не грузить её на каждое сообщение и не съесть память.
4. Whitelist владельца применяется к голосовым так же, как к тексту: чужой user_id
   отсекается ДО расшифровки и до вызова мозга. Секреты в чат не выводи, в код не хардкодь.
5. Если в расшифрованном тексте окажется что-то, ведущее к необратимому действию, —
   сначала подтверждение у меня, только потом выполнять.

Покажи точечный diff и объясни по-русски. Кроме обработки голоса — ничего не трогай.
```

> ✅ **Получилось, если:** отправляешь боту голосовое — он отвечает по его содержанию; на коротких голосовых сервер (2 ядра / 4 ГБ) справляется; чужой аккаунт отсекается до расшифровки; модель грузится один раз, а не на каждое сообщение.

## Шаг 6 — Бэкап: сервер → твой личный ПК

**Что делает:** настраивает регулярную резервную копию рабочего мозга **с сервера на твой компьютер**. Направление именно такое — сервер источник, ПК хранилище копии.

```text
Настроим регулярный бэкап моего рабочего мозга С СЕРВЕРА НА МОЙ ЛИЧНЫЙ ПК (направление
сервер → ПК). Личное на сервере не хранится, поэтому бэкапим рабочий контур.

1. Предложи, что именно бэкапить (рабочие папки мозга, конфиги — БЕЗ секретов из ~/.config,
   их бэкапим отдельно и осознанно) и как часто.
2. Настрой автоматический бэкап под МОЮ ОС. Дай ГОТОВУЮ инструкцию именно под неё:

   - Windows: задача в Планировщике заданий (Task Scheduler) + скрипт (например, robocopy
     или scp/rsync через WSL) для регулярного скачивания копии с сервера.
   - macOS: агент launchd (файл .plist в ~/Library/LaunchAgents/) + rsync-скрипт для
     регулярного скачивания копии с сервера.
   - Linux: задача cron + rsync-скрипт для регулярного скачивания копии с сервера.

3. Сделай первую копию прямо сейчас и покажи мне, где на моём ПК она лежит и как проверить,
   что файлы действительно скачались и открываются.
4. Объясни простыми словами, как восстановиться из бэкапа, если с сервером что-то случится.

Секреты в общий бэкап не клади; доступы к серверу держи по стандарту моей ОС (macOS/Linux —
~/.config/ с правами 600; на Windows — %USERPROFILE%\.secrets\ с доступом только для владельца
или в Credential Manager).
```

> ✅ **Получилось, если:** на твоём ПК появилась папка с копией серверного мозга, файлы открываются, а задача (Планировщик / launchd / cron) стоит в расписании и повторится сама.

## Шаг 7 — Безопасность и наведение порядка с секретами

**Что делает:** финальная защита. Проверяет, что все ключи в `~/.config/` с правами 600, ничего не торчит наружу лишнего, и что личное не уехало на сервер.

```text
Проведи проверку безопасности моего нового серверного дома. Ты — в защитной роли, ничего
не ломаешь, опасное делаешь только с моим «да».

Проверь и приведи в порядок:
1. СЕКРЕТЫ: все токены/ключи/пароли должны лежать в ~/.config/<имя-сервиса>/ с правами 600.
   Найди секреты, которые лежат не там (в коде, в .env в проекте, в общих папках) и предложи
   перенести. Значения в чат НЕ выводи — только пути и факт.
2. ДОСТУП НА СЕРВЕР: вход по SSH-ключу (не по паролю), фаервол включён и открыты только нужные

Выдай отчёт светофором: 🟢 в порядке / 🟡 стоит поправить / 🔴 надо чинить — с конкретикой.
```

### 🧷 Шпаргалка на холодильник

- Секреты → **по стандарту ОС**: Windows — `%USERPROFILE%\.secrets\<имя-сервиса>\` или Credential Manager; macOS/Linux — `~/.config/<имя-сервиса>/`, **chmod 600** (mac ещё Keychain). Никогда в чат/код/git.
- Личное (здоровье/семья/финансы) → на сервер **не** едет.
- Истина → на **сервере**; ПК и телефон → окна.
- Бэкап → **сервер → ПК** (Windows: Планировщик · macOS: launchd · Linux: cron).
- После каждого шага → смотри **✅ pruf**. Зелёный — идёшь дальше.
- Что-то непонятно/страшно → зови агента универсальным промптом выше. Ты заказчик, он исполнитель.
