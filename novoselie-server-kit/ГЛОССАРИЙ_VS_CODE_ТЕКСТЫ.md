# 📖 Глоссарий и тексты для VS Code / Claude Code

### Справочник всех промптов кита «Новоселье» в одном месте

---

## Как этим пользоваться

Здесь собраны **все** ключевые тексты-промпты, которые ты по ходу кита вставляешь в свой Claude Code (в терминале или внутри VS Code). Один справочник — чтобы не искать по модулям.

**Правила на всё время (агенту они уже прописаны в каждом промпте, но знай их и ты):**

- 🔒 Секреты (пароли, токены, приватные ключи) хранятся **по стандарту твоей ОС** (все три варианта равноценны — «по стандарту»): **Windows** — `%USERPROFILE%\.secrets\<имя-сервиса>\` (доступ только владельцу) или Windows Credential Manager; **macOS** — `~/.config/<имя-сервиса>/` (chmod 600) или Keychain; **Linux** — `~/.config/<имя-сервиса>/` (chmod 600). Общий принцип: **не в чат, не в код, не в git.**
- 🚫 Агент **никогда** не пишет секреты в чат и не «зашивает» их в код. Если он вдруг показал токен — останови: «выведи только путь, не значение».
- 🏠 Личные данные (**здоровье, семья, финансы**) на сервер **не переносим**. Сервер — рабочий контур.
- 🔑 **IP, логин и пароль сервера ты в промпты НЕ вписываешь.** Они живут в **Файле доступа** (macOS/Linux — `~/.config/brain/server_access`; Windows — `%USERPROFILE%\.secrets\brain\server_access.txt`), агент берёт их оттуда сам. Как файл создаётся и заполняется — раздел «🔑 Файл доступа» ниже.
- 🧩 Плейсхолдеры для НЕсекретного: `<SERVER>` — имя/хост, `<name>` / `<имя-сервиса>` — короткое имя твоего сервиса. Подставляй своё **на своей машине**, не пиши реальные значения в общие документы.

**Мини-словарь терминов:**

| Термин | Простыми словами |
|--------|------------------|
| **VPS / сервер** | Твой компьютер «в облаке», который всегда включён и на связи. |
| **Файл доступа** | Защищённый файл, где лежат IP/логин/пароль сервера. Ты заполняешь его один раз, агент дальше берёт данные оттуда сам — не через чат. |
| **SSH** | Защищённый способ подключиться к серверу из терминала. |
| **Claude Code** | Твой AI-агент, который делает всю техническую работу. |
| **Agent SDK** | «Движок», на котором Claude Code работает автономно на сервере. |
| **Истина на сервере** | Главная копия второго мозга лежит на VPS; ПК и телефон — окна к нему. |
| **Бэкап** | Резервная копия. У нас идёт **с сервера на твой ПК**. |
| **Токен бота** | Секретный ключ Telegram-бота. Хранится в `~/.config/`, не в коде. |
| **systemd / launchd / Планировщик / cron** | Способ сказать системе «запускай это само и держи запущенным». |
| **chmod 600** | Права на файл «читать/писать может только владелец». Для секретов. |
| **pruf** | Явный признак «шаг удался». После каждого промпта смотри на него. |

> Порядок промптов ниже совпадает с порядком кита: аудит → установка → переезд → бот → бэкап → безопасность → QA.

## Шаг 0 — Аудит: агент определяет твою ситуацию и ветку

**Что делает:** исследует твой компьютер (и сервер, если есть), понимает ОС, наличие VPS, бота, где «истина», где секреты — и выдаёт персональный план + ветку A/B. Ничего не меняет.

> Полная версия этого промпта — в модуле `00_СТАРТ_И_АУДИТ.md`. Здесь дублируется для удобства.

```text
Ты — мой технический помощник. Мы готовимся к «переезду второго мозга на сервер»:
цель — чтобы Claude Code (Agent SDK) жил на VPS и работал 24/7, а мой компьютер и телефон
были окнами к нему. Сейчас нужен АУДИТ моей ситуации. Ничего не меняй — только исследуй.

Правила безопасности (соблюдай всегда): секреты не выводи в чат (только путь к файлу);
секреты храни по стандарту ОС — Windows: %USERPROFILE%\.secrets\<имя-сервиса>\ (доступ только
владельцу) или Windows Credential Manager; macOS: ~/.config/<имя-сервиса>/ (chmod 600) или
Keychain; Linux: ~/.config/<имя-сервиса>/ (chmod 600). Общий принцип: не в чат, не в код,
не в git. Личное (здоровье/семья/финансы) на сервер не переносим.

Правило передачи секретов: если для шага нужны IP/логин/пароль сервера или другой секрет —
НЕ проси их в чат. Создай/открой мне «Файл доступа» (macOS/Linux: ~/.config/brain/server_access;
Windows: %USERPROFILE%\.secrets\brain\server_access.txt), я впишу значения и скажу «готово»;
проверь, что значения настоящие (не пустые, не плейсхолдеры вида <...>, IP не 1.2.3.4 /
127.0.0.1 / 0.0.0.0; настоящий пароль может содержать любые символы — за них не отвергай,
судья — успешное подключение), и дальше работай сам, повторно не спрашивая.

Проверь и дай короткий факт по каждому пункту:
1. ОС и версия, оболочка терминала.
2. Claude Code: установлен ли, версия, как аутентифицирован (подписка/API-ключ).
3. VPS: есть ли сервер (глянь ~/.ssh/config и следы SSH); если есть — ОС, что запущено,
   настроен ли там Claude Code. Если нет — скажи «VPS не обнаружен».
4. Telegram-бот: есть ли, как называется, что умеет, где код и где токен (путь, не токен),
   где запущен (ПК/сервер).
5. Где сейчас «истина» (второй мозг): на ПК или на сервере; есть ли синхронизация/бэкапы.
6. Сервисы/инструменты: MCP, скрипты, cron/Планировщик — что уже настроено.
7. Секреты: где хранятся ключи (код/.env/~/.config/env-переменные), безопасно ли —
   но НЕ показывай значения.

Вывод:
A) Ветка A (VPS нет — строим с нуля) или Ветка B (VPS есть — донастраиваем). Обе → один результат.
B) Персональный план шагов под мою ситуацию + какие модули кита 00–10 мне актуальны.
C) Не более 3 уточняющих вопросов, только если без них план не собрать.

Пиши тёпло, без жаргона. Я предприниматель, не технарь.
```

> ✅ **Получилось, если:** агент назвал твою ОС, чётко сказал «Ветка A» или «Ветка B», выдал список шагов под тебя, и ни один секрет не всплыл в чате.

## Шаг 1 — Заказ и первичная проверка VPS *(ветка A)*

**Что делает:** помогает выбрать и заказать сервер простыми словами, а после заказа — проверить, что к нему есть доступ.

```text
Мне нужно завести VPS для того, чтобы мой AI-мозг (Claude Code / Agent SDK) работал 24/7.
Я не технарь — объясни по-человечески.

1. Порекомендуй минимальные разумные характеристики VPS под Claude Code, работающий постоянно
   (сколько RAM, CPU, диска), и на какой ОС остановиться по умолчанию (например, свежий
   Ubuntu LTS) — с объяснением, почему.
2. Дай пошаговый чек-лист заказа у типичного хостинг-провайдера: что выбрать, что НЕ нужно,
   на что не купиться (лишние апселлы).
3. Объясни, что мне после заказа пришлют (IP-адрес, root-доступ или пароль). Записывать их
   я буду НЕ в переписку и не в заметки, а в «Файл доступа» — когда данные придут, я запущу
   отдельный промпт «Файл доступа», ты создашь защищённый файл и откроешь его мне.

Когда сервер у меня будет, я вернусь — поможешь сделать первый безопасный вход.
```

> ✅ **Получилось, если:** у тебя на руках IP-адрес сервера и способ входа (ключ или пароль), а сами данные лежат в Файле доступа (следующий раздел), не в заметках и не в чате.

## 🔑 Файл доступа — как передать агенту IP, логин и пароль (никогда через чат)

**Что делает:** агент создаёт защищённый файл, открывает его тебе на экран, ты вписываешь туда данные из письма хостера, говоришь «готово» — агент проверяет, что значения настоящие, сам подключается, ставит SSH-ключ и дальше строит всё автоматически, ничего больше не спрашивая. Запускай сразу, как только хостер прислал IP и пароль.

```text
Хостер прислал мне данные доступа к серверу (IP, логин, пароль). Мне нужно передать их
тебе БЕЗ чата — через «Файл доступа». Сделай строго так:

1. Создай «Файл доступа» в защищённой папке по стандарту моей ОС (определи ОС сам):
   - macOS / Linux: ~/.config/brain/server_access (папке права 700, файлу 600);
   - Windows: %USERPROFILE%\.secrets\brain\server_access.txt (доступ только владельцу).
   Если файл уже существует — НЕ перезаписывай его: пропусти шаг 2 и переходи
   сразу к проверке значений (шаг 4).
2. Запиши в файл ровно такой шаблон. Поля после «=» оставь ПУСТЫМИ — никаких
   примеров-значений в них не вписывай:
   # Данные доступа к твоему серверу.
   # Заполни три строки внизу: вставь свои значения СРАЗУ ПОСЛЕ знака «=».
   # Где взять: письмо или личный кабинет хостера (после заказа VPS).
   # IP — четыре числа через точку. LOGIN — обычно root.
   # PASSWORD — пароль из письма, вставляй ЦЕЛИКОМ и как есть (любые символы — нормально).
   # Если вход уже настроен только по SSH-ключу — впиши PASSWORD=KEY-ONLY.
   # Если у сервера нестандартный SSH-порт — добавь отдельную строку PORT= с номером.
   # Заполнил? Сохрани файл (Cmd+S / Ctrl+S) и напиши мне в чат: «готово».
   IP=
   LOGIN=root
   PASSWORD=
3. Открой этот файл мне на экран (в VS Code — командой `code <путь-к-файлу>`; если не
   выходит — напиши путь и попроси меня открыть его самому) и одной фразой скажи, что
   куда вписать. Дальше ЖДИ моего «готово» — сам не продолжай.
4. Когда я напишу «готово» — прочитай файл и ПРОВЕРЬ каждое значение.
   Как читать: значения бери только из строк вида КЛЮЧ=значение; строки на «#» —
   комментарии, не значения; в PASSWORD бери ВСЁ после ПЕРВОГО знака «=» (пароль может
   содержать «=»); пробелы и переводы строки по краям значений отбрасывай.
   - IP: четыре числа 0–255 через точку (или доменное имя сервера от хостера);
     НЕ 127.0.0.1, НЕ 0.0.0.0, НЕ 1.2.3.4; не обёрнуто в угловые скобки.
   - LOGIN: не пустой, одно слово без пробелов, не обёрнут в угловые скобки.
   - PASSWORD: не пустой. Отвергай ТОЛЬКО если значение целиком обёрнуто в угловые
     скобки (вида <...>) или равно слову «пароль»/«password»/«пример». Настоящий пароль
     может содержать ЛЮБЫЕ символы (включая < > " = и пробел) — за это НЕ отвергай.
     Особое значение KEY-ONLY валидно: вход только по SSH-ключу, пароль не нужен.
   Если что-то не так — снова открой мне файл, скажи КОНКРЕТНО какую строку поправить,
   и жди нового «готово». Сомневаешься в пароле — спроси одной фразой «это настоящий
   пароль из письма хостера?» и, если да, принимай: окончательный судья настоящести —
   успешное подключение (шаг 6).
5. Пароль НИКОГДА не выводи в чат — ни целиком, ни частично. И не подставляй его
   литералом в команды: текст команд тоже виден в чате. IP и логин показывать можно.
6. Когда значения прошли проверку — проверь их делом: подключись к серверу.
   Порт: если в файле есть строка PORT= — используй её, иначе 22.
   Пароль передавай безопасно: читай из файла внутри команды (например, `sshpass -f`
   или переменная окружения); если неинтерактивно не получается — запусти ssh в
   терминале и попроси МЕНЯ ввести пароль в окно терминала (терминал — не чат).
   Выполни `whoami` и `uname -a` и покажи мне вывод.
   Если сервер отвечает «Permission denied» — не зацикливайся: частая причина — лишний
   пробел или неполностью скопированный пароль. Снова открой мне файл, попроси вставить
   пароль из письма заново целиком и жди нового «готово».
   Затем сразу создай SSH-ключ (если у меня его нет) и установи его на сервер, чтобы
   дальше пароль был не нужен. Финальная проверка:
   `ssh -o BatchMode=yes <логин>@<IP-из-файла> 'echo OK'` печатает OK.
   С этого момента данные доступа у меня больше НЕ спрашивай — при любой следующей
   задаче бери их сам из Файла доступа.
```

> ✅ **Получилось, если:** агент показал `whoami` / `uname -a` с сервера и «вход по ключу: OK», а пароль ни разу не появился в чате. Дальше во всех промптах кита агент берёт данные из этого файла сам.

## Шаг 2 — Первый вход и базовая настройка сервера

**Что делает:** первый безопасный вход на VPS, обновления системы, создание рабочего пользователя (не работать под root), подготовка к установке Claude Code.

```text
У меня есть VPS. Адрес, логин и пароль возьми САМ из моего Файла доступа
(macOS/Linux: ~/.config/brain/server_access; Windows:
%USERPROFILE%\.secrets\brain\server_access.txt) — в чат я их не пишу, пароль не выводи.
Если файла нет или значения в нём не настоящие (пустые, плейсхолдеры вида <...>,
IP вида 1.2.3.4 / 127.0.0.1; настоящий пароль может содержать ЛЮБЫЕ символы — за них
не отвергай, судья — успешное подключение) — сначала пройди со мной протокол
«Файл доступа»: создай файл, открой мне, дождись «готово», проверь значения.

Проведи меня за руку по безопасной базовой настройке, объясняя каждый шаг простыми словами:
1. Подключись к серверу по SSH сам (данные — из Файла доступа) и покажи признак успеха.
2. Обнови систему до актуального состояния.
3. Заведи отдельного НЕ-root пользователя для повседневной работы и объясни, почему под
   root постоянно работать не стоит.
4. Настрой вход по SSH-ключу вместо пароля (сгенерируй ключ, если нужно; приватный ключ
   остаётся на моём компьютере, публичный — на сервере). Секреты — только в ~/.config/,
   права 600, в чат не выводи.
5. Ничего необратимого (менять порт SSH, выключать вход по паролю, ставить фаервол) не делай
   без моего явного «да» — сначала объясни последствия и как откатить.

После каждого пункта скажи, по какому признаку я пойму, что он выполнен успешно.
```

> ✅ **Получилось, если:** ты зашёл на сервер, увидел приглашение командной строки от **своего пользователя** (не root), система обновлена, а приватный ключ остался у тебя на ПК.

## Шаг 3 — Установка Claude Code на сервер

**Что делает:** ставит Claude Code на VPS и подключает его по твоей подписке **выделенным долгоживущим токеном** (`claude setup-token`) — движок из подписки, без сюрпризов по расходам и без «разлогинов», когда ты обновляешь вход на ноутбуке. Здесь различий по ОС **твоего** компьютера нет — работаем внутри сервера (Linux).

```text
На моём VPS нужно установить Claude Code и подключить его по моей ПОДПИСКЕ (не по API-ключу),
чтобы он работал автономно.

1. Установи Claude Code на сервер актуальным официальным способом, объясняя шаги.
2. Подключи его к подписке ВЫДЕЛЕННЫМ токеном, а НЕ переиспользуя мой обычный вход ноутбука
   (общий интерактивный вход на сервере периодически протухает — сервер начинает
   «разлогиниваться» из подписки; выделенный токен развязывает сервер от ноутбука):
   - команду `claude setup-token` я выполню САМ в своём терминале (откроется браузер,
     ~5 минут) — ты её НЕ запускай и её вывод НЕ читай: она интерактивная и печатает
     секрет; объясни мне, как открыть терминал и запустить команду, и жди;
   - токен я передам НЕ через чат: добавь в мой Файл доступа пустую строку CLAUDE_TOKEN=,
     открой файл мне, я перенесу строку вида `sk-ant-oat...` из терминала в файл и скажу
     «готово»; проверь, что значение начинается с sk-ant-, длиннее 30 символов и не
     содержит троеточия «...» (иначе это пример из инструкции, а не настоящий токен);
   - положи его на сервер в env-файл сервиса в ~/.config/<имя-сервиса>/ с правами 600
     (строка CLAUDE_CODE_OAUTH_TOKEN=...), в чат не выводи, затем удали строку
     CLAUDE_TOKEN из локального Файла доступа. ANTHROPIC_API_KEY не задавай
     (иначе включится платный биллинг).
3. Проверь, что всё встало: покажи версию (claude --version) и сделай короткий тестовый
   запрос, чтобы убедиться, что агент отвечает по подписке.
4. Напомни мне выключить трату кредитов/овердрафт, чтобы расходы имели жёсткий потолок
   и не было неожиданных списаний (объясни, где это переключается).

Секреты — только в ~/.config/, права 600. Ничего в чат не печатай из чувствительного.
```

> ✅ **Получилось, если:** `claude --version` на сервере показал номер версии, тестовый запрос получил ответ по подписке, выделенный токен (`sk-ant-oat...`) лежит в `~/.config/<имя-сервиса>/` с правами 600, и после обновления входа на ноутбуке сервер НЕ отваливается.

## Шаг 4 — Переезд «мозга»: истина теперь на сервере

**Что делает:** переносит рабочий второй мозг (заметки, память, конфиги агента) с ПК на сервер так, чтобы главной копией стал сервер. Личное **не** переносит.

```text
Переносим мой второй мозг на сервер так, чтобы ИСТИНА жила на сервере, а ПК и телефон
были окнами к нему.

Очень важно (контур):

завершённым. Если что-то 🔴 — скажи прямо и предложи, что доделать.
```

> ✅ **Получилось, если:** по всем семи пунктам стоит 🟢 и агент подтвердил, что переезд завершён. Есть 🟡/🔴 — не беда: вернись к соответствующему промпту выше и доведи до зелёного.

## 🆘 Если что-то пошло не так — универсальный промпт

**Что делает:** зовёшь агента разобраться в любой заминке спокойно и безопасно.

```text
Что-то пошло не так на шаге <номер/название>. Вот что я вижу: <опиши своими словами или
вставь текст ошибки БЕЗ секретов>.

Разберись спокойно:
1. Объясни простыми словами, что произошло и опасно ли это (скорее всего — нет).
2. Предложи безопасное решение по шагам. Ничего необратимого без моего «да».
3. Если нужно откатиться — используй бэкап/резервную копию, которую мы делали.
Секреты в чат не выводи. Я не технарь — говори по-человечески.
```

> ✅ **Получилось, если:** агент объяснил причину человеческим языком и предложил безопасный следующий шаг. Спокойствие — часть метода: почти всё чинится, и почти ничего не срочно.

### 🧷 Шпаргалка на холодильник

- IP/логин/пароль сервера → в **Файл доступа** (`~/.config/brain/server_access`; Windows: `%USERPROFILE%\.secrets\brain\server_access.txt`). Агент открывает файл — ты вписываешь — говоришь «готово». **В чат — никогда.**
- Остальные секреты → **по стандарту ОС**: Windows — `%USERPROFILE%\.secrets\<имя-сервиса>\` или Credential Manager; macOS/Linux — `~/.config/<имя-сервиса>/`, **chmod 600** (mac ещё Keychain). Никогда в чат/код/git.
- Личное (здоровье/семья/финансы) → на сервер **не** едет.
- Истина → на **сервере**; ПК и телефон → окна.
- Бэкап → **сервер → ПК** (Windows: Планировщик · macOS: launchd · Linux: cron).
- После каждого шага → смотри **✅ pruf**. Зелёный — идёшь дальше.
- Что-то непонятно/страшно → зови агента универсальным промптом выше. Ты заказчик, он исполнитель.
