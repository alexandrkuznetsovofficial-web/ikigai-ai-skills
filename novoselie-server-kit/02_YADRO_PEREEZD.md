# Модуль 02 · Ядро переезда: что делает brain-link на сервере

> Сервер заказан, Файл доступа заполнен (модуль 01). Теперь `brain-link` готовит сервер-базу и кладёт на неё первую копию твоей памяти. Этот модуль объясняет, **что происходит на каждом шаге и почему так**. Руками команды собирать не нужно: шаги идемпотентны (повторный запуск ничего не ломает), только добавляют и перед любой правкой сохраняют копию `.bak`.

**Что получится в конце модуля:**
- на сервере есть отдельный пользователь `brain` для мозга и бота;
- у сервера есть запас памяти (swap);
- под `brain` стоит Claude Code и работает **из твоей подписки**, а платного API-ключа нет нигде;
- на сервере лежит первая копия памяти и скиллов, личного в ней нет;
- главная копия мозга по-прежнему у тебя на компьютере.

| Шаг brain-link | Что делает | Где в модуле |
|---|---|---|
| `detect` | смотрит систему, ssh, Python, Файл доступа, сервер, часы; выбирает ветку A / B / C | Шаг 0 |
| `keys` | ключ для входа без пароля; закрепляет «отпечаток» сервера | Шаг 0 |
| `harden` | пользователь `brain`, swap, файрвол, fail2ban, обновления, часы | Шаг 1 (безопасность — модуль 05) |
| `claude` | Claude Code под `brain`, проверка «API-ключа нет» | Шаг 2 |
| `put-token claude` | ты сам выпускаешь токен подписки, он сразу уходит на сервер | Шаг 3 |
| `init` (или `adopt` для ветки B) | первая копия памяти и скиллов на сервере | Шаг 4 |

Запуск любого шага: скажи Claude Code *«Запусти brain-link, шаг <имя>»*. Команды для Mac и Windows — в [README](README.md).

> ⚠️ **Общий принцип.** Пароли, токены и IP — как ключи от квартиры. Не в чат, не в git, не скриншотами. Данные сервера живут в Файле доступа (`~/.config/brain/server_access`; Windows: `%USERPROFILE%\.config\brain\server_access`), токен подписки — только на сервере.

## Шаг 0. Знакомство с сервером: `detect` и `keys`

**`detect`** ничего не меняет. Он проверяет твою систему, `ssh`, Python, читает Файл доступа, заглядывает на сервер, сверяет часы и называет ветку.

**`keys`** создаёт на компьютере ключ (ed25519) и показывает **одну команду**, которую ты вводишь в терминал **сам**. Она один раз спросит пароль root (его берёшь из менеджера паролей; при вводе символы не видны — это нормально). После этого вход идёт по ключу, без пароля. Заодно `keys` запоминает «отпечаток» сервера: если однажды на этот адрес ответит другая машина, связка остановится и скажет об этом, а не будет молча работать с чужим сервером.

| Где ввести команду из `keys` | Mac | Windows |
|---|---|---|
| Открыть терминал | Cmd+Пробел → «Терминал» → Enter | Пуск → «PowerShell» → Enter |
| Что делать | вставить команду, которую показал brain-link, ввести пароль root | то же |

✅ **Получилось, если** brain-link написал, что вход по ключу работает, а пароль не появился ни в чате, ни в командах. Не пускает — модуль [08](08_ESLI_NE_VZLETELO.md), раздел «Подключение».

## Шаг 1. Отдельный пользователь для мозга и запас памяти (`harden`)

### 1.1. Почему отдельный пользователь `brain`

Бот и мозг **не живут под `root`** (всесильный администратор). `harden` заводит отдельного пользователя `brain`:
- если что-то пойдёт не так, «взрыв» ограничен его домашней папкой `/home/brain`;
- у `brain` нет пароля для входа и нет полного администраторского доступа. Подбирать нечего, ломать нечем;
- обслуживать сервер можно через `sudo brain-admin <команда>`: в ней короткий белый список безопасных действий (перезапустить бот, синхронизировать часы и т. п.).

Под `root` свежий Claude Code ещё и отказывается работать без экрана, так что отдельный пользователь нужен не только для безопасности.

### 1.2. Запас памяти — swap

На сервере 4 ГБ оперативной памяти. Claude Code и (по желанию) расшифровка голосовых — прожорливые соседи. **Swap** — запасной бак на диске: медленнее памяти, но не даёт процессам падать в пиковый момент. `harden` включает его так, чтобы он подключался сам после перезагрузки.

### 1.3. Остальное, что делает `harden`

Файрвол (наружу открыт только вход по ssh), fail2ban (банит перебор паролей), автоматические обновления безопасности, синхронизация часов. Подробно и зачем — модуль [05](05_BEZOPASNIK.md).

✅ **Получилось, если** `harden` закончил без ошибок и в итоге перечислил: пользователь `brain`, swap, файрвол, fail2ban, обновления, часы.

## Шаг 2. Claude Code на сервере (`claude`)

Шаг `claude` ставит Claude Code **официальным установщиком** под пользователем `brain` и проверяет:
- `claude --version` печатает версию;
- переменной `ANTHROPIC_API_KEY` нет нигде — ни в окружении, ни в файлах автозапуска (почему это важно — ниже);
- скиллы на сервере лежат в стандартном месте: `/home/brain/.claude/skills`. Туда их будет привозить синк с твоего компьютера.

✅ **Получилось, если** шаг напечатал версию Claude Code и строку о том, что API-ключа нет.

## Шаг 3. Токен подписки — самый важный шаг. Мозг работает «из подписки, а не с кошелька»

Прочитай раздел целиком: здесь легко сделать дорогую ошибку.

### 3.1. Две разные вещи, которые нельзя путать

| | Токен подписки (`CLAUDE_CODE_OAUTH_TOKEN`) | API-ключ (`ANTHROPIC_API_KEY`) |
|---|---|---|
| Что это | Вход по твоей **подписке** (Pro / Max) | Вход по **платному API** |
| Как считаются деньги | В рамках лимитов подписки | **За каждый запрос**, с карты |
| Аналогия | Проездной | Такси по счётчику |

Нам нужен **токен подписки**. И критично, чтобы **API-ключа на сервере не было**. Если он есть, Claude Code возьмёт его и начнёт считать по счётчику. Бот работает сам по себе, вызовов много, и ночь такой работы — неприятный сюрприз в счёте. Поэтому `brain-link` API-ключ не ставит нигде, а `verify` отдельно проверяет, что его нет.

### 3.2. Выделенный токен для сервера — его выпускаешь ты сам: `brain-link put-token claude`

**Подписка одна, входа два.** На компьютере Claude Code открывается твоим обычным входом. Серверу нужен **отдельный долгоживущий токен**, выпущенный командой `claude setup-token`.

> ⚠️ **Не копируй на сервер вход с ноутбука.** Обычный вход периодически обновляется, и серверная копия «протухает»: бот вдруг замолкает и пишет что-то про вход. Выделенный токен живёт своей жизнью и не зависит от того, что ты делаешь на ноутбуке.

Как это устроено:
1. Ты **сам** открываешь терминал и запускаешь `brain-link put-token claude` (команда — в таблице ниже). Агент эту команду не запускает и её вывод не читает.
2. Команда вызывает `claude setup-token`: откроется браузер, ты входишь под своей подпиской. Это пара минут.
3. Токен **сразу уходит на сервер**, в защищённое место, доступное только системе. Ввод скрыт, на экран и в чат он не попадает. **В Файл доступа токен не пишется.**

| Как запустить put-token | Mac | Windows |
|---|---|---|
| Открыть терминал | Cmd+Пробел → «Терминал» | Пуск → «PowerShell» |
| Команда | `python3 ~/.claude/skills/brain-link/scripts/brain_link.py put-token claude` | `py -3 "$env:USERPROFILE\.claude\skills\brain-link\scripts\brain_link.py" put-token claude` |

> 🔴 **Токен в чат не присылай никогда** — ни агенту, ни Александру, ни в чат потока. Если всё же прислал — запусти `put-token claude` заново: выйдет новый токен.

✅ **Получилось, если** команда закончилась сообщением, что токен на сервере, а в терминале и в чате не появилось строки, похожей на токен.

### 3.3. Выключи доплату сверх подписки

В настройках аккаунта Claude может быть включена доплата сверх лимитов подписки (usage credits / extra usage). Это те же деньги «с кошелька». Выключи её: тогда потолок — твой тариф. Кончился лимит — бот подождёт, а не потратит лишнее.

**Промпт для VS Code:**
> «Подскажи, где в настройках моего аккаунта Claude выключается доплата сверх подписки (usage credits / extra usage). Я выключу сам — проведи меня по шагам и скажи, как убедиться, что выключено.»

✅ **Получилось, если** в настройках аккаунта доплата сверх подписки выключена.

> 🧠 **Формула:** токен подписки на сервере + API-ключа нет + доплата выключена = мозг работает «из подписки» с известным потолком. Три условия вместе.

### 3.4. Проверка на стабильность

✅ **Получилось, если**
- бот (или проверка в `verify`) получает ответ модели по подписке;
- ты перезашёл в Claude Code на ноутбуке, а сервер продолжает отвечать как ни в чём не бывало. Значит, сервер живёт своим токеном.

## Шаг 4. Первая копия памяти на сервере — `brain-link init`

### 4.1. Где главная копия

**Главная копия мозга — на твоём компьютере.** Здесь ты правишь память, здесь ставишь скиллы, здесь Claude Code видит твои файлы. Сервер держит **копию**: её читает бот, чтобы отвечать с опорой на твою память. Синк `brain-sync` каждые 5 минут привозит туда твои правки, а обратно забирает то, что записал бот (`memory/inbox/` и `memory/dialogues/`). Кто чем владеет — модуль [04](04_ISTINA_I_BEKAPY.md).

### 4.2. Что едет на сервер, а что — нет

Едет:
- `memory/` — рабочая память, проекты, заметки;
- скиллы из `~/.claude/skills` — на сервере они лежат в `/home/brain/.claude/skills`;
- `CLAUDE.md` — правила системы.

**Не едет никогда, в обе стороны:**
- `personal/`, `private/`, `secret…`, `sessions/` — личное и служебное;
- `.secrets/`, `.config/`, `.git/`, файлы `.env`, `.session`, `.bak`, `.conflict-…`;
- любой файл больше 20 МБ.

Почему личное не едет: сервер — машина в дата-центре, доступная по сети, а бот читает память. Личному там не место. Это не паранойя, а гигиена: работник не носит с собой твой паспорт.

### 4.3. Как работает `init`

Для ветки A (чистый сервер) шаг `init` делает первую выгрузку:
1. показывает, сколько файлов поедет и сколько исключено как личное. Проверь глазами, что в «поедет» нет ничего из `personal/`;
2. копирует память и скиллы на сервер, права там ставит сам сервер (только `brain` читает);
3. запоминает состояние, чтобы следующие синки везли только изменения.

Для ветки B (уже переезжал по старой модели) вместо `init` запускается **`adopt`** — он аккуратно выключает старую схему (модуль [04](04_ISTINA_I_BEKAPY.md), раздел «Если ты переехал по старой модели»).

✅ **Получилось, если**
- `init` закончил без ошибок и показал число отправленных файлов;
- в списке исключённого есть `personal/` (если такая папка у тебя есть), а в отправленном её нет;
- позже, на шаге `verify`, проверка №4 «`personal` на сервере нет» зелёная.

### 4.4. Дальше

- `schedule` — синк по расписанию каждые 5 минут (launchd на Mac, Планировщик задач на Windows). Сразу делает пробный запуск и читает журнал;
- `bot` — стандартный бот (модуль [03A](03A_BOT_S_NULYA.md));
- `verify` — 8 проверок (модуль [06](06_QA_PROVERKA.md));
- `lockdown` — закрыть вход по паролю (модуль [05](05_BEZOPASNIK.md)).

## Итог модуля

1. **Пользователь `brain`** без пароля и без полного администраторского доступа; обслуживание — через `sudo brain-admin`.
2. **Swap** с автоподключением.
3. **Claude Code** под `brain`, официальным установщиком; скиллы в `/home/brain/.claude/skills`.
4. **Выделенный токен подписки** выпущен тобой через `brain-link put-token claude` и лежит только на сервере. **API-ключа нет**, доплата сверх подписки выключена.
5. **Первая копия памяти и скиллов** на сервере (`init`), личное осталось дома. Главная копия — на компьютере.

> 📎 Где живут секреты: данные сервера и токен бота — в Файле доступа на компьютере (права 600, на Windows — в твоей личной папке); на сервере токен подписки и токен бота лежат в закрытом месте (`/etc/brain-bot/credentials/`), куда не дотягивается даже модель, которую зовёт бот. В чате и в git их нет.
