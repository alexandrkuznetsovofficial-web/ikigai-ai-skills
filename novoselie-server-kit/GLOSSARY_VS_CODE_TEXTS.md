# 📖 Глоссарий и тексты для VS Code / Claude Code

### Справочник всех промптов кита «Новоселье» в одном месте (kit 2.1)

---

## Как этим пользоваться

Здесь собраны **все** ключевые тексты-промпты кита. Ты вставляешь их в Claude Code внутри VS Code, **на компьютере**, в папке своего второго мозга. Один справочник — чтобы не искать по модулям. Тексты совпадают с модулями 00–08; если где-то разошлись, верен модуль.

**Правила на всё время (агенту они прописаны в промптах, но знай их и ты):**

- 🧭 **Компьютер — мастерская, сервер — база.** Память и скиллы правишь на компьютере, синк `brain-sync` каждые 5 минут везёт их на сервер. Бот пишет только в `memory/inbox/` и `memory/dialogues/`, они приезжают к тебе.
- 🔑 **Данные сервера — в Файле доступа**, не в промптах и не в чате: Mac — `~/.config/brain/server_access`, Windows — `%USERPROFILE%\.config\brain\server_access`. Ключи: `SERVER_IP`, `SERVER_USER`, `SERVER_PORT`, `BOT_TOKEN`, `USER_ID`, временно `PASSWORD`.
- 🎟 **Токен подписки** в файлы и в чат не пишется. Ты сам запускаешь `brain-link put-token claude`, токен сразу уходит на сервер.
- 🔒 Остальные секреты — **по стандарту твоей ОС**: Windows — `%USERPROFILE%\.secrets\<имя-сервиса>\` (доступ только владельцу) или Диспетчер учётных данных; Mac — `~/.config/<имя-сервиса>/` (chmod 600) или Связка ключей. **Не в чат, не в код, не в git.**
- 🏠 Личное (**здоровье, семья, финансы**) на сервер не едет: `personal/`, `private/`, `secret…`, `sessions/` синк пропускает в обе стороны.
- 🧩 Плейсхолдеры: `<имя-сервиса>`, `<ТВОЯ-ТЕМА>` и т. п. Подставляй своё **на своей машине**, не пиши реальные значения в общие документы.

**Как запускать шаги brain-link** (Claude делает это сам; тебе команды нужны только в шагах `keys` и `put-token`):

| Что | Mac | Windows |
|---|---|---|
| Фраза для Claude | «Запусти brain-link, шаг <имя>» | то же |
| Команда шага | `python3 ~/.claude/skills/brain-link/scripts/brain_link.py <шаг>` | `py -3 "$env:USERPROFILE\.claude\skills\brain-link\scripts\brain_link.py" <шаг>` (PowerShell) |
| Расписание синка | launchd `com.ikigai.brain-sync` | Планировщик задач, `Ikigai brain-sync` |

Шаги: `detect`, `keys`, `harden`, `claude`, `put-token claude` / `put-token bot`, `init` или `adopt`, `schedule`, `bot` (`--voice`), `verify`, `lockdown`, а также `status`, `pause`, `resume`. Синк: `brain-sync pause`, `brain-sync resume`, `brain-sync run` (`--allow-mass-delete`).

**Мини-словарь терминов:**

| Термин | Простыми словами |
|--------|------------------|
| **VPS / сервер** | Твой компьютер «в облаке», всегда включён. У нас — вне РФ, Ubuntu 24.04. |
| **Мастерская** | Твой компьютер: здесь главная копия памяти и скиллов, здесь правишь. |
| **База** | Сервер: бот 24/7, утренний брифинг, копия памяти. |
| **brain-link** | Скилл-установщик связки. Проводит по шагам от `detect` до `lockdown`. |
| **brain-sync** | Синк «компьютер ↔ сервер» каждые 5 минут. |
| **Зона и хозяин** | У каждой папки один хозяин: память и скиллы — компьютер, `inbox/` и `dialogues/` — бот. |
| **`.conflict-…`** | Вторая версия файла, которую синк отложил тебе на разбор вместо того, чтобы молча выбросить. |
| **Файл доступа** | Защищённый файл с данными сервера. Ты заполняешь, агент читает сам — не через чат. |
| **VNC-консоль** | Аварийный вход на сервер из личного кабинета хостера. Работает, даже когда ssh закрыт. |
| **SSH** | Защищённый способ подключиться к серверу. |
| **Токен бота** | Секретный ключ Telegram-бота от BotFather. |
| **Токен подписки** | Ключ, по которому бот на сервере думает из твоей подписки. Выпускаешь через `put-token claude`. |
| **launchd / Планировщик / systemd** | Способ сказать системе «запускай это само по расписанию». |
| **chmod 600** | Права на файл «читать и писать может только владелец». Для секретов. |
| **pruf** | Явный признак «шаг удался». После каждого промпта смотри на него. |

> Порядок промптов ниже совпадает с порядком кита: аудит → Файл доступа → шаги brain-link → бот → где что живёт → безопасность → приёмка.

## Шаг 0 — Аудит: агент определяет твою ветку *(модуль 00)*

**Что делает:** только смотрит. Определяет систему, состояние Claude Code, папки мозга, сервера и бота и называет ветку: A (с нуля), B (старая модель → `adopt`), C (связка уже стоит → `verify`).

```text
Ты — мой технический помощник. Мы собираем связку «как у Александра»:
мой компьютер — мастерская (здесь ты видишь мои файлы, здесь я правлю память
и ставлю скиллы), сервер вне РФ — база (бот в Telegram 24/7, утренний брифинг,
копия памяти). Связывает их brain-sync каждые 5 минут. Ставит всё скилл brain-link.
Сейчас нужен АУДИТ. Ничего не меняй и не устанавливай — только посмотри и составь план.

Правила на всё время работы:
- Не выводи в чат пароли, токены и приватные ключи. Нашёл секрет — назови факт
  и путь к файлу, не содержимое.
- Данные сервера я не пишу в чат. Они лежат в моём Файле доступа:
  Mac — ~/.config/brain/server_access; Windows — %USERPROFILE%\.config\brain\server_access.
  Если файл лежит по старому пути (%USERPROFILE%\.secrets\brain\server_access.txt) —
  скажи об этом, перенесём на шаге detect.
- Личное (здоровье, семья, финансы) на сервер не переносим.

Проверь и дай короткий факт по каждому пункту:
1. Система и версия (Mac или Windows), есть ли ssh (`ssh -V`) и Python 3.
2. Claude Code: установлен ли, версия, вход по подписке или по API-ключу.
3. Папка второго мозга: где CLAUDE.md и memory/, есть ли локальный git
   и скилл auto-commit-backup.
4. Скилл brain-link: установлен ли в папку скиллов. Если да — запусти
   `brain-link detect` (он только смотрит) и перескажи результат.
5. Сервер: есть ли Файл доступа и сервер в нём. Если сервер есть — что на нём
   уже стоит (бот, ночное зеркало «сервер → компьютер», git-снимки), только чтение.
6. Telegram-бот: есть ли, где запущен (компьютер или сервер), где код
   и где токен (путь, не токен).
7. Расписания на компьютере: утренний брифинг, авто-коммиты, ночное зеркало.

Вывод:
A) Моя ВЕТКА:
   A — сервера нет или он чистый: ставим связку с нуля.
   B — я уже переезжал по старой модели «главная копия на сервере, компьютер — окно,
       ночное зеркало»: переводим через brain-link adopt.
   C — связка brain-link уже стоит: проверяем через brain-link verify.
B) Персональный план: какие шаги brain-link мне нужны и какие модули кита
   читать (00–10), что можно пропустить.
C) Не больше 3 уточняющих вопросов, только если без них план не собрать.

Пиши тепло и без жаргона. Я предприниматель, не технарь.
```

> ✅ **Получилось, если:** агент назвал систему, ветку (A, B или C) и дал план, а ни один секрет не появился в чате.

## Шаг 1 — 🔑 Файл доступа: данные сервера без чата *(модуль 01)*

**Что делает:** агент создаёт защищённый файл, открывает его тебе, ты вписываешь данные из письма хостера, агент проверяет и запускает `detect`. До этого: сервер вне РФ заказан, пароль root — в менеджере паролей.

```text
Хостер прислал мне данные сервера. Передаю их тебе БЕЗ чата — через «Файл доступа».
Сделай строго так:

1. Создай Файл доступа:
   - Mac: ~/.config/brain/server_access (папке права 700, файлу 600);
   - Windows: %USERPROFILE%\.config\brain\server_access.
   Если файл уже есть — НЕ перезаписывай: переходи сразу к проверке (шаг 4).
   Если есть файл по старому пути (%USERPROFILE%\.secrets\brain\server_access.txt)
   или со старыми ключами IP / LOGIN / PORT / CLAUDE_TOKEN — скажи мне, перенеси
   значения в новые ключи ниже, строку CLAUDE_TOKEN не переноси (токен подписки больше
   в файле не храним), а старый файл удали только после моего «да».
2. Запиши в файл ровно такой шаблон. Пустые поля оставь ПУСТЫМИ, примеров не вписывай:
   # Файл доступа к твоему серверу. НИКОМУ не пересылай.
   # Вставь значения СРАЗУ ПОСЛЕ знака «=».
   # SERVER_IP — четыре числа через точку из письма хостера.
   # PASSWORD — пароль root, целиком и как есть (любые символы — нормально).
   #   Нужен только до шага lockdown, потом строку удалим.
   # BOT_TOKEN — от @BotFather, USER_ID — твоё число от @userinfobot (модуль 03A).
   #   Если бота ещё нет — оставь пустыми, заполнишь позже.
   # Заполнил? Сохрани (Cmd+S / Ctrl+S) и напиши в чат: «готово».
   SERVER_IP=
   SERVER_USER=root
   SERVER_PORT=22
   PASSWORD=
   BOT_TOKEN=
   USER_ID=
3. Открой файл мне на экран (в VS Code: `code <путь-к-файлу>`; не выходит — напиши путь
   и попроси открыть самому) и одной фразой скажи, что куда вписать. Дальше ЖДИ «готово».
4. Когда я напишу «готово» — прочитай файл и ПРОВЕРЬ значения.
   Читай только строки КЛЮЧ=значение; строки на «#» — комментарии; значение — всё после
   ПЕРВОГО «=» (в пароле может быть «=»); пробелы по краям отбрасывай.
   - SERVER_IP: четыре числа 0–255 через точку (или имя сервера от хостера);
     НЕ 127.0.0.1, НЕ 0.0.0.0, НЕ 1.2.3.4; не в угловых скобках.
   - SERVER_USER: одно слово (сейчас root). SERVER_PORT: число (обычно 22).
   - PASSWORD: не пустой. Отвергай ТОЛЬКО если значение целиком в угловых скобках
     или равно «пароль» / «password» / «пример». Любые другие символы — нормально.
   - BOT_TOKEN и USER_ID могут быть пустыми. Если заполнены: USER_ID — только цифры;
     BOT_TOKEN — число, двоеточие и длинный хвост.
   Что-то не так — открой файл снова, скажи КОНКРЕТНО какую строку поправить, жди «готово».
5. Пароль и токен НИКОГДА не выводи в чат — ни целиком, ни частично — и не подставляй
   их в команды (текст команд виден в чате). IP показывать можно.
6. Проверь делом: запусти шаг `brain-link detect` (скилл brain-link; если его ещё нет —
   скажи, что поставим на встрече) и перескажи итог простыми словами.
   С этого момента данные сервера у меня не спрашивай — бери из Файла доступа.
```

> ✅ **Получилось, если:** Файл доступа открыт в VS Code, `SERVER_IP` и `PASSWORD` прошли проверку, пароль ни разу не появился в чате.

## Шаг 2 — Ядро: `detect → keys → harden → claude → put-token → init` *(модуль 02)*

**Что делает:** готовит сервер-базу и кладёт первую копию памяти. Каждый шаг запускается фразой; после каждого — признак.

```text
Запусти brain-link по шагам: detect, keys, harden, claude, init.
Перед каждым шагом коротко скажи, что он сделает. После каждого — покажи итог
и признак «получилось». Где нужна команда, которую ввожу я сам (keys) —
покажи её и жди моего «готово». Шаг put-token claude я запускаю сам в своём
терминале — подскажи команду для моей системы и жди, его вывод не читай.
Если detect сказал «ветка B» — вместо init запускай adopt (см. модуль 04, Часть 6).
Пароли и токены в чат не выводи.
```

| Шаг | Что делает | ✅ Признак |
|---|---|---|
| `detect` | смотрит систему, ssh, Python, Файл доступа, сервер, часы; называет ветку | названа ветка A / B / C |
| `keys` | ключ для входа без пароля; одна команда, которую вводишь **ты** (пароль root один раз); закрепляет ключ сервера | «вход по ключу работает» |
| `harden` | пользователь `brain`, swap, ufw (только ssh), fail2ban, обновления, часы, `brain-admin` | перечислено всё, без ошибок |
| `claude` | Claude Code под `brain`, проверка «API-ключа нет», скиллы в `/home/brain/.claude/skills` | версия Claude Code + «API-ключа нет» |
| `put-token claude` | **ты сам** в терминале: вызывает `claude setup-token`, токен сразу уходит на сервер | «токен на сервере», в терминале и чате токена нет |
| `init` | первая копия памяти и скиллов на сервере, личное исключено | число отправленных файлов, `personal/` в исключённом |

**Команда put-token, которую вводишь сам:**

| | Mac (Терминал) | Windows (PowerShell) |
|---|---|---|
| put-token | `python3 ~/.claude/skills/brain-link/scripts/brain_link.py put-token claude` | `py -3 "$env:USERPROFILE\.claude\skills\brain-link\scripts\brain_link.py" put-token claude` |

**Выключить доплату сверх подписки:**

```text
Подскажи, где в настройках моего аккаунта Claude выключается доплата сверх подписки
(usage credits / extra usage). Я выключу сам — проведи меня по шагам и скажи,
как убедиться, что выключено.
```

> ✅ **Получилось, если:** все шесть шагов дали свой признак, токен подписки ни разу не появился на экране, доплата сверх подписки выключена.

## Шаг 4 — Где что живёт, конфликты, пауза *(модуль 04)*

**Разобрать конфликты:**

```text
Найди в моей памяти файлы `.conflict-*`. По каждому покажи, чем он отличается
от основного файла. Предложи, что объединить, и сделай только после моего «да».
После объединения удали `.conflict-*`.
```

**Массовая правка памяти (memory-upgrade, garden_stage --apply, project-splitter):**

```text
Поставь brain-sync на паузу, сделай <правку>, потом brain-sync resume
и brain-sync run. Покажи brain-link status в конце.
```

**Проверить страховку:**

```text
Проверь мою страховку: (1) стоит ли auto-commit-backup и когда был последний снимок
`auto-backup` в git рабочей папки; (2) нет ли у папки мозга облачного адреса
(`git remote -v`) и стоит ли замок pre-push; (3) входит ли рабочая папка в Time Machine (Mac)
или «Историю файлов» (Windows). По каждому пункту — 🟢/🔴 и что сделать.
Ничего не меняй без моего «да».
```

**Вернуть испорченный файл:**

```text
Я испортил `<путь-к-файлу>`. Покажи историю этого файла в локальном git
(`git log --oneline -10 -- <путь>`), покажи предыдущую версию, я выберу нужную —
верни файл из неё. Остальное не трогай.
```

**Ветка B — уйти со старой модели:**

```text
У меня старая модель «главная копия на сервере + ночное зеркало». Запусти brain-link, шаг adopt.
Перед каждым шагом, где нужно моё «да», остановись и покажи, что именно будет сделано.
В конце покажи: что выключено, сколько файлов `.conflict-local`, что из личного забрано
домой и удалено ли оно на сервере.
```

> ✅ **Получилось, если:** конфликтов не осталось; после паузы синк свежий; последний снимок `auto-backup` не старше часа; (ветка B) старое зеркало выключено, личное с сервера дома, `verify` — 8 из 8.

## Шаг 5 — Безопасность: `harden` и `lockdown` *(модуль 05)*

**Проверка после harden (только чтение):**

### 🧷 Шпаргалка на холодильник

- **Компьютер — мастерская, сервер — база.** Правлю на компьютере, сервер получает копию за 5 минут.
- Бот пишет только в `memory/inbox/` и `memory/dialogues/` — у меня через 5 минут.
- Данные сервера → **Файл доступа** (Mac `~/.config/brain/server_access`; Windows `%USERPROFILE%\.config\brain\server_access`). **В чат — никогда.**
- Токен подписки → только `brain-link put-token claude`, сам, в своём терминале.
- Личное (здоровье, семья, финансы) → в `personal/`, на сервер **не** едет.
- Конфликт = файл `.conflict-…`, ничего не потеряно. Удалённое — в корзине сервера 30 дней.
- Массовая правка → `brain-sync pause` … `resume` + `run`.
- Бэкап → локальная история git (`auto-commit-backup`) + Time Machine / «История файлов».
- Аварийный вход → VNC-консоль хостера, пароль root — в менеджере паролей.
- Что-то сломалось → `brain-link status` → модуль 08.
