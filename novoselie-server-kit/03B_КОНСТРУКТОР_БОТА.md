# 03B · Конструктор бота: сначала спроектируйте — потом стройте

> **Для кого этот модуль.** Для двух моментов. **Момент 1:** вы собираетесь строить бота (по модулю [03A](03A_БОТ_С_НУЛЯ.md) или [03](03_ИНТЕГРАЦИЯ_БОТА.md)) и хотите заранее понять, ЧТО именно строите. **Момент 2:** первый бот уже работает, и вы задумали следующего — для команды, для клиентов, для приёма заявок. Второй бот — это всегда другой бот, и вот здесь без проектирования уже никак.

**Главная идея.** «Telegram-бот» — это не одна вещь, а конструктор. Личный ассистент, командный бот, бот для клиентов, фильтр заявок, вахтёр-мониторинг — снаружи все они «просто бот в телеграме», но внутри отличаются ответами на семь групп вопросов — от «кто может ему писать» и «что он помнит» до «как он запускается». У автора этого кита ботов больше десяти — и ни одна пара не совпадает по настройкам.

Ошибка на этом этаже стоит дороже всего. Не та аудитория — и чужие люди тратят вашу подписку. Не тот контур памяти — и командный бот пересказывает сотруднику ваши личные заметки. Не продуман запуск — и сырой бот позорится перед клиентами. Всё это лечится на этапе ТЗ за 15 минут разговора.

**Как работает модуль:** вы вставляете один промпт → агент берёт роль архитектора ботов и проводит интервью (вопрос — ответ, простым языком, с подсказками) → на выходе у вас файл **ТЗ вашего бота**. С этим файлом идёте строить: в 03A (бота ещё нет) или в 03 (бот есть — донастраиваем).

## Сначала карта: какие боты бывают

Шесть архетипов. Ваш будущий бот почти наверняка — один из них или смесь двух:

| Архетип | Кто пишет боту | Что он помнит | Фирменная черта |
|---|---|---|---|
| 🧠 **Личный ассистент** | только вы | вашу память целиком | утренний брифинг, «запомни», голосовые (это бот из модуля 03A) |
| 👥 **Командный бот** | 2–10 человек по списку | отдельный рабочий контур — личное не видит | живёт в рабочей группе, может сам вступать в разговор (с лимитами) |
| 🎓 **Бот для клиентов / учеников** | только те, кому выдан доступ | базу знаний продукта | отвечает каждому ровно по его тарифу; чужому — вежливый отказ со ссылкой «как попасть» |
| 📨 **Фильтр входящих** | клиенты, оставившие заявку (боту пишет их заявка — он начинает диалог сам) | анкету и историю переписки | задаёт вопросы, а вам приносит карточку-вердикт с кнопками «принять / подключиться / отклонить» |
| 🛰 **Вахтёр-мониторинг** | никто — входящих нет вообще | список источников и «что уже видел» | следит за темой (новости, цены, конкуренты) и пишет вам сам: дайджест по расписанию, тревога — немедленно |
| 🌍 **Публичный продукт** | любой желающий | базу пользователей | онбординг, рассылки, оплаты; максимум требований к безопасности |

**Оси конструктора** — то, чем эти архетипы на самом деле отличаются:

1. **Аудитория** — только владелец · список людей · купившие доступ · любой.
2. **Кто начинает разговор** — только человек · бот по расписанию · бот по событию.
3. **Жизнь в группах** — не живёт · слушает молча · отвечает на @упоминание · вступает сам (только с лимитами).
4. **Контур памяти** — личный мозг · отдельный рабочий контур · выгрузки «только чтение» · без памяти.
5. **Права** — только отвечает · действует после кнопки «Подтвердить» · действует сам (почти никогда).
6. **Проактивность** — молчун · будильник (по расписанию) · сторож (по событию) · советник (сам, но под лимитами).
7. **Ответ чужому** — молчание · вежливый отказ · отказ-воронка («вот как получить доступ»).
8. **Запуск** — сразу боевой (только личный бот) · сначала «тень», потом боевой.
9. **Движок** — из подписки (как весь этот кит) + сторож лимитов.
10. **Срок жизни** — постоянный · временный с автостопом (вахтёр под конкретное событие).

**Несовместимые комбинации** — конструктор их не соберёт, и вы не собирайте:

| ❌ Нельзя | Почему |
|---|---|
| Личная память + любая аудитория, кроме вас | Командному/клиентскому боту — отдельный контур. Изоляция делается архитектурой (отдельный пользователь на сервере), а не фразой «не рассказывай» в промпте |
| «Вступает сам в разговор» без лимитов | Без пауз, потолка реплик и стоп-слова бот душит чат и жжёт подписку |
| Бот к незнакомцам + запуск сразу в бой | Сначала режим «тень»: бот всё делает, но наружу не уходит ничего — вы читаете его черновики |
| Действия (рассылка, запись, оплата) без кнопки подтверждения | Читать и отвечать — свободно; менять и отправлять — только после вашего «Подтвердить» |
| Бот выдаёт себя за человека | Бот представляется ботом. Всегда. Это репутация — а местами уже и требование закона |
| Рассылка тем, кто не нажимал Start | Правило Telegram: бот может писать первым только тем, кто сам начал с ним диалог |

## Запуск конструктора

Откройте Claude Code и вставьте промпт целиком. Отвечайте на вопросы своими словами — агент сам переведёт их в технические решения. Не знаете ответа — так и говорите: у каждого вопроса есть безопасный вариант по умолчанию.

### 📋 Текст-промпт для VS Code (скопируйте целиком)

```
Ты — архитектор Telegram-ботов. Сейчас ты НЕ пишешь код. Твоя работа — провести со мной
интервью и спроектировать техническое задание (ТЗ) моего будущего бота.

ПРАВИЛА ИНТЕРВЬЮ:
- По ОДНОМУ вопросу за раз. Простым языком, я предприниматель, не технарь.
- К каждому вопросу — 2–4 варианта ответа с примерами из жизни и пометкой,
  какой вариант безопасный «по умолчанию», если я не уверен.
- Мои ответы переспрашивай, только если они противоречат друг другу.
- Адаптируйся: если из ответов ясно, что бот личный — пропускай клиентские ветки
  (вопрос 3 — база доступов, 8 — уровни видимости, 13 — текст отказа);
  если бот-вахтёр без входящих — пропускай вопросы про группы.
- Замечаешь несовместимую комбинацию (список ниже) — останови и объясни, что
  выбрать вместо неё.

НЕСОВМЕСТИМО (блокируй): личная память + чужая аудитория · проактивность в группе
без лимитов · исходящие незнакомым людям сразу в боевом режиме · действия без
кнопки подтверждения · бот, выдающий себя за человека · рассылки тем, кто не
нажимал Start.

ИНТЕРВЬЮ — 7 БЛОКОВ:

БЛОК 1 · РАБОТА БОТА
1. Какую работу бот делает? Опиши день с ботом: что присылаешь, что он отвечает,
   что делает сам. (Помоги мне примерами: ассистент с брифингом; ответы клиентам;
   приём заявок; слежение за темой.)
2. Как через месяц поймёшь, что бот удался? Один измеримый критерий
   (сэкономленные часы, скорость ответа клиенту, ни одного пропущенного лида).

БЛОК 2 · АУДИТОРИЯ
3. Кто может писать боту? (только я / семья / команда — перечисли людей /
   клиенты с доступом / любой). Для команды и клиентов: откуда бот узнаёт,
   что человек «свой» — фиксированный список id или база доступов?
4. Пишет ли бот кому-то ПЕРВЫМ? (никогда / мне по расписанию — брифинг, дайджест /
   пользователю по событию — новая заявка, напоминание). Напомни мне правило
   Telegram: первым — только тем, кто уже нажал Start у этого бота.
5. Будет ли бот жить в группе? Если да — какой режим:
   а) слушает молча (копит контекст, не отвечает),
   б) отвечает только на @упоминание или ответ на его сообщение,
   в) вступает сам — тогда сразу спроси лимиты: пауза между репликами
      (по умолчанию 3 мин), потолок реплик в час (по умолчанию 4),
      стоп-слово, которым я его глушу.

БЛОК 3 · ПАМЯТЬ И ДАННЫЕ
6. На какие данные бот опирается? (моя память на сервере / отдельная рабочая
   папка / база клиентов / внешние источники — сайты, новости)
7. КРАСНЫЙ СПИСОК: чего бот не должен видеть никогда? Пройдись по каждому пункту
   со мной: здоровье · семья · личные финансы · личные переписки · данные других
   людей. Если аудитория бота — не только я, красный список обязателен, и в ТЗ
   должно попасть: отдельный контур памяти = отдельный пользователь на сервере
   (изоляция архитектурой, не обещанием в промпте).
8. Если бот знает что-то о людях (клиенты, участники, ученики): три уровня
   видимости — что можно показывать всем · что можно использовать только внутри
   (для подбора/аналитики, без цитат) · что не выходит наружу никогда (сырые
   цитаты, личные истории). Даже «своим» бот не пересказывает чужие слова дословно.

БЛОК 4 · ПРАВА И ХАРАКТЕР
9. Бот только отвечает — или ДЕЛАЕТ (отправляет рассылку, пишет в таблицу, ставит
   задачу)? Каждое действие, которое что-то меняет или отправляет, — только после
   моей inline-кнопки «Подтвердить». Читать/отвечать — свободно.
10. Проактивность: молчун / будильник (что и во сколько присылает) / сторож
    (какое событие будит) / советник в группе (только с лимитами из вопроса 5в).
    Если это уже прозвучало в вопросе 4 — не спрашивай заново, только уточни детали.
11. Голос: как бота зовут, на «ты» или на «вы», тон (деловой/тёплый/краткий).
    Бот всегда представляется ботом-помощником — не человеком.

БЛОК 5 · ЗАМКИ БЕЗОПАСНОСТИ — это «четыре замка» из модуля 03A + турникет для
входа снаружи. Не спрашивай «нужно ли» — спрашивай параметры.
12. Whitelist ДО движка: сообщение не от разрешённого человека → отказ без вызова
    модели. Для ВСЕХ типов входа: текст, голосовые, фото, файлы, кнопки.
13. Что видит чужой: полное молчание (для личного) / вежливый отказ / отказ-воронка:
    «доступ выдаётся там-то» — отказ работает как реклама, а не как стена. Что
    написать в отказе?
14. Токены и ключи — только в защищённом файле на сервере (права 600): не в коде,
    не в чате, не в git. Это не вопрос, а строка ТЗ.
15. Алерт хозяину: чужой постучался / ошибка / бот упал → сообщение мне (не чаще
    1 раза в час, чтобы не спамить).
16. Если у бота будет вход «снаружи» (кнопка на сайте, публичная ссылка) — турникет
    от слива подписки, 4 уровня: (1) запросы только со своей страницы; (2) мусорный
    ввод отсекается ДО модели; (3) нет данных для обработки → модель не вызывается;
    (4) лимит запросов с одного адреса + счётчик. Тест: «если скрипт дёрнет бота
    10 000 раз за ночь — что произойдёт?» Ответ должен быть: «ничего страшного».

БЛОК 6 · ЧЕСТНОСТЬ И ГРАНИЦЫ
17. Чего бот НЕ делает и по каким вопросам зовёт живого человека? (по умолчанию:
    деньги, доступы, жалобы, «не знаю ответа» — бот не выдумывает никогда, лучше
    «позову хозяина», чем красивая выдумка)
18. Если бот читает группу: участники должны об этом знать (строка в правилах
    чата/онбординге). Впиши в ТЗ.

БЛОК 7 · ЖИЗНЬ И РОСТ
19. Запуск фазами — предложи план: скелет → функции → замки́ → ТЕНЬ (если аудитория
    не только я: бот работает, но наружу молчит, я читаю черновики) → боевой режим
    моим решением.
20. Срок жизни: постоянный или под событие (тогда — дата автостопа)?
21. Тест на масштаб: что изменится при 10× пользователей? Где появится ручная
    работа, которой не должно быть?

КОГДА ОТВЕТЫ СОБРАНЫ — СГЕНЕРИРУЙ ФАЙЛ ТЗ_бота_<имя>.md:

# ТЗ: <имя бота>
## 1. Работа и критерий успеха     ← блок 1
## 2. Аудитория и доступ           ← кто пишет, кто первым, группы, режимы
## 3. Память                       ← контур, красный список, уровни видимости,
##                                    отдельный пользователь на сервере (да/нет)
## 4. Права и проактивность        ← действия-с-кнопкой, расписание, лимиты советника
## 5. Замки́                        ← whitelist до движка (все типы входа), ответ
##                                    чужому, токены 600, алерты, турникет
## 6. Границы и честность          ← голос и тон (вопрос 11), эскалация к человеку,
##                                    «представляюсь ботом», предупреждение в группе
## 7. Инфраструктура               ← сервер 24/7, работа НЕ от root (изолированный
##                                    пользователь), автозапуск с самоподъёмом после
##                                    падения, движок из подписки + сторож лимитов,
##                                    бэкапы, автостоп
## 8. План запуска фазами          ← с фазой «тень», если аудитория шире владельца;
##                                    сюда же — вывод теста на масштаб (вопрос 21)
## 9. Чек-лист приёмки             ← 5–8 проверок «готово, если…», которые я смогу
##                                    прогнать сам (по образцу Pruf из этого кита)

В конце скажи: с этим ТЗ иди в модуль 03A (бота ещё нет) или 03 (бот есть) — и
приложи ТЗ агенту первым сообщением перед промптами модуля. Если по ТЗ нужен
ОТДЕЛЬНЫЙ контур памяти — напомни: новый изолированный пользователь на сервере,
свой токен бота, своя папка, и личный мозг туда не монтируем.
```

> 💡 **Хотите, чтобы конструктор остался навсегда?** Скажите агенту: «Сохрани этот промпт как скилл с триггером „спроектируй бота“» — и в любой момент будете запускать интервью одной фразой.

### ✅ Pruf — получилось, если…

- агент задавал вопросы **по одному** и предлагал варианты, а не вывалил анкету простынёй;
- у вас появился файл `ТЗ_бота_<имя>.md`, и в нём заполнены все 9 разделов;
- в разделе «Замки́» стоит whitelist **до** вызова движка — для текста, голосовых, фото, файлов и кнопок;
- если аудитория шире вас одного — в ТЗ есть отдельный контур памяти и фаза «тень»;
- вы можете пересказать своё ТЗ партнёру за две минуты, не заглядывая в файл.

## Пример: как выглядит результат (сжатый)

Студия, владелец + 2 менеджера. Ответы: «бот принимает заявки клиентов с сайта, менеджеры дособирают детали, я вижу карточку с кнопками» → конструктор собирает:

- **Архетип:** фильтр входящих + командный (смесь).
- **Аудитория:** менеджеры по списку id; клиент общается с ботом только после того, как сам нажал Start по ссылке с сайта.
- **Память:** отдельный рабочий контур (заявки, регламенты). Красный список: финансы владельца, личное. Отдельный пользователь на сервере — да.
- **Права:** отвечает свободно; отправка предложения клиенту — после кнопки «Подтвердить» менеджера.
- **Замки́:** whitelist до движка; чужому в личке — «Оставьте заявку на сайте …»; турникет на веб-вход (форма на сайте); алерт владельцу при 3+ отказах за час.
- **Запуск:** 2 недели «тени» (карточки приходят, клиентам не уходит ничего) → боевой.
