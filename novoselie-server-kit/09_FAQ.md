# ❓ FAQ обывателя — память, бэкапы, источник истины, доступ бота

Простыми словами, без технического тумана.

## 1. Где хранится память — на компьютере или на сервере?
**В трёх местах сразу, но главный — сервер.**
- 🖥 **Сервер (папка мозга пользователя `brain`: `~/memory`, `~/skills`) — ИСТОЧНИК ИСТИНЫ.** Здесь живёт бот 24/7 и читает память отсюда. Это «оригинал». Правки вносим здесь.
- 📸 **Снимки на сервере** — git-история внутри самого сервера, коммит каждый час, **без облака** (модуль 04, Слой 1). Это машина времени: испортил файл — откатился на час назад.
- 💻 **Ночное зеркало на компьютере** — каждую ночь компьютер сам забирает копию с сервера (модуль 04, Слой 2). Это копия для чтения и восстановления, а не место для правок. Дальше её подхватывает штатный бэкап компьютера (Time Machine / История файлов).

Личное (`personal/`, `sessions/`, диалоги) живёт **только на компьютере**: на сервер оно не едет, а ночное зеркало его не трогает.

🔴 **Память в GitHub не отправляем никогда** — даже в приватный репозиторий. Приватный репозиторий однажды открывают по ошибке, к аккаунту подбирают пароль, а из истории git удалить уже отправленное почти невозможно. GitHub — только для кода и скиллов (подробно — скилл `auto-commit-backup`).

## 2. Что является источником истины?
**Сервер.** Потому что именно с него работает бот круглосуточно. Логика: ты правишь на сервере (из VS Code по SSH или с планшета через туннель) → сервер = то, что реально действует → снимок фиксирует версию каждый час → ночью копия уезжает к тебе домой. Течёт всегда в одну сторону: **сервер → копии**.

## 3. Как делаются бэкапы, как часто, где лежат?
Правило **3-2-1**: 3 копии, 2 разных места, 1 — вне сервера.
| Что | Как | Частота | Где лежит |
|---|---|---|---|
| Память (MD) — история версий | git-снимок **на сервере**, без отправки в облако | каждый час | на сервере |
| Память (MD) — копия вне сервера | ночное зеркало `rsync` сервер → ПК | каждую ночь | твой компьютер + его штатный бэкап |
| База/состояние бота (`.db`, `.session`) | дамп в папку, которую забирает ночное зеркало, или шифрованный бэкап (restic) | раз в сутки | компьютер / шифрованное хранилище |
| Перед любой опасной правкой | ручной бэкап-копия | по событию | папка бэкапов на сервере |

**Важно:** бэкап, который ни разу не разворачивали, — не бэкап. Раз в месяц открой ночное зеркало и проверь, что свежие заметки там есть.

🔴 **Удалённое возвращается.** Убрал что-то на сервере — проверь, что этого нет и в зеркале на ПК, и наоборот. Чувствительное удаляют **в обоих местах** (подробно — модуль 04, Часть 3.5).

## 4. К чему имеет доступ бот, а к чему — нет?
**Бот видит ровно то, что ты ему дал, и ничего сверх.**

✅ **Имеет доступ:**
- Файлы памяти мозга на сервере — это его «знания» (отвечает на их основе).
- Свои собственные секреты из `.env` (его токен Telegram, ключ модели) — чтобы работать.
- То, что ты явно закодил ему уметь (написать тебе, искать по памяти и т.п.).

❌ **НЕ имеет доступа (и не должен):**
- Твои другие аккаунты, твой компьютер, секреты вне его `.env`.
- Он отвечает **только тебе** (авторизованному), а не случайным людям — если ты не открыл публичный эндпоинт (тогда обязателен «турникет», см. файл 04).

🔴 **Тонкость безопасности (почему секреты НЕ кладём в память):** бот читает память мозга на сервере. Если положить туда пароль/токен в текст MD-файла — бот сможет его «вспомнить» и выдать, плюс он попадёт в снимки git и в зеркало. Поэтому **секреты живут только в `.env`/`~/.config` (права 600), которых нет в памяти и нет в git.** Память — для знаний, не для ключей.

## 5. Если что-то сломалось — что делать?
1. Не паникуй: бот настроен на авто-перезапуск (`systemd Restart=always`) — после сбоя/перезагрузки поднимается сам.
2. Зайди на сервер (с компьютера), посмотри `journalctl -u brain-bot -n 50`.
3. Память цела в ночном зеркале на компьютере — в худшем случае поднимаешь сервер заново и заливаешь мозг из зеркала (модуль 04, Сценарий B).
4. Потерял доступ к серверу — заходи через **VNC-люк хостера** (см. файл 03, часть C).

## 6. Коротко: что у меня в итоге?
- Мозг (MD) на сервере = источник истины, бот читает его 24/7. Правки — на сервере.
- Копии: снимки на сервере (каждый час) + ночное зеркало на компьютере. В GitHub память не уходит.
- Секреты — отдельно, в `.env` 600, не в памяти и не в git.
- Доступ: с компьютера (база) + опционально с планшета (надстройка-туннель).
- Сломалось — само поднимается; не поднялось — есть бэкап и аварийный люк.
