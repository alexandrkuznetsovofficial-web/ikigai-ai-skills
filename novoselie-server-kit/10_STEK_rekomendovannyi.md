# 🧰 Рекомендованный стек — проверенные связки под нас

> Подобрано под нашего участника: предприниматель, не сисадмин, работает через **Claude Code в VS Code** на **Mac или Windows**. Модель kit 2.1: **компьютер — мастерская** (главная копия памяти), **сервер вне РФ — база** (бот 24/7 и копия памяти), синк каждые 5 минут (модуль [04](04_ISTINA_I_BEKAPY.md)). Каждый инструмент — зрелый, с большим сообществом, бесплатный или почти. Два трека: **A — простой (всем)**, **B — про (по желанию)**.

## Карта «потребность → инструмент»
| Потребность | Берём (Трек A) | Почему именно это | Трек B (про) |
|---|---|---|---|
| Бот работает 24/7 | **systemd** (встроен в Ubuntu), стандартный бот `brain-link bot` под пользователем `brain` | стандарт Linux, `Restart=always` — сам поднимается после сбоя и перезагрузки | pm2 (если свой бот на Node) |
| Безопасный вход на сервер | **ssh по ключу** (`lockdown`) + **ufw** + **fail2ban**, без белого списка IP | одна дверь наружу, и она на ключе; меняющийся адрес не запирает хозяина (модуль [05](05_BEZOPASNIK.md)) | Tailscale как дополнительный слой (модуль [07](07_DOSTUP_Tailscale_i_planshet.md)); Headscale — свой сервер управления |
| Мозг с телефона и планшета | **Telegram-бот**: вопросы, «запомни», голос, ссылки | память правится на компьютере, бот кладёт новое в `memory/inbox/` (модуль [07](07_DOSTUP_Tailscale_i_planshet.md)) | VS Code `code tunnel` → vscode.dev к **компьютеру**, не к серверу (на сервере — копия) |
| Память: синк компьютер ↔ сервер | **`brain-sync`** каждые 5 минут — Mac: launchd `com.ikigai.brain-sync`; Windows: Планировщик задач, задача `Ikigai brain-sync` | у каждой папки один хозяин: правки не теряются, удалённое не воскресает, личное не уезжает | — |
| Память: история и бэкап | **`auto-commit-backup`** — локальная история git на компьютере каждые 30 минут + Time Machine (Mac) / «История файлов» (Windows). **Память в GitHub не отправляем никогда** | откат на полчаса назад без облака; сервер пересобирается шагами `brain-link` | restic / borg (шифрованные снимки на свой диск или в хранилище, ключ только у тебя) |
| Веб-эндпоинт (если нужен сайт/вебхук) | **Caddy** | авто-HTTPS «из коробки», конфиг в 1 строку — проще nginx для новичка | nginx (если уже умеешь) |
| Секреты (ключи, токены) | на компьютере — Файл доступа `~/.config/brain/server_access` (Windows: `%USERPROFILE%\.config\brain\server_access`); на сервере — `/etc/brain-bot/credentials/` (root, 0600), бот получает их через `LoadCredential` | вне папки мозга: ничего не утечёт в git, в синк и в модель | sops + age (шифрованные секреты в репо) |
| Кто обслуживает сервер | **Claude Code на компьютере** через скилл `brain-link`; на сервере — `sudo brain-admin` с белым списком команд | ты не пишешь команды руками; root-вход после `lockdown` закрыт | — |
| Резервный вход, если всё сломал | **VNC / Recovery-консоль хостера** (FoxCloud) | работает, даже когда SSH/сеть мертвы — это твоя страховка от самоблокировки | — |

## Почему именно так (ключевые решения)
- **Ключ + fail2ban, без белого списка IP.** Белый список IP однажды закрывает дверь перед самим хозяином: адрес меняется в дороге и в мобильном интернете. Вход только по ключу закрывает перебор паролей полностью, fail2ban отсекает роботов, а VNC-консоль — запасной вход. Tailscale можно добавить сверху, но не вместо этого (модуль [07](07_DOSTUP_Tailscale_i_planshet.md)).
- **Главная копия памяти — на компьютере.** Здесь Claude Code видит твои файлы, «Загрузки» и скиллы. Сервер держит копию для бота, `brain-sync` обновляет её каждые 5 минут. Если сервер умрёт, мозг цел: новый собирается шагами `brain-link`, память на него заливает `brain-link init`.
- **Бэкап — локальная история git на компьютере** (`auto-commit-backup`) плюс бэкап системы. Почему не GitHub: память — это заметки о тебе, людях и деньгах; приватный репозиторий открывают по ошибке, а из истории git отправленное не вычистить. **GitHub — только для кода и скиллов, без памяти и секретов.**
- **Модель — только через `claude -p` по подписке**, без `ANTHROPIC_API_KEY`: ключ уводит на платный счётчик.
- **Caddy** берём только если реально нужен веб; боту с Telegram он не обязателен.

## Философия (Карпаты-aligned — честно)
У Андрея Карпаты **нет** готового «стека бота-на-сервере» — у него **подход**: своё, минимальное, хакабельное, под твоим контролем (`nanochat` — собери свой ChatGPT за $100; `autoresearch` — агент сам крутит цикл ночью). Мы берём этот дух: не арендованная платформа-чёрный-ящик, а **твой дом**, где агент работает на тебя 24/7, а ключ — у тебя.

## Что НЕ берём (чтобы не усложнять новичку)
- Тяжёлые self-host PaaS (Coolify/CapRover) — мощно, но избыточно для одного бота. Это уже Трек B для тех, кто захочет «как у больших».
- Docker на старте — не обязателен; systemd проще и прозрачнее для первого переезда.
- Kubernetes — нет.
