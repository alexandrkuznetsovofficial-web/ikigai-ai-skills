# Модуль 02 · Ядро переезда: второй мозг едет на сервер

> Ты прошёл аудит (Модуль 01) и решил: мозг переезжает на VPS. Дальше — общее ядро для всех. Не важно, Windows у тебя, Mac или Linux: сама операция происходит **на сервере**, а с локальной машины ты просто отдаёшь команды и один раз переносишь файлы.

**Зачем этот модуль.** Пока твой второй мозг живёт на ноутбуке — он спит вместе с ноутбуком, зависит от того, открыт ли VS Code, и умирает, если ноутбук потеряется. Сервер работает 24/7, переживает перезагрузки и не зависит от того, где ты. Мы делаем так, чтобы мозг жил там сам по себе — и делал это безопасно.

**Что получится в конце модуля:**
- на сервере есть отдельный, изолированный пользователь для мозга;
- у сервера есть запас памяти (swap), чтобы он не падал под нагрузкой;
- на сервере установлен Claude Code;
- он работает **из твоей подписки**, а не «с кошелька» (это ключевой момент — объясню почему);
- твои навыки (skills) и память (memory) лежат на сервере — и именно сервер теперь «источник истины»;
- твой **личный контур остался на ноутбуке** и на сервер не уехал.

**Плейсхолдеры, которые встретишь ниже** (подставляй свои значения, никому не показывай):
- `<IP>` — IP-адрес твоего сервера;
- `<SERVER>` — удобное имя-ярлык сервера (как ты его назовёшь в SSH);
- `<name>` — короткое имя твоего мозга/проекта (например, имя папки конфига);
- `<USER>` — имя пользователя на сервере (в этом модуле мы создадим пользователя `brain` — можешь оставить так).

> ⚠️ **Общий принцип безопасности.** Токены, пароли и IP — это как ключи от квартиры. Не вставляй их в чаты, не коммить в git, не отправляй скриншотами. Ниже везде, где нужен секрет, стоит плейсхолдер — так и держи.

## Шаг 0. Как мы будем «разговаривать» с сервером

Весь модуль ты работаешь в **VS Code** с расширением Claude Code. Модель сама выполняет команды на сервере через SSH — тебе нужно только давать ей точные задачи (промпты) и проверять результат по метке «✅ Получилось, если…».

**Правило хорошего промпта в этом ките:** одна задача — один промпт. Не проси «настрой мне всё сразу». Идём по шагам: так проще заметить, где что пошло не так, и откатиться.

Прежде чем начать, убедись, что ты можешь зайти на сервер. В VS Code открой терминал и подключись:

**Промпт для VS Code:**
> «Подключись к моему серверу по SSH: `ssh <USER-админ>@<IP>`. Если подключение прошло — покажи вывод команды `whoami` и `uname -a`, чтобы я убедился, что мы на сервере.»

✅ **Получилось, если…** в ответ ты видишь имя пользователя сервера и строку про Linux (например, Ubuntu). Если SSH не пускает — вернись к модулю про доступ к серверу, дальше идти рано.

## Шаг 1. Отдельный пользователь для мозга + права + запас памяти

### 1.1. Почему отдельный пользователь

Мы не селим мозг под `root` (всесильный администратор) и не мешаем его с другими сервисами. Заводим **отдельного изолированного пользователя** — назовём его `brain`. Плюсы:
- если что-то пойдёт не так, «взрыв» ограничен домашней папкой этого пользователя;
- у мозга своя песочница: свои файлы, свои настройки, свой git;
- чужие сервисы на сервере не видят его данные.

Пользователь создаётся **без пароля для входа** (`--disabled-password`) — заходить к нему мы будем не паролем, а через администратора сервера. Так безопаснее: нет пароля — нечего подбирать.

**Промпт для VS Code:**
> «На сервере создай изолированного пользователя `brain` без пароля и закрой его домашнюю папку от посторонних:
> ```bash
> sudo adduser --disabled-password --gecos "" brain
> sudo chmod 700 /home/brain
> ```
> Потом покажи `ls -ld /home/brain` и `id brain`, чтобы я убедился, что пользователь создан и папка закрыта.»

✅ **Получилось, если…**
- `id brain` показывает нового пользователя;
- `ls -ld /home/brain` начинается с `drwx------` (это и есть `700` — «вижу только я»).

> 💡 `chmod 700` означает: владелец папки может всё, а больше — никто. Для личного мозга это правильный уровень.

### 1.2. Запас памяти — swap

Сервер, особенно недорогой VPS, может иметь немного оперативной памяти (RAM). Когда её не хватает — процессы падают. **Swap** — это «резервный бак»: кусок диска, который система использует как медленную доп-память. Он не заменяет RAM, но не даёт мозгу упасть в пиковый момент.

Сделаем swap на 2 гигабайта и пропишем его так, чтобы он подключался сам после перезагрузки.

**Промпт для VS Code:**
> «Создай на сервере swap-файл на 2 ГБ и включи его на постоянной основе:
> ```bash
> sudo fallocate -l 2G /swapfile
> sudo chmod 600 /swapfile
> sudo mkswap /swapfile
> sudo swapon /swapfile
> echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
> ```
> После этого покажи `swapon --show` и `free -h`.»

✅ **Получилось, если…**
- `swapon --show` показывает строку с `/swapfile` и размером `2G`;
- `free -h` в строке `Swap` показывает `2.0Gi`;
- строка `/swapfile ... swap` появилась в `/etc/fstab` (это гарантирует, что swap вернётся после ребута).

> 💡 `chmod 600` на swap обязателен: файл памяти не должен читать никто, кроме системы.

## Шаг 2. Устанавливаем Claude Code на сервер

Дальше всё делаем **от имени пользователя `brain`** — мозг должен жить в своей песочнице, а не под администратором.

Ставим Claude Code **официальным установщиком**. Не скачивай сборки со сторонних сайтов — только официальный адрес.

**Промпт для VS Code:**
> «Переключись на пользователя `brain` и установи Claude Code официальным установщиком, от его имени:
> ```bash
> sudo -u brain -i bash -lc 'curl -fsSL https://claude.ai/install.sh | bash'
> ```
> После установки проверь версию: `sudo -u brain -i bash -lc 'claude --version'`.»

✅ **Получилось, если…** команда `claude --version` печатает номер версии без ошибок. Если терминал пишет «command not found» — скорее всего, не подхватился PATH: попроси модель перелогинить пользователя (`sudo -u brain -i`) и повторить проверку.

> 💡 Мы ставим Claude Code именно под `brain`, чтобы его настройки и токен лежали в домашней папке `brain` (которую мы закрыли на `700`), а не где попало.

## Шаг 3. Токен подписки — самый важный шаг. Мозг работает «из подписки, а не с кошелька»

Это место, где легко сделать дорогую ошибку. Прочитай раздел целиком, прежде чем запускать команды.

### 3.1. Две разные вещи, которые нельзя путать

Есть **два способа**, которыми Claude Code может авторизоваться:

| | Токен подписки (`CLAUDE_CODE_OAUTH_TOKEN`) | API-ключ (`ANTHROPIC_API_KEY`) |
|---|---|---|
| Что это | Вход по твоей **подписке** | Вход по **платному API** |
| Как считаются деньги | В рамках **месячного кредита подписки** — как «безлимит по тарифу» с потолком | **Поштучно за каждый запрос**, списывается с баланса/карты |
| Аналогия | Проездной на месяц | Такси по счётчику |

Нам нужен **токен подписки**. И — критично — нам нужно **убедиться, что API-ключа на сервере НЕТ**. Потому что если на сервере окажется `ANTHROPIC_API_KEY`, Claude Code возьмёт **его** и начнёт считать по счётчику — то есть тратить деньги «с кошелька» за каждый вызов. А мозг работает автономно и может делать много вызовов. Ночь такой работы по счётчику — неприятный сюрприз в биллинге.

Поэтому правило: **токен подписки ставим, API-ключ убираем и не ставим никогда.**

### 3.2. Получаем токен подписки на локальной машине

Токен рождается там, где ты уже залогинен в свою подписку — на **локальной машине**. Не на сервере.

**Промпт для VS Code (выполняется на ЛОКАЛЬНОЙ машине, не по SSH):**
> «На моей локальной машине выполни `claude setup-token`. Это откроет вход в мою подписку. Дождись, пока команда выдаст токен вида `CLAUDE_CODE_OAUTH_TOKEN=...`. **Не сохраняй его в файл проекта, не выводи в чат целиком и не коммить.** Просто скажи, что токен получен, и подожди, пока я перенесу его на сервер.»

✅ **Получилось, если…** команда завершилась и показала, что токен выпущен. Сам токен — это секрет уровня пароля: обращайся с ним соответствующе.

### 3.3. Кладём токен на сервер в защищённое место

Токен должен лежать в конфиге пользователя `brain`, в закрытой папке, с правами `600` (читает только владелец).

**Промпт для VS Code:**
> «На сервере, от имени пользователя `brain`, создай защищённую папку конфига и положи туда токен подписки:
> ```bash
> sudo -u brain -i bash -lc 'mkdir -p ~/.config/<name> && chmod 700 ~/.config/<name>'
> ```
> Затем помоги мне записать в файл `~/.config/<name>/env` строку `CLAUDE_CODE_OAUTH_TOKEN=<мой токен>` (значение я вставлю сам, не подставляй его в промпт) и поставь на файл права `600`:
> ```bash
> sudo -u brain -i bash -lc 'chmod 600 ~/.config/<name>/env'
> ```
> Покажи `ls -l ~/.config/<name>/` — но НЕ выводи содержимое файла `env`.»

✅ **Получилось, если…**
- `ls -l` показывает файл `env` с правами `-rw-------` (это `600`);
- содержимое файла **не** мелькнуло в терминале.

### 3.4. Убираем API-ключ и включаем режим «только подписка»

Теперь — защитный шаг, тот самый, который бережёт кошелёк.

**Промпт для VS Code:**
> «Проверь, что на сервере у пользователя `brain` НЕТ переменной `ANTHROPIC_API_KEY`, и убедись, что она нигде не задаётся:
> ```bash
> sudo -u brain -i bash -lc 'env | grep -i ANTHROPIC || echo "нет ANTHROPIC-переменных — хорошо"'
> sudo -u brain -i bash -lc 'grep -RIn "ANTHROPIC_API_KEY" ~/.bashrc ~/.profile ~/.config 2>/dev/null || echo "ANTHROPIC_API_KEY нигде не прописан — хорошо"'
> ```
> Если где-то `ANTHROPIC_API_KEY` найдётся — покажи мне, где, и убери его (`unset` в текущей сессии + удали строку из файла автозапуска). Оставить нужно ТОЛЬКО `CLAUDE_CODE_OAUTH_TOKEN`.»

✅ **Получилось, если…** обе команды говорят, что `ANTHROPIC`-переменных / `ANTHROPIC_API_KEY` нет. Значит, Claude Code сможет авторизоваться только токеном подписки — «по проездному».

**Отдельно — выключить usage credits (потолок = месячный кредит подписки).**

«Usage credits» — это возможность доплачивать сверх месячного лимита подписки (те же деньги «с кошелька», просто из другого кармана). Мы их **выключаем**. Тогда потолок мозга — это твой месячный кредит подписки, и ни центом больше: как только он выбран, мозг просто ждёт следующего периода, а не тратит деньги дальше.

**Промпт для VS Code:**
> «Зайди в настройки моего аккаунта (usage / billing) и выключи возможность доплаты сверх подписки (usage credits / pay-as-you-go overage). Мне нужно, чтобы потолком был месячный кредит подписки, без автосписаний сверху. Подскажи точный тумблер и подтверди, что он выключен.»

✅ **Получилось, если…** в настройках доплата сверх подписки выключена. С этого момента у мозга есть жёсткий предсказуемый потолок расходов = твой тариф.

> 🧠 **Запомни формулу:** токен подписки стоит + API-ключа нет + usage credits выключены = мозг работает «из подписки, а не с кошелька», с известным месячным потолком. Это три условия вместе, не по отдельности.

## Шаг 4. Переносим навыки и память на сервер. Теперь «источник истины» — сервер

### 4.1. Что значит «источник истины на сервере»

До сих пор главная копия твоего мозга (skills + memory) жила на ноутбуке. После переезда **главная, рабочая копия живёт на сервере** — потому что именно там мозг работает 24/7, туда пишет новые заметки, там принимает решения. Ноутбук становится не «главным», а «зеркалом для подстраховки» (об этом — Модуль 04).

Почему это важно проговорить: если ты продолжишь править файлы и на ноутбуке, и на сервере вразнобой — получишь две расходящиеся версии мозга и не будешь знать, какая правильная. Договорённость простая: **правим на сервере, ноутбук — резервная копия.**

### 4.2. Что переносим, а что — НЕТ

Переносим на сервер:
- **skills** — навыки/скиллы твоего мозга;
- **memory** — рабочая база знаний, проекты, заметки.

**НЕ переносим на сервер (остаётся только на локальной машине):**
- **личный контур** — папка `personal/` (личное, финансы, здоровье, семья, всё чувствительное);
- **`sessions/`** — служебные данные локальных сессий.

Почему личный контур не едет: сервер — это машина в дата-центре, доступная по сети. Всё, что попадает туда, потенциально шире по доступу, чем то, что лежит только на твоём ноутбуке. Личное и чувствительное держим **максимально узко** — только локально. Это не паранойя, это гигиена: мозг-работник на сервере не должен носить с собой твой паспорт.

> 🔴 **Если у тебя уже был мозг на сервере раньше** (ветка B — мозг когда-то уезжал на сервер целиком) — на сервере может лежать **старая полная копия или архив**, где осталось личное. Не забудь сделать **ревизию старой копии** — отдельный шаг в [`05_БЕЗОПАСНИК.md`](05_БЕЗОПАСНИК.md) (раздел «Если мозг уже уезжал на сервер целиком»).

### 4.3. Как переносим — rsync с явным исключением

Переносить будем `rsync` — он копирует только то, что изменилось, и умеет **исключать** папки. Исключения — самая важная часть команды, поэтому мы их проговариваем явно и проверяем.

> ⚠️ Обрати внимание на **завершающий слэш** у путей и на флаг `--dry-run` в первом прогоне. Сначала «репетиция» (ничего не копирует, только показывает, что будет), потом — боевой прогон.

**Промпт для VS Code (репетиция — сначала так):**
> «Сделай ПРОБНЫЙ прогон переноса моих skills и memory на сервер, БЕЗ реального копирования (`--dry-run`), с явным исключением личного контура. Источник — мои локальные папки, приёмник — домашняя папка пользователя `brain`:
> ```bash
> rsync -avz --dry-run \
>   --exclude 'personal/' \
>   --exclude 'sessions/' \
>   <локальный-путь-к-skills>/ <USER-админ>@<IP>:/home/brain/skills/
>
> rsync -avz --dry-run \
>   --exclude 'personal/' \
>   --exclude 'sessions/' \
>   <локальный-путь-к-memory>/ <USER-админ>@<IP>:/home/brain/memory/
> ```
> Покажи мне список файлов, которые собираешься перенести. Я хочу **своими глазами убедиться**, что в списке НЕТ ничего из `personal/` и `sessions/`.»

✅ **Получилось, если…** в списке репетиции нет ни одного файла из `personal/` и `sessions/`. Если что-то из личного всё же мелькнуло — **стоп**, не запускай боевой прогон, разбирайся с путями исключения.

**Промпт для VS Code (боевой прогон — только после успешной репетиции):**
> «Репетицию проверил, личного в списке нет. Запусти те же две команды `rsync` БЕЗ `--dry-run` — перенеси skills и memory на сервер. После переноса выставь владельца файлов на пользователя `brain`:
> ```bash
> sudo chown -R brain:brain /home/brain/skills /home/brain/memory
> ```»

✅ **Получилось, если…** rsync отработал без ошибок, и на сервере появились папки `skills` и `memory`, принадлежащие `brain`.

### 4.4. Контрольная проверка — личного контура на сервере нет

Доверяй, но проверяй. Отдельно убедимся, что чувствительное не уехало.

**Промпт для VS Code:**
> «Проверь на сервере, что личный контур НЕ попал на сервер:
> ```bash
> sudo -u brain -i bash -lc 'ls -la ~/memory/ | grep -i personal || echo "personal/ на сервере НЕТ — правильно"'
> sudo -u brain -i bash -lc 'find ~ -type d -name personal -o -type d -name sessions 2>/dev/null || true'
> ```
> Если найдёшь папку `personal/` или `sessions/` на сервере — немедленно останови всё и сообщи мне: это значит, исключения не сработали, и нужно их удалить с сервера и разобраться в причине.»

✅ **Получилось, если…** первая команда говорит «personal/ на сервере НЕТ», вторая не находит ни `personal`, ни `sessions`. Вот теперь перенос сделан правильно.
