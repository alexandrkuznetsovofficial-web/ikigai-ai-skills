## Привет. Через один урок у тебя будет вот что

Ты пишешь своему боту в Telegram с телефона: «запомни: позвонить поставщику в четверг». Через пять минут эта заметка уже лежит у тебя на компьютере, в папке памяти. Утром бот сам присылает брифинг. Ты в дороге, ноутбук закрыт — бот всё равно отвечает и опирается на твою память. А вечером ты садишься за компьютер, открываешь VS Code, и Claude Code видит всё: твои файлы, «Загрузки», скиллы, свежие заметки из бота.

Так устроено у Александра, и так будет у тебя.

**Что важно знать сразу:**

- 🧑‍🌾 **Программистом быть не нужно.** Всю техническую работу делает Claude Code вместе с готовым скиллом-установщиком `brain-link`. Ты заказываешь, принимаешь и пару раз вводишь пароль в терминал сам.
- 🧭 **Кит подстраивается под тебя.** Первый шаг — аудит: он покажет, что у тебя уже есть, и выберет твою ветку.
- 🛟 **Ничего необратимого без твоего «да».** Опасные шаги `brain-link` делает только после подтверждения, а перед любой правкой сохраняет копию.
- 🔒 **Личное остаётся дома.** Здоровье, семья, деньги на сервер не уезжают никогда (подробно — ниже).

## 🧭 Модель: компьютер — мастерская, сервер — база

```
КОМПЬЮТЕР — мастерская                          СЕРВЕР вне РФ — база
Claude Code видит твои файлы                    бот в Telegram 24/7, утренний брифинг
memory/ и скиллы правишь здесь   ── каждые 5 мин ──►  копия памяти и скиллов
memory/inbox/, memory/dialogues/ ◄── каждые 5 мин ──  бот записал «запомни …» и журнал
```

- **Компьютер (Mac или Windows) — мастерская.** Здесь Claude Code в VS Code видит локальные файлы. Здесь ты правишь память и ставишь скиллы. Главная копия мозга — здесь.
- **Сервер — база.** Бот работает 24/7 «как у Александра», утренний брифинг приходит с сервера, на сервере лежит копия памяти, чтобы бот мог на неё опираться.
- **Синк `brain-sync` — каждые 5 минут.** Твои правки уезжают на сервер. Всё, что записал бот (`memory/inbox/` и `memory/dialogues/`), приезжает к тебе.
- **У каждой папки один хозяин.** Память и скиллы — компьютер. Бот пишет только в `inbox/` и `dialogues/`. Поэтому правки не теряются молча, а удалённое не воскресает (подробно — модуль 04).

Готов? Начинаем со знакомства агента с твоей ситуацией.

## 🌿 Три ветки — одна связка

Все три ведут в одну точку: **компьютер-мастерская + сервер-база + бот 24/7 + синк каждые 5 минут**.

### Ветка A — «Строим с нуля»

Сервера нет или он только что выдан хостером.

```
01 заказ сервера → detect → keys → harden → claude → put-token claude →
init → schedule → bot → verify → lockdown
```

Главные модули: **01** (заказ сервера), дальше шаги `brain-link`; модули 02, 03A, 04, 05 объясняют, что делает каждый шаг.

### Ветка B — «Я уже переехал по старой модели»

Раньше ты переносил мозг на сервер целиком, правил там, а на компьютер каждую ночь приезжало зеркало. Эта модель снята: серверный Claude не видит твои «Загрузки» и локальные скиллы, а ночное зеркало стирает правки, сделанные на компьютере.

```
detect → keys → harden → claude → put-token claude →
adopt → schedule → bot → verify → lockdown
```

Что делает **`brain-link adopt`** вместо `init`:
- выключает старое ночное зеркало и git-снимки на сервере;
- делает на компьютере коммит «до» — точку возврата;
- там, где файлы разошлись, побеждает версия сервера (там ты правил последнее время), а твоя локальная сохраняется рядом как `имя.conflict-local…`;
- находит на сервере личное (`personal/`, `sessions/` и т. п.), забирает его домой, а удаляет на сервере только после твоего «да»;
- старого бота только отключает, не удаляет (это делает шаг `bot`).

Подробно — модуль [04](04_ISTINA_I_BEKAPY.md), раздел «Если ты переехал по старой модели».

### Ветка C — «Связка уже стоит»

`brain-link` уже ставили. Запусти `brain-link verify` и посмотри, что не зелёное. Чинить — по модулю [08](08_ESLI_NE_VZLETELO.md).

> Не гадай, какая у тебя ветка, — это **скажет аудит**.

## 🧭 Принцип «pruf»: как понять, что шаг удался

**После каждого шага** в этом ките есть блок:

> ✅ **Получилось, если видишь X**

Увидел описанное — идёшь дальше. Не увидел — рядом подсказка «что проверить». У `brain-link` каждый шаг сам печатает итог, а `verify` в конце проверяет всё разом.

Правило простое: **не переходи к следующему шагу, пока не увидел зелёный признак текущего.**

## 🔒 Одно важное правило про личное

Во втором мозге бывает очень личное: здоровье, семья, финансы. **На сервер оно не уезжает.** Сервер — рабочий контур: бот, брифинг, рабочая память.

Как это обеспечено:
- синк пропускает в обе стороны папки `personal/`, `private/`, `secret…`, `sessions/`, файлы `.env`, `.session`, `.bak` и любые файлы больше 20 МБ. Этот список не нужно помнить, он зашит в `brain-link`;
- проверка №4 в `brain-link verify` отдельно убеждается, что `personal` на сервере нет;
- если раньше личное уже уезжало на сервер (ветка B), `adopt` заберёт его домой и удалит на сервере после твоего «да».

Сомневаешься, рабочее это или личное? Спроси агента и оставь личное в `personal/`.
