# ❓ FAQ обывателя — память, бэкапы, источник истины, доступ бота

Простыми словами, без технического тумана.

## 1. Где хранится память — на компьютере или на сервере?
**В трёх местах сразу, но главный — сервер.**
- 🖥 **Сервер `/opt/brain` — ИСТОЧНИК ИСТИНЫ.** Здесь живёт бот 24/7 и читает память отсюда. Это «оригинал».
- 💻 **Компьютер — твоя рабочая копия** (git-клон). Удобно править. Это не оригинал, а синхронизируемая копия.
- ☁️ **Приватный GitHub — копия вне сервера** (бэкап). Если сервер сгорит — мозг цел здесь.

Все три синхронизируются через git (`push`/`pull`). Правило простоты: **правь в одном основном месте** (либо с компьютера, либо с планшета через туннель), чтобы копии не разъехались.

## 2. Что является источником истины?
**Сервер (`/opt/brain`).** Потому что именно с него работает бот круглосуточно. Логика: ты правишь → отправляешь на сервер (git) → сервер = то, что реально действует. GitHub — это «сейф с копией», а не рабочий оригинал.

## 3. Как делаются бэкапы, как часто, где лежат?
Правило **3-2-1**: 3 копии, 2 разных места, 1 — вне сервера.
| Что | Как | Частота | Где лежит |
|---|---|---|---|
| Память (MD) | авто `git commit + push` | каждые 30 мин | приватный GitHub (вне сервера) |
| База/состояние бота (`.db`, `.session`) | дамп → облако (restic/rclone) | раз в сутки | облако (Я.Диск/GDrive/бакет) |
| Перед любой опасной правкой | ручной бэкап-копия | по событию | папка `/opt/backups` на сервере |

**Важно:** бэкап, который ни разу не разворачивали, — не бэкап. Раз в месяц скачай последнюю копию и проверь, что она открывается.

## 4. К чему имеет доступ бот, а к чему — нет?
**Бот видит ровно то, что ты ему дал, и ничего сверх.**

✅ **Имеет доступ:**
- Файлы памяти в `/opt/brain` — это его «знания» (отвечает на их основе).
- Свои собственные секреты из `.env` (его токен Telegram, ключ модели) — чтобы работать.
- То, что ты явно закодил ему уметь (написать тебе, искать по памяти и т.п.).

❌ **НЕ имеет доступа (и не должен):**
- Твои другие аккаунты, твой компьютер, секреты вне его `.env`.
- Он отвечает **только тебе** (авторизованному), а не случайным людям — если ты не открыл публичный эндпоинт (тогда обязателен «турникет», см. файл 04).

🔴 **Тонкость безопасности (почему секреты НЕ кладём в память):** бот читает память `/opt/brain`. Если положить туда пароль/токен в текст MD-файла — бот сможет его «вспомнить» и выдать, плюс он утечёт в git и бэкап. Поэтому **секреты живут только в `.env`/`~/.config` (права 600), которых нет в памяти и нет в git.** Память — для знаний, не для ключей.

## 5. Если что-то сломалось — что делать?
1. Не паникуй: бот настроен на авто-перезапуск (`systemd Restart=always`) — после сбоя/перезагрузки поднимается сам.
2. Зайди на сервер (с компьютера), посмотри `journalctl -u brain-bot -n 50`.
3. Память цела в GitHub — в худшем случае разворачиваешь сервер заново и `git clone` мозг обратно.
4. Потерял доступ к серверу — заходи через **VNC-люк хостера** (см. файл 03, часть C).

## 6. Коротко: что у меня в итоге?
- Мозг (MD) на сервере = источник истины, бот читает его 24/7.
- Копии: на компьютере (правка) + в GitHub (бэкап каждые 30 мин).
- Секреты — отдельно, в `.env` 600, не в памяти и не в git.
- Доступ: с компьютера (база) + опционально с планшета (надстройка-туннель).
- Сломалось — само поднимается; не поднялось — есть бэкап и аварийный люк.
