# 🆘 Если не взлетело — симптом → причина → что сделать

> Открой, если на переезде что-то застряло. Большинство затыков — из этого списка. Дай агенту (Claude/Codex) симптом + соответствующую строку — он починит.

## Подключение к серверу
**Симптом: `sshpass: command not found` / агент не может зайти на сервер.**
→ Причина: `sshpass` не стоит (на Mac/Windows его нет по умолчанию).
→ Фикс: заходи обычным `ssh root@<IP>` (введёшь пароль). Лучше сразу настрой вход по ключу: `ssh-keygen` → скопируй ключ на сервер → больше пароль не нужен. (Windows: встроенный `ssh` в PowerShell.)

**Симптом: соединение висит/отказ, хотя IP и пароль верные.**
→ Причина: не тот порт, файрвол, сервер ещё не поднят.
→ Фикс: проверь порт (обычно 22 у нового VPS), что сервер запущен в панели хостера. Если включал ufw/Tailscale — см. блок «Потерял доступ».

## Бот 24/7
**Симптом: бот на сервере запустился, но не отвечает / падает.**
→ Причина №1 (частая): локальный бот ещё работает — Telegram пускает только ОДИН экземпляр (`Conflict: terminated by other getUpdates`).
→ Фикс: **останови локального бота** перед запуском на сервере.
→ Причина №2: нет токена/ключа в окружении. → Проверь `EnvironmentFile`/`.env`, права 600.
→ Диагностика: `journalctl -u <твой-сервис> -n 50` — покажет реальную ошибку. `systemctl is-active <сервис>` должно быть `active`.

**Симптом: бот падает на импорте (ModuleNotFound / ошибка пакета).**
→ Причина: зависимости не поставлены / другая версия Python.
→ Фикс: активируй venv, `pip install` нужные пакеты; проверь `python3 -c "import telethon"` (и др.) ДО запуска сервиса.

## Перенос памяти / GitHub
**Симптом: `git push` падает (auth/permission denied).**
→ Причина: GitHub не настроен (нет аккаунта / токена / `gh auth login`).
→ Фикс: `gh auth login` или Personal Access Token. **Не блокируйся:** можно сначала просто скопировать память на сервер (`scp`/`rsync`), а offsite-бэкап в GitHub настроить позже.

**Симптом: имена файлов с кириллицей ломаются (Windows / git / агент).**
→ Фикс: продублируй проблемные имена латиницей или попроси агента переименовать на латиницу перед коммитом.

**Симптом: после переноса в репо случайно попал секрет.**
→ Фикс: ПЕРЕД первым `git add` прогони поиск секретов; найден ключ в коде/MD → вынеси в `.env` (600), а если уже закоммитил — **смени (ротируй) этот ключ**.

## Доступ / VPN / самоблокировка
**Симптом: страница логина GitHub/Microsoft/Google не открывается (из РФ).**
→ Причина: нужен VPN на шагах Tailscale / code tunnel / git push.
→ Фикс: включи VPN именно на момент авторизации, повтори шаг.

**Симптом: потерял доступ к серверу после настройки безопасности.**
→ Причина: включил ufw/хардненинг ДО проверенного входа.
→ Фикс: зайди через **VNC / Recovery-консоль хостера** (работает, даже когда SSH мёртв) → откати правило. На будущее: Tailscale + проверенный VNC-люк ПЕРЕД любыми замками.

## Планшет (надстройка)
**Симптом: vscode.dev не пускает / туннель отвалился.**
→ Фикс: тот же GitHub-аккаунт на сервере и на планшете; VPN на логине; в Safari включи «Request Desktop Website».

## Агент «сказал готово», а ничего нет
→ Причина: агент не проверил результат (или упёрся в лимит контекста).
→ Фикс: требуй чек-точку — пусть ВСТАВИТ реальный вывод команды (`systemctl is-active…`, `journalctl…`), а не «по памяти». Если контекст кончился — начни новый чат и дай ему этот файл + что уже сделано.
