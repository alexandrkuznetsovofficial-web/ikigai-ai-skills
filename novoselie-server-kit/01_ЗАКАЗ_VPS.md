# 🖥 Пре-ворк — Заказать VPS (до урока!)

> Делай **за 2–4 дня до урока** — поддержке хостера нужен запас. К субботнему уроку сервер должен быть уже на руках.

## Самый простой путь (для нетехнического) — тикет в FoxCloud
Не регистрируйся сам через формы (в Потоке 1 на этом застревали). Напиши в поддержку **FoxCloud** — тебе подберут и поднимут сервер живые люди.

> 🌐 **Правильный сайт для оплаты из РФ (рубли/СБП): [ru.foxcloud.net](https://ru.foxcloud.net).** Есть и международный foxcloud.net — там цены в долларах. Признак «ты не там»: видишь цены в $ — переходи на `ru.foxcloud.net`.

**В заявке укажи:**
- Кодовое слово: **Икигай** (по нему помогут как участнику нашего потока)
- Страна: **Нидерланды**
- ОС: **Ubuntu 24.04 LTS**
- Конфигурация: **2 vCPU / 4 GB RAM / 50 GB SSD**

> ⚠️ Кодовое слово **«Икигай»** — это для FoxCloud. Не путать с кодовым словом урока **«НОВОСЕЛЬЕ»** (его пишешь Claude, чтобы поднять этот план).

## Что получить
На выходе хостер пришлёт тебе (обычно письмом или в личном кабинете):
- **IP-адрес сервера**
- **root-пароль**

## 🔑 Куда их положить — «Файл доступа» (не в чат, не в заметки!)

Как только IP и пароль у тебя на руках — **не отправляй их никуда** (ни в чат Claude, ни в Telegram «самому себе», ни в открытую заметку). Вместо этого открой свой Claude Code и вставь этот промпт целиком — агент создаст защищённый файл, откроет его тебе, и ты впишешь данные туда:

```text
Хостер прислал мне данные доступа к серверу (IP, логин, пароль). Мне нужно передать их
тебе БЕЗ чата — через «Файл доступа». Сделай строго так:

1. Создай «Файл доступа» в защищённой папке по стандарту моей ОС (определи ОС сам):
   - macOS / Linux: ~/.config/brain/server_access (папке права 700, файлу 600);
   - Windows: %USERPROFILE%\.secrets\brain\server_access.txt (доступ только владельцу).
   Если файл уже существует — НЕ перезаписывай его: пропусти шаг 2 и переходи
   сразу к проверке значений (шаг 4).
2. Запиши в файл ровно такой шаблон. Поля после «=» оставь ПУСТЫМИ — никаких
   примеров-значений в них не вписывай:
   # Данные доступа к твоему серверу.
   # Заполни три строки внизу: вставь свои значения СРАЗУ ПОСЛЕ знака «=».
   # Где взять: письмо или личный кабинет хостера (после заказа VPS).
   # IP — четыре числа через точку. LOGIN — обычно root.
   # PASSWORD — пароль из письма, вставляй ЦЕЛИКОМ и как есть (любые символы — нормально).
   # Если вход уже настроен только по SSH-ключу — впиши PASSWORD=KEY-ONLY.
   # Если у сервера нестандартный SSH-порт — добавь отдельную строку PORT= с номером.
   # Заполнил? Сохрани файл (Cmd+S / Ctrl+S) и напиши мне в чат: «готово».
   IP=
   LOGIN=root
   PASSWORD=
3. Открой этот файл мне на экран (в VS Code — командой `code <путь-к-файлу>`; если не
   выходит — напиши путь и попроси меня открыть его самому) и одной фразой скажи, что
   куда вписать. Дальше ЖДИ моего «готово» — сам не продолжай.
4. Когда я напишу «готово» — прочитай файл и ПРОВЕРЬ каждое значение.
   Как читать: значения бери только из строк вида КЛЮЧ=значение; строки на «#» —
   комментарии, не значения; в PASSWORD бери ВСЁ после ПЕРВОГО знака «=» (пароль может
   содержать «=»); пробелы и переводы строки по краям значений отбрасывай.
   - IP: четыре числа 0–255 через точку (или доменное имя сервера от хостера);
     НЕ 127.0.0.1, НЕ 0.0.0.0, НЕ 1.2.3.4; не обёрнуто в угловые скобки.
   - LOGIN: не пустой, одно слово без пробелов, не обёрнут в угловые скобки.
   - PASSWORD: не пустой. Отвергай ТОЛЬКО если значение целиком обёрнуто в угловые
     скобки (вида <...>) или равно слову «пароль»/«password»/«пример». Настоящий пароль
     может содержать ЛЮБЫЕ символы (включая < > " = и пробел) — за это НЕ отвергай.
     Особое значение KEY-ONLY валидно: вход только по SSH-ключу, пароль не нужен.
   Если что-то не так — снова открой мне файл, скажи КОНКРЕТНО какую строку поправить,
   и жди нового «готово». Сомневаешься в пароле — спроси одной фразой «это настоящий
   пароль из письма хостера?» и, если да, принимай: окончательный судья настоящести —
   успешное подключение (шаг 6).
5. Пароль НИКОГДА не выводи в чат — ни целиком, ни частично. И не подставляй его
   литералом в команды: текст команд тоже виден в чате. IP и логин показывать можно.
6. Когда значения прошли проверку — проверь их делом: подключись к серверу.
   Порт: если в файле есть строка PORT= — используй её, иначе 22.
   Пароль передавай безопасно: читай из файла внутри команды (например, `sshpass -f`
   или переменная окружения); если неинтерактивно не получается — запусти ssh в
   терминале и попроси МЕНЯ ввести пароль в окно терминала (терминал — не чат).
   Выполни `whoami` и `uname -a` и покажи мне вывод.
   Если сервер отвечает «Permission denied» — не зацикливайся: частая причина — лишний
   пробел или неполностью скопированный пароль. Снова открой мне файл, попроси вставить
   пароль из письма заново целиком и жди нового «готово».
   Затем сразу создай SSH-ключ (если у меня его нет) и установи его на сервер, чтобы
   дальше пароль был не нужен. Финальная проверка:
   `ssh -o BatchMode=yes <логин>@<IP-из-файла> 'echo OK'` печатает OK.
   С этого момента данные доступа у меня больше НЕ спрашивай — при любой следующей
   задаче бери их сам из Файла доступа.
```

✅ **Получилось, если:** агент показал `whoami` / `uname -a` с сервера, сказал «вход по ключу работает (OK)», а пароль ни разу не появился в чате.

## Definition of done (Стадия 1)
IP + root-пароль вписаны в **Файл доступа**, агент проверил вход на сервер и настроил SSH-ключ (`echo OK` прошёл).
