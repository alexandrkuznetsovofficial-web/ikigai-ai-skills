# Стартовая команда агентов

Три агента, с которых начинается ваша команда. Каждый — один файл `.md`.

| Агент | Кто это | Когда звать | Что умеет |
|---|---|---|---|
| [`checker`](checker.md) | проверяющий, который не участвовал в работе | после каждой готовой работы, до того как показать её людям | только читает: сверяет факты с памятью, правила из `CLAUDE.md` и `memory/feedback_*.md`, голос с образцами. Возвращает вердикт и список замечаний, сам ничего не правит |
| [`secops`](secops.md) | офицер безопасности | перед всем, что связано с паролями, сервером, публикацией, удалением | только читает: ищет пароли и ключи в памяти, объясняет риск действия и говорит «можно» или «стоп» |
| [`researcher`](researcher.md) | исследователь | «изучи», «найди», «сравни», «как это делают другие», «разбери эти файлы» | ищет в интернете и в ваших файлах, приносит выжимку до 400 слов с источниками |

## Скилл и агент — в чём разница

**Скилл** — должностная инструкция. Папка с файлом `SKILL.md` в `~/.claude/skills/`.
Claude «надевает» её прямо в вашем разговоре: попросили пост — надел копирайтера.

**Агент** — отдельный сотрудник со своей головой. Один файл в `~/.claude/agents/`.
Работает в своём окне: не видит ваш разговор, получает задачу и приносит результат.

Агент нужен, когда:
- нужна **независимая проверка**: один написал, другой проверил. Автор, который проверяет сам себя, видит то, что хотел сделать, а не то, что сделал;
- задача **длинная** и забьёт основной разговор (поиск, разбор больших файлов);
- нужно **ограничить права**: проверяющий и офицер безопасности могут только читать.

Подробнее — в официальной документации Anthropic: https://code.claude.com/docs/en/sub-agents

**Агент secops и скилл secops — не одно и то же.** В наборе есть оба: агент `agents/secops.md`
(отдельное окно, только читает, говорит «можно» / «стоп») и скилл `secops` из `team-kit/skills/secops/`
(инструкция для серверной команды, работает внутри разговора). Чтобы Claude не путал, говорите явно:
«позови **агента** secops» — для проверки перед рискованным шагом; «**скилл** secops» — когда работаете
с сервером по киту «Новоселье». В `TEAM.md` агент записывается как `@secops`, скилл — как `/secops`.

## Как установить

Агенты ставятся в папку `agents` внутри папки `.claude` в вашей домашней папке:

| | Mac | Windows |
|---|---|---|
| Куда кладём | `~/.claude/agents/` | `%USERPROFILE%\.claude\agents\` (например `C:\Users\Имя\.claude\agents\`) |
| Как открыть эту папку | Finder → Cmd+Shift+G → вставить `~/.claude` | Проводник → в адресную строку вставить `%USERPROFILE%\.claude` |

Проще всего поручить установку Claude Code. Откройте его в папке второго мозга и вставьте:

```
В папке агентов из набора Академии (agents/) лежат три файла: checker.md, secops.md, researcher.md.
1. Создай папку агентов ~/.claude/agents/, если её нет (на Windows это %USERPROFILE%\.claude\agents\).
2. Скопируй туда эти три файла без изменений. Если файл с таким именем уже есть —
   покажи мне разницу и спроси, заменять ли.
3. Найди мой TEAM.md — он лежит только в папке моего оркестратора: ~/.claude/skills/<оркестратор>/TEAM.md.
   Есть — добавь агентов в раздел «Агенты» (создай раздел, если его нет): имя с @ (@checker),
   кто это, когда звать — живыми русскими фразами в «ёлочках».
   Оркестратора нет — TEAM.md НЕ создавай, просто поставь агентов: они работают и без карты команды.
4. Допиши в CLAUDE.md правило: «Готовую работу перед показом мне — через агента checker.
   Всё, что связано с доступами, сервером, публикацией и удалением, — сначала через агента secops
   (агента, не скилл secops)».
5. Покажи, что получилось. Затем скажи мне закрыть и заново открыть VS Code, чтобы агенты подхватились.
```

**Признак, что всё получилось:** после перезапуска спросите «Какие у меня есть агенты?» — Claude
называет все три. Если не называет — проверьте, что файлы лежат прямо в папке `agents`, а не во
вложенной папке, и что VS Code вы закрыли целиком, а не только вкладку.

## Первый запуск

- «Позови агента secops, пусть проверит мою папку второго мозга на пароли и ключи».
- «Напиши пост про [тема], потом отдай агенту checker на проверку и покажи мне только после его вердикта».
- «Попроси агента researcher изучить трёх моих конкурентов: [ссылки]».

## Как агенты связаны с остальным набором

- **Правило двойной ошибки.** Вы поправили помощника второй раз в одном и том же — правило
  записывается в `memory/feedback_<тема>.md`. `checker` читает эти файлы и ловит нарушение до того,
  как работу увидите вы.
- **[craft-to-skill](../craft-to-skill/SKILL.md).** Когда одну и ту же работу (досье, КП, отчёт)
  приходится поправлять снова и снова, этот скилл собирает под неё отдельную инструкцию и своего
  проверяющего `<работа>-checker`. Общий `checker` остаётся для всего остального.

## Своего агента под свою задачу

```
Ты знаешь мой бизнес и мою задачу: [одна строка — что хочу сделать].
Предложи 3–5 агентов, которые нужны, чтобы её сделать. Для каждого: имя латиницей,
зачем он, что умеет, какие ему нужны права (только читать или ещё и менять файлы).
Обязательно один из них — проверяющий, который не делает работу, а только проверяет.
После моего «ок» создай их в ~/.claude/agents/ по формату официальной документации
Claude Code (name, description, tools). Если у меня есть оркестратор — добавь их в
~/.claude/skills/<оркестратор>/TEAM.md, раздел «Агенты» (имя с @). Оркестратора нет — TEAM.md не создавай.
```

Главное в агенте — поле `description`: по нему Claude решает, когда его звать.
Пишите в нём, **когда** звать и **когда не звать**.
