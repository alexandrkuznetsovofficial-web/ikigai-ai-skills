# Апгрейд второго мозга до kit 2.0

Ты обновляешь **живую** систему человека, которой он пользуется каждый день. Главное правило:
**только добавлять.** Файлы памяти не переносятся и не удаляются, ссылки не переписываются,
чужие правки не перезаписываются, история git не трогается.

Порядок жёсткий: **распознать → снимок → план → 🛑 стоп «делаем?» → применить → проверить
поведением → повторный прогон = 0 изменений.** Между планом и применением ты ничего не меняешь.

Эталонная раскладка и поля — контракт памяти kit 2.0 (`KIT_CONVENTIONS.md`, раздел 7, в репозитории
`ikigai-ai-skills`). Ниже `WS` — рабочая папка (где `CLAUDE.md`), `MEM` = `WS/memory`.

## Шаг 0. Профиль компьютера и рабочая папка

Прочитай `~/.claude/ikigai_env.json`; нет или старше 30 дней — `bash ~/.claude/skills/ikigai-preflight/scripts/probe.sh`.
Нужны `os_branch`, `python_cmd`, `workspace`. Пробника нет — определи систему сам и спроси, где рабочая папка.

| Что | Mac | Windows (Claude выполняет через Git Bash) |
|---|---|---|
| Python | `python3` | `py -3`, иначе `python` |
| Скрипты этого скилла | `~/.claude/skills/memory-upgrade/scripts/` | то же в Git Bash |
| Скрипты сада | `~/.claude/skills/memory-garden/scripts/` | то же |
| Снимок без git | `~/.claude/backups/memory-upgrade_ДАТА/` | `%USERPROFILE%\.claude\backups\memory-upgrade_ДАТА\` |
| Расписание брифинга | launchd `com.ikigai.morning-brief` | Планировщик заданий `Ikigai morning-brief` |
| Синк связки (если стоит `brain-link`) | launchd `com.ikigai.brain-sync`; пауза `brain-sync pause` | Планировщик задач `Ikigai brain-sync`; пауза `brain-sync pause` |

Нужны установленные `memory-garden` и `weekly-distill` (папками целиком, со `scripts/`). Нет — сначала
поставь их из репозитория и скажи человеку, что поставил.

**Запуск — всегда на компьютере** (kit 2.1: компьютер — мастерская, сервер — база). Есть связка `brain-link`
(файл `~/.config/brain/server_access`; Windows — `%USERPROFILE%\.config\brain\server_access`) — перед
изменениями синк ставится на паузу (Шаг 2, пункт 0), после — включается и прогоняется (конец Шага 4).
Иначе промежуточное состояние уедет на сервер, а массовые правки упрутся в защиту синка от массового удаления.

**Мозг ещё по старой модели «главная копия на сервере + ночное зеркало „сервер → компьютер“»** (кит «Новоселье» до 2.1) —
стоп: ночное зеркало к утру сотрёт правки на компьютере. Скажи это и предложи сначала перейти на связку:
`brain-link adopt` (модуль 04 «Новоселья», Часть 6). Человек всё равно хочет сейчас — спроси, как продолжить.

## Шаг 2. Снимок до изменений

0. **Стоит связка `brain-link` — `brain-sync pause`** (скажи человеку одной строкой: «ставлю синк с сервером
   на паузу, включу в конце»). Признак: `brain-link status` показывает паузу.
1. **Автобэкап с отправкой в облако стоит по расписанию — поставь его на паузу** (команды — в скилле
   `auto-commit-backup`, шаг 1.1), иначе фоновая отправка унесёт промежуточное состояние. В конце включишь.
2. Снимок:
   - есть git → `git -C WS add -A && git -C WS commit -m "memory-upgrade: снимок до kit 2.0"` (локально,
     без отправки). `add -A` забирает всё, включая `memory/personal/` и `sessions/`, — так и задумано:
     локальная история хранит всё, иначе нечем откатиться (формула бэкапа — `KIT_CONVENTIONS.md`, §7).
     До коммита проверь две вещи: в `.gitignore` есть секреты (`.secrets/`, `.env`, `*.session`) — нет, допиши
     только эти строки; у папки нет облачного адреса (`git -C WS remote -v` пусто) или стоит замок `pre-push`.
     Адрес есть, а замка нет — 🛑 стоп: снимок не делай, сначала пункт 9;
   - git нет → копия рабочей папки **вне неё**: `~/.claude/backups/memory-upgrade_ГГГГ-ММ-ДД_ЧЧММ/`,
     без тяжёлых `brain-rag/`, `rag_db/`, `node_modules/`, `.venv/`:
     ```bash
     PY -c "import shutil,sys,datetime,os;d=os.path.expanduser('~/.claude/backups/memory-upgrade_'+datetime.datetime.now().strftime('%Y-%m-%d_%H%M'));shutil.copytree(sys.argv[1],d,ignore=shutil.ignore_patterns('brain-rag','rag_db','node_modules','.venv','.git'));print(d)" "WS"
     ```
3. Скажи человеку одной строкой, где снимок и как откатиться.

**10. Брифинг: расписание, которое переживает сон.** Cron и задача Windows без «запуска при первой

Поставь новое расписание и проверь пробным запуском, что сообщение **пришло**. Только после этого убери
старое: Mac — строку брифинга из cron через файл и со сверкой числа строк (стало ровно на одну меньше);

**11. Скиллы набора.** Найди установленные скиллы kit 1.x — у них в шапке нет `kit_version:`:

## Правила

- Ничего не удалять, не переносить, не переписывать ссылки и историю git.
- Существующий файл не перезаписывать: только дописать недостающее.
- Каждый пункт — после «да»; два живых `ACTIVE.md` — отдельный стоп.
- Пароли, коды подтверждения, токены у человека не спрашивать.
- Память и личное — никогда в GitHub; в локальном git — всё (формула бэкапа, `KIT_CONVENTIONS.md` §7).
- Запуск — на компьютере, не на сервере. Связка `brain-link` стоит — между `brain-sync pause` и `resume` + `run` (§8).
- Раскладку «корень без memory/» доводишь здесь сам; к `second-brain-architect` отправляешь только пустую папку.
