# 03 · Прототип за вечер: кликабельная LMS без единой строки бэкенда

> **Для кого этот модуль.** У вас есть `LMS_TZ_APPROVED.md` и `LMS_PROTOTYPE_BRIEF.md` из модуля [02](02_LMS_SPEC_APPROVAL.md). Теперь — увидеть платформу глазами до того, как потрачены деньги и недели. Прототип — это один HTML-файл, который открывается в браузере и по которому можно кликать: вход, каталог, урок с видео, домашка, кабинет с прогрессом.

**Главная идея.** Люди не умеют согласовывать документы — люди умеют согласовывать картинки. ТЗ на 3 страницы вызывает «ну вроде норм», а кликабельный экран урока вызывает «а почему кнопка тут, у нас же сотрудники с телефона» — и это самая дешёвая правка в жизни проекта. Прототип за вечер экономит месяц переделок.

**Что прототип НЕ делает:** не хранит данные, не проверяет пароли, не проигрывает настоящие видео. Всё понарошку — и в этом его сила: менять «понарошку» можно за минуты.

**Как работает модуль:** новый чат → промпт + два файла из модуля 02 → агент собирает `lms_prototype.html` → вы кликаете, правите словами («сделай темнее», «урок слишком пустой») → показываете 2–3 будущим ученикам → фиксируете правки → в модуль [04 — MVP](04_LMS_MVP.md).

---

## Запуск прототипа

Откройте новый чат, вставьте промпт, приложите `LMS_TZ_APPROVED.md` и `LMS_PROTOTYPE_BRIEF.md`.

### 📋 Текст-промпт для VS Code (скопируйте целиком)

```
Ты — продуктовый дизайнер и frontend-инженер обучающих платформ. Я прилагаю
согласованное ТЗ (LMS_TZ_APPROVED.md) и бриф прототипа (LMS_PROTOTYPE_BRIEF.md).
Собери кликабельный прототип моей LMS — ОДИН файл lms_prototype.html, который
я открою двойным кликом в браузере, без сервера и установки чего-либо.

ЖЁСТКИЕ РАМКИ:
- Один самодостаточный HTML-файл: стили и скрипты внутри, никаких внешних
  библиотек и загрузок из интернета (файл будут открывать без сети).
- Только экраны MVP-ЯДРА из ТЗ. Функции из «второй очереди» и бэклога —
  НЕ рисовать (максимум: серый пункт меню с пометкой «после MVP»).
- Все данные — вымышленные, но правдоподобные ИМЕННО для моей компании:
  названия курсов и уроков возьми из ТЗ (первый курс MVP!), имена учеников
  выдумай нейтральные. Видео — плейсхолдер с кнопкой play и таймлайном.
- Никаких настоящих логинов: экран входа ведёт внутрь по любой кнопке.

ЭКРАНЫ (сверь список с путём ученика из ТЗ, это база — адаптируй):
1. Вход — как в ТЗ (ссылка-приглашение / код на почту / логин), с брендингом.
2. Мой кабинет — прогресс по курсам, «продолжить с места остановки»,
   ближайший дедлайн, что дальше.
3. Курс — список модулей и уроков со статусами (пройден / доступен / закрыт),
   видна логика дозирования из ТЗ.
4. Урок — видео-плейсхолдер, текст, материалы, кнопка «урок пройден» по правилу
   из ТЗ (досмотрел / сдал ДЗ).
5. Домашнее задание — форма в формате из ТЗ (тест / текст / загрузка файла),
   состояния: не сдано → на проверке → принято/вернулось с комментарием.
6. Экран проверяющего — очередь работ, одна открытая работа, кнопки
   «зачесть / вернуть с комментарием» (если по ТЗ проверяет человек).
7. Экран руководителя — прогресс команды, отстающие (если в ядре по ТЗ).

ДИЗАЙН:
- Мобильный и десктоп: сначала сверстай под телефон (ученики по ТЗ — смотри
  устройства), на широком экране — расширяй.
- Стиль из брифа прототипа (цвета, настроение). Если не задан — спокойный
  рабочий: много воздуха, один акцентный цвет, без стоковых улыбающихся людей.
- Тёмная и светлая тема по системной настройке.
- Переходы между экранами — простые клики, «как будто всё работает»:
  сдал ДЗ → статус сменился, прошёл урок → прогресс вырос (в пределах страницы,
  без хранения).

ПОСЛЕ СБОРКИ:
1. Скажи, как открыть файл, и дай маршрут демо-клика на 2 минуты:
   «вход → кабинет → урок 1 → сдать ДЗ → посмотреть глазами проверяющего».
2. Предложи 5 вопросов, которые мне стоит задать будущим ученикам, показывая
   прототип (не «нравится?», а «покажи пальцем, куда нажмёшь, чтобы…»).
3. Жди правок. Я говорю словами («темнее», «крупнее кнопку сдачи», «поменяй
   порядок экранов») — ты правишь файл. Итерируем, пока я не скажу
   «прототип согласован».

КОГДА Я СКАЖУ «ПРОТОТИП СОГЛАСОВАН»:
Создай файл PROTOTYPE_NOTES.md: что изменилось относительно ТЗ по итогам
прототипа и показов (эти находки поедут в модуль 04 вместе с ТЗ),
плюс список замечаний учеников и что с каждым решили.
```

### ✅ Pruf — получилось, если…

- файл `lms_prototype.html` открывается двойным кликом **без интернета** и красиво выглядит на телефоне;
- на прототипе — названия ВАШИХ курсов из ТЗ, а не «Курс 1»;
- демо-маршрут за 2 минуты проходится без объяснений: вход → урок → ДЗ → прогресс вырос;
- нарисовано только MVP-ядро — вы не поддались соблазну «дорисуй ещё вот это»;
- прототип показан **минимум двум будущим ученикам**, их замечания записаны в `PROTOTYPE_NOTES.md`;
- фраза «прототип согласован» сказана вами после показов, а не до.

## Как показывать прототип ученикам (5 минут теории)

1. **Не рассказывайте — дайте в руки.** Молчите первые 2 минуты, смотрите куда тыкают.
2. **Задания, не вопросы.** «Найди, где сдать домашку» лучше, чем «понятно ли, где домашка?».
3. **Записывайте дословно.** «А чё, видео нельзя ускорить?» — это готовая строка ТЗ.
4. **Два человека достаточно.** Первые два находят 80% проблем; десять — те же проблемы восемь лишних раз.
5. **Правки — сразу.** Прототип правится за минуты, покажите исправленное тем же людям.

## Если что-то пошло не так

| Симптом | Что сказать агенту |
|---|---|
| Файл огромный и тормозит | «Упрости: убери анимации и декоративные эффекты, оставь структуру и переходы» |
| Дизайн «как у всех нейросетей» — фиолетовые градиенты | «Убери градиенты и глянец. Возьми стиль: <два прилагательных, например „спокойный, инженерный“> + один акцентный цвет <какой>» |
| Агент дорисовал функции из бэклога | «Стоп, сверься с MVP-ядром ТЗ. Убери всё, чего нет в ядре» |
| На телефоне всё съехало | «Открой прототип как ученик с телефона шириной 390px и почини каждый экран» |
| Ученикам непонятно, куда нажимать | Это не сбой — это находка! Запишите дословно и попросите агента перестроить экран |

## Итог модуля

У вас есть кликабельный прототип, согласованный с живыми учениками, и `PROTOTYPE_NOTES.md` с находками. Заказчик внутри компании (директор, HR) теперь может «пощупать» платформу — это лучший аргумент за бюджет. Дальше → [04_LMS_MVP.md](04_LMS_MVP.md): превращаем прототип в работающую систему.

```
#домашнее_задание Прототип LMS: собран lms_prototype.html (вход, кабинет, курс, урок,
ДЗ, проверка), показан 2+ будущим ученикам, правки зафиксированы в PROTOTYPE_NOTES.md.
Прикладываю скрин экрана урока.
```
