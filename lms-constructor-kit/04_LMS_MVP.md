# 04 · MVP: от прототипа к работающей платформе

> **Для кого этот модуль.** У вас есть согласованное ТЗ (`LMS_TZ_APPROVED.md`), прототип и находки показов (`PROTOTYPE_NOTES.md`). Пора строить настоящее: с реальным входом, реальным видео и реальным прогрессом. Этот модуль ведёт по одному из двух маршрутов — и заканчивается пилотом на живых учениках.

**Главная идея.** MVP — это не «маленькая версия всего», а **полный путь одного ученика через один курс**: пригласили → вошёл → посмотрел уроки → сдал ДЗ → получил проверку → дошёл до конца. Всё, что не лежит на этом пути, в MVP не строится. Зато сам путь должен работать безупречно — включая скучное: отзыв доступа, бэкап, «забыл как войти».

## Развилка: маршрут А или Б

Решение уже принято в ТЗ (проверка 5 модуля 02 считала деньги). Здесь — сверка перед стартом:

| | 🅰 Готовая платформа | 🅱 Своя на сервере |
|---|---|---|
| **Быстро** | дни | 1–2 недели с AI-командой |
| **Деньги** | $30–300/мес, растёт с учениками | ~$10–40/мес сервер, растёт медленно |
| **Свобода** | их правила, их дизайн-рамки | любая логика из вашего ТЗ |
| **Данные** | у них (проверьте экспорт!) | у вас |
| **Поддержка** | их саппорт | вы + AI-команда |
| **Кому** | нужен запуск за неделю; никто не будет поддерживать своё | уже есть сервер/навык работы с AI-агентами; специфичное ТЗ; 100+ учеников на горизонте |

> 💡 Если у вас уже есть свой сервер (например, по киту [«Новоселье»](../novoselie-server-kit/README.md)) — маршрут Б у вас наполовину пройден: дом стоит, осталось построить в нём учебный класс.

## Маршрут А · Готовая платформа

Ваше ТЗ — это фильтр для выбора и план настройки. Вставьте промпт:

### 📋 Промпт А (скопируйте целиком)

```
Ты — интегратор обучающих платформ. Прилагаю согласованное ТЗ (LMS_TZ_APPROVED.md)
и находки прототипа (PROTOTYPE_NOTES.md). Мы выбрали маршрут: ГОТОВАЯ платформа.
Помоги выбрать её и довести до пилота. Код не пишем.

ШАГ 1 · ВЫБОР. Возьми 3–4 платформы-кандидата, доступные в моей стране
(спроси, из какой я страны и как смогу платить). Сравни таблицей СТРОГО по моему
ТЗ: вход учеников как в ТЗ? отзыв доступа? форматы ДЗ? отчёты? цена на моём
количестве учеников сейчас и при 3×? экспорт контента и данных при переезде?
Отметь, какие пункты ТЗ платформа НЕ умеет — и что делаем (меняем процесс /
терпим / это причина выбрать другую).

ШАГ 2 · ПЛАН НАСТРОЙКИ. Для выбранной платформы — пошаговый чек-лист настройки
под моё ТЗ: структура курса, правила доступа, дозирование, ДЗ и проверка,
уведомления, брендинг, домен. Каждый шаг: где в интерфейсе это ищется
(по логике платформы), что вставить, как проверить, что сработало.
Я иду по шагам и возвращаюсь с вопросами и скриншотами — веди меня.

ШАГ 3 · ПЕРЕНОС КОНТЕНТА. По разделу 4 ТЗ составь план загрузки первого курса:
что, в каком порядке, сколько часов займёт. Тексты уроков помогай доводить:
я даю черновик/транскрипт — ты структурируешь в урок.

ШАГ 4 · ПЕРЕД ПИЛОТОМ. Прогони со мной чек-лист приёмки из раздела 11 ТЗ —
пункт за пунктом, я делаю руками и говорю результат. Не пройден пункт —
чиним до перехода дальше. Отдельно проверь: тестовый ученик с чужого
устройства, отзыв его доступа, экспорт данных (скачали — открылось).
```

## Маршрут Б · Своя платформа на сервере

Здесь ваш прототип из модуля 03 — не выбрасывается, а **становится настоящим**: агент надстраивает под ним вход, базу и прогресс.

### 📋 Промпт Б (скопируйте целиком)

```
Ты — техлид маленькой команды, строящей LMS по согласованному ТЗ. Прилагаю:
LMS_TZ_APPROVED.md, PROTOTYPE_NOTES.md и прототип lms_prototype.html.
Мы выбрали маршрут: СВОЯ платформа. Веди меня фазами, после каждой — работающий
результат, который я проверяю руками. Я не программист: объясняй решения
по-простому, а команды давай готовыми к вставке.

ПРИНЦИПЫ (не обсуждаются):
- Скучная техника: минимальный веб-сервер + база SQLite + статические страницы.
  Никаких модных фреймворков — ничто не должно требовать «специалиста по X».
- Секреты (пароли, токены, ключи видеохостинга) — только в защищённом файле
  на сервере с правами 600. Не в коде, не в git, не в чатах.
- Каждая правка на работающем сервере — через бэкап до неё и проверку после.
- Прототип — источник дизайна: настоящие страницы собираем ИЗ него.

ФАЗА 1 · СКЕЛЕТ (результат: сайт открывается)
Сервер по ТЗ (если нет — сначала арендуем VPS и настраиваем как дом: отдельный
пользователь для LMS, не root; автозапуск; https на домене из ТЗ).
Страницы из прототипа раздаются с сервера. Пилотный «замок»: пока строимся —
один общий код доступа, чтобы чужие не гуляли.

ФАЗА 2 · ВХОД И ДОСТУПЫ (результат: ученики входят как в ТЗ)
Таблица учеников в базе: кто, сегмент/отдел, срок доступа, статус.
Вход по механике из ТЗ (безопасный дефолт: персональная ссылка-приглашение
с токеном + код на почту для восстановления).
ОБЯЗАТЕЛЬНО: отключение доступа одним действием (уволился → закрыто сегодня),
и страница «доступ закрыт» с контактом ответственного.

ФАЗА 3 · КОНТЕНТ (результат: первый курс лежит целиком)
Структура курс → модуль → урок из ТЗ. Уроки — страницы по шаблону прототипа.
Видео — на видеохостинге из ТЗ, в урок встраивается плеер (сами файлы
на сервер не кладём: дорого и медленно). Дозирование — по правилу из ТЗ.

ФАЗА 4 · ДЗ И ПРОГРЕСС (результат: полный путь ученика)
Сдача ДЗ в формате из ТЗ; статусы: не сдано → на проверке → принято/возврат.
Экран проверяющего с очередью. Прогресс ученика в базе; «урок пройден»
по правилу из ТЗ. Кабинет с прогрессом — как в прототипе.

ФАЗА 5 · СТРАХОВКИ (результат: не страшно запускать людей)
Бэкап базы и контента по расписанию + один тестовый прогон восстановления
(не «настроен», а «восстановили и открылось»). Уведомления по событиям из ТЗ.
Журнал входов. Алерт админу, если сервер упал или бэкап не прошёл.

ПОСЛЕ КАЖДОЙ ФАЗЫ: чек «фаза принята» — 3–5 проверок руками (формат: открываю
X → делаю Y → вижу Z). Перед пилотом — ПОЛНЫЙ чек-лист приёмки из раздела 11 ТЗ,
плюс три обязательных теста: (1) вход нового ученика с чужого телефона,
(2) отзыв доступа реально закрывает вход, (3) восстановление из бэкапа.
```

> 🎁 К маршруту Б полагается команда: скиллы из [skills/](skills/) этого кита (и, если проходили кит «Новоселье», ваша [IT-команда](../team-kit/README.md): cto, devops, secops, code-reviewer). Билдер строит — ревьюер проверяет каждую правку до деплоя.
>
> 🧱 Если у вас стоит методология [deep-build](../meeting-2-3/deep-build.md) (набор Встречи 2–3) — каждая фаза маршрута Б идёт по ней: исследование → план → сборка → проверка, режим M/L по размеру фазы. Скажите агенту в начале фазы: «веди эту фазу по deep-build». Это лучшая страховка от «неделю почти работает».

## Пилот: две недели, которые решают всё

Одинаков для обоих маршрутов. Из ТЗ у вас уже есть: состав пилотной группы, длительность, критерии успеха в цифрах (вопросы 91–92).

1. **Запуск руками.** Пригласите пилотную группу лично (не рассылкой): «ты в первой группе, твои замечания попадут в продукт». Первые 72 часа — личное касание каждому: вошёл? что непонятно?
2. **Дневник пилота.** Один файл `PILOT_LOG.md`: каждый вопрос ученика, каждый сбой, каждое «а как…» — с датой. Это план доработок, отсортированный самой жизнью.
3. **Правило севшей батарейки.** Ничего не дорабатывать в первые 3 дня, кроме блокеров («не могу войти»). Дайте проблемам накопиться и показать паттерн — иначе будете чинить случайный шум.
4. **Сверка с критериями.** В конце пилота — цифры против критериев из ТЗ. Прошли → расширяетесь на следующую фазу из плана запуска. Не прошли → это успех пилота (он для этого и был): доработки → второй пилот.

### ✅ Pruf модуля — получилось, если…

- полный путь ученика работает: приглашение → вход → уроки → ДЗ → проверка → финал курса;
- чек-лист приёмки из ТЗ прогнан **вами руками** — все пункты зелёные;
- отзыв доступа проверен фактом: закрытый ученик не входит;
- восстановление из бэкапа прогнано один раз по-настоящему;
- пилотная группа прошла курс, `PILOT_LOG.md` заполнен, цифры сверены с критериями;
- у платформы есть владелец после запуска (имя из ТЗ), и он знает, как ей управлять.

## Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| Маршрут А: платформа не умеет пункт ТЗ | Не привыкайте страдать: спросите агента «обходной путь / другая платформа / упростить процесс — сравни три варианта» |
| Маршрут Б: фаза «почти работает» неделю | «Стоп. Откати к концу прошлой фазы, разбей текущую на два шага поменьше, идём по одному» |
| Пилот молчит — ни вопросов, ни жалоб | Это не успех, это молчание. Личное касание каждому: «покажи экраном, как ты проходишь урок» — 15 минут дадут больше, чем неделя ожидания |
| Всё работает, но учеников не загнать | Проблема не техническая: вернитесь к вопросам 6 и 67 ТЗ (обязательность и связь с карьерой) — и к руководителям |
| Хочется дорабатывать вместо запуска | Перечитайте список «НЕ делаем в MVP» из ТЗ. Запуск с недоделками у пилота — норма; вечная стройка — смерть |

## Итог модуля и кита

У вас есть работающая LMS, прошедшая пилот: свой первый цифровой продукт. Дальше он растёт по плану из ТЗ: вторая очередь функций (отчёты руководителям, чат, выгрузки) → бэклог (бот, геймификация) → новые курсы. Каждая крупная доработка — тот же цикл в миниатюре: бриф → ТЗ → прототип → релиз.

```
#домашнее_задание MVP LMS: платформа запущена (маршрут А/Б), чек-лист приёмки прогнан,
пилотная группа прошла первый курс, PILOT_LOG.md с находками. Прикладываю ссылку
на платформу и скрин кабинета ученика.
```
