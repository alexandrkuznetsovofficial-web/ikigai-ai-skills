# Связка Икигай: сервер + бот в Telegram, пошагово

> **Для человека.** Этот файл ведёт Claude Code от твоего компьютера до работающей связки. Созвон не нужен.
> Claude сам осмотрит компьютер, сверит твою систему с эталоном Академии (что уже стоит, а чего не хватает),
> скачает свежие скиллы, поставит недостающее по шагам и в конце покажет, что было и что стало.
> Заложи 1,5–2 часа. Можно с перерывами: Claude ведёт журнал и продолжит с того же места.
>
> **Что получится в конце:**
> - сервер защищён: вход только по ключу, вход по паролю закрыт;
> - скиллы «Пробник», «Связка» и «Аудит второго мозга» обновлены до актуальной версии;
> - чекап по эталону Академии: сколько пунктов эталона закрыто до установки и после, плюс план на остальные;
> - память сама ездит между компьютером и сервером каждые 5 минут;
> - бэкапы: история версий на компьютере, копия на сервере, корзина на 30 дней;
> - бот в Telegram отвечает только тебе и по твоей памяти, утром в 08:00 присылает брифинг.
>
> **Отдельную программу «Терминал» открывать не нужно.** Все команды выполняет Claude. Ты отвечаешь в чате, вписываешь данные
> в блокнот, который он откроет, и пару раз заходишь в браузере в кабинет хостера и в Telegram.
> В трёх коротких моментах (пароль от сервера, токен подписки Claude и запасной вход перед финальной защитой)
> Claude попросит вставить одну готовую строку в новую вкладку терминала внизу окна VS Code и подскажет,
> как её открыть. Так пароль и токен не попадают в чат.
>
> **Перед началом — один клик.** Внизу окна чата Claude, рядом с полем ввода, переключи режим на ****Manual** (в других версиях — «Manual»; не «Edit automatically» и не «Auto»)**.
> В авто-режиме защита Claude Code молча отказывает установке скиллов и настройке сервера. В режиме «Manual»
> перед каждым действием всплывёт окно — нажимай «Разрешить». После установки авто-режим можно вернуть.
>
> **Главное правило:** пароли и токены никогда не пиши в чат Claude.

## 🔴 Железные правила для Claude (действуют на всех этапах)

1. **Пароли и токены — только через блокнот или скрытый ввод.** Никогда не проси их в чат и не выводи на экран.
   Секреты живут в файле доступа: ты создаёшь его, открываешь человеку в блокноте
   (Mac: `open -e <файл>`, Windows: `notepad <файл> &` — с `&`, чтобы команда не ждала закрытия блокнота), человек вписывает значения сам, сохраняет и закрывает.
   Заполненность проверяешь только счётчиком, не показывая значение:
   `grep -c '^BOT_TOKEN=.' <файл>` (1 — заполнено, 0 — пусто). Файл целиком не открываешь и не читаешь.
   Прислал секрет в чат — скажи, что он засвечен, и попроси перевыпустить (токен у @BotFather, пароль у хостера).
2. **Ничего не удаляем.** Старые версии скиллов — в `~/.claude/skills_old/`, старый бот и старые расписания — выключаем, не стираем.
3. **Один шаг за раз.** Сделал шаг → показал признак «готово» → записал строку в журнал → только потом дальше.
4. **IP сервера целиком не показываешь** ни в чате, ни в журнале.
5. **Шаги связки — только скриптом `brain_link.py`** по правилам скилла `brain-link` (его `SKILL.md` — главный
   источник). Не правишь сервер руками и в обход скрипта. Этот гайд ничего в правилах скилла не отменяет.
6. **Сбой → протокол сбоя скилла:** строка в `reference/troubleshooting.md` → не больше одной автоматической
   попытки → стоп → `brain_link.py report` → человек отправляет файл отчёта в чат потока. Обходы не изобретай.
7. **Человек не работает в терминале.** Все команды выполняешь ты сам. Исключения ровно три — `keys` (пароль root),
   `put-token claude` (токен подписки) и запасной вход перед `lockdown`: секрет не должен проходить через тебя.
   - Человек открывает **новую вкладку** терминала VS Code: только меню «Терминал → Новый терминал» (или Ctrl+Shift+`,
     на Mac ⌃⇧`). Не Ctrl+` — он может вернуть в окно, где работаешь ты, и пароль уйдёт в чат. Скажи прямо:
     «в новой вкладке, не там, где я». Windows: стрелка ˅ рядом с «+» → PowerShell (команды для Git Bash там не сработают).
   - Строку для вставки (в ней IP сервера) **не печатай в чат**: положи её в буфер обмена прямо из JSON скрипта
     (Mac `pbcopy`, Windows `clip`) и скажи «вставь Cmd/Ctrl+V и Enter». Вывод этой вкладки ты не читаешь.
   - Четвёртый случай — только в ветке B и только по желанию: команду `sudo brain-admin remove-private`
     (удалить личное с сервера) человек вводит так же, после своего «да».
   - Пароль-фразу на ключ (`ssh-keygen -p`) сейчас не предлагай.
   Отдельную программу «Терминал» человек не открывает.
8. **Никакого ручного подключения к серверу.** Не предлагай человеку подключать VS Code к серверу (Remote-SSH,
   кнопка `><` слева внизу), заходить по ssh в отдельном окне или руками править ssh-настройки. Связь компьютера
   и сервера ставит и чинит только `brain_link.py` и его `reference/troubleshooting.md`. Исключения — только три
   момента из правила 7 (`keys`, `put-token claude`, запасной вход перед `lockdown`) и VNC-консоль хостера. Отдельное окно Remote-SSH открывает чужую историю Claude — человек
   теряет диалог установки. Человек уже в таком окне — попроси закрыть его и вернуться в окно на компьютере.

## Этап 6. Связка: шаги скилла brain-link

Дальше ведёт скилл `brain-link`: прочитай его `SKILL.md` целиком и иди по таблице «Шаги». Для каждого шага —
«что сейчас будет» до, признак «готово» после, строка в журнале. Где действует сам человек:

| Шаг | Что говоришь человеку |
|---|---|
| `detect` | «Смотрю компьютер и сервер». Назови ветку: A — чистый сервер, B — сервер по старой схеме (переведём, ничего не удаляя), C — связка уже стоит (только проверим), D — сменился сервер |
| `keys` | «Сверяем отпечаток сервера, чтобы никто не подменил его по дороге». Первый `keys` выдаёт `vnc_command`: человек выполняет её в VNC-консоли и присылает строку `SHA256:…` (это не секрет). Ты сравниваешь её с `fingerprints` и запускаешь `keys --fingerprint SHA256:…`. Только после этого появится `command`: человек вставляет её в **панель терминала VS Code** по правилу 7 (на Windows — PowerShell, не Git Bash) и на вопрос пароля вставляет пароль root из блокнота. Символы при вводе не видны — так и должно быть |
| `harden` | «Защищаю сервер: отдельный пользователь, файрвол, защита от перебора паролей, автообновления». 5–10 минут |
| `claude` | «Ставлю Claude Code на сервер. Платный API-ключ не нужен» |
| `put-token claude` | Человек **сам** вставляет в панель терминала VS Code (правило 7; Windows — PowerShell) команду из колонки «человек сам» в `SKILL.md`: откроется вход в Claude, потом скрытое поле для токена. Ты вывод не читаешь. После — попроси выключить доплату сверх подписки в настройках Claude |
| `put-token bot` | Токен бота берётся из файла доступа, человеку ничего вводить не нужно |
| `init` / `adopt` | Сначала отчёт: сколько файлов уедет, сколько приедет, есть ли конфликты. Дальше — только после «да» |
| `schedule` | «Включаю синк: раз в 5 минут память будет сверяться с сервером». Mac пишет «Operation not permitted» → по `SKILL.md`: «Полный доступ к диску» для python3 |
| `bot` | Спроси: «Хочешь, чтобы бот понимал голосовые?» Да → `bot --voice`. Голос ставится только до lockdown |
| `verify` | Перед запуском: «Как только запущу проверку, напиши боту "запомни тест связки"». Проверка ждёт до 6 минут. Пункт (з) «чужому бот не отвечает» — попроси знакомого написать боту; некому — честно отметь «не проверено» |
| `lockdown` | Только если в `verify` все автоматические проверки ✅ и самопроверка (и) — PASS. Пункт (з) «чужому не отвечает» с отметкой «не проверено» lockdown не блокирует. Пройди чек-лист. Запасной вход: человек открывает ещё одну **новую** вкладку терминала VS Code (правило 7), ты кладёшь в буфер `ssh -p <порт> root@<сервер>` — пароль не спросит, вход по ключу. Увидел `root@…:~#` — вкладку не закрывает, пока ты не скажешь «lockdown включён». Плюс VNC работает, пароль root в менеджере паролей. «Да» дважды. Затем `lockdown --drop-password` — строка пароля уйдёт из файла доступа (копия .bak рядом) |

Самопроверка в `verify` упёрлась в лимит подписки → lockdown не делай, запиши в журнал «verify завтра» и переходи
к Этапу 7. Завтра человек говорит «продолжи установку связки по журналу».

## Этап 7. Бэкапы: три слоя

## Этап 9. Остаток плана и чекап «после»

2. Применяй **только после «делай»** и только согласованную часть (обычно скилл `memory-upgrade` из выпускного пака).
   Перед массовой правкой памяти — `brain_link.py pause`, после — `brain_link.py resume` (memory-upgrade делает это сам;
