# Связка Икигай: сервер + бот в Telegram, пошагово

> **Для человека.** Этот файл ведёт Claude Code от твоего компьютера до работающей связки. Созвон не нужен.
> Неважно, откуда ты стартуешь: с нуля, с полпути, со старой июльской схемы или после прошлой попытки.
> Claude сначала обновит три скилла, потом сам посмотрит, что у тебя уже сделано, покажет это одной таблицей
> «Где ты сейчас» — и дальше пойдёт только по тому, чего не хватает.
> С нуля заложи 1,5–2 часа, с полпути — меньше. Можно с перерывами: Claude ведёт журнал и продолжит с того же места.
>
> **Что получится в конце:**
> - сервер защищён: вход только по ключу, вход по паролю закрыт;
> - скиллы «Пробник», «Связка» и «Аудит второго мозга» обновлены до актуальной версии;
> - память сама ездит между компьютером и сервером каждые 5 минут;
> - бэкапы: история версий на компьютере, копия на сервере, корзина на 30 дней;
> - бот в Telegram отвечает только тебе и по твоей памяти, утром в 08:00 присылает брифинг;
> - по желанию — чекап по эталону Академии «было → стало».
>
> **Отдельную программу «Терминал» открывать не нужно.** Все команды выполняет Claude. Ты отвечаешь в чате, вписываешь данные
> в блокнот, который он откроет, и пару раз заходишь в браузере в кабинет хостера и в Telegram.
> В одном коротком моменте — токен подписки Claude — Claude попросит вставить одну готовую строку в новую
> вкладку терминала внизу окна VS Code и подскажет, как её открыть. Так токен не попадает в чат. Пароль от
> сервера ты вписываешь в блокнот, дальше его использует скрипт, через чат он не проходит.
>
> **Перед началом — один клик.** Внизу окна чата Claude, рядом с полем ввода, переключи режим на **«Manual»** (ладошка; в других версиях — «Ask before edits»; не «Edit automatically» и не «Auto»).
> В авто-режиме защита Claude Code молча отказывает установке скиллов и настройке сервера. В режиме «Manual»
> перед каждым действием всплывёт окно — нажимай «Разрешить». После установки авто-режим можно вернуть.
>
> **Главное правило:** пароли и токены никогда не пиши в чат Claude.

## 🔴 Железные правила для Claude (действуют на всех этапах)

1. **Пароли и токены — только через блокнот или скрытый ввод.** Никогда не проси их в чат и не выводи на экран.
   Секреты живут в файле доступа: ты создаёшь его, открываешь человеку в блокноте
   (Mac: `open -e <файл>`, Windows: `notepad <файл> &` — с `&`, чтобы команда не ждала закрытия блокнота), человек вписывает значения сам, сохраняет и закрывает.
   Заполненность проверяешь только счётчиком, не показывая значение:
   `grep -c '^BOT_TOKEN=.' <файл>` (1 — заполнено, 0 — пусто). Файл целиком не открываешь и не читаешь.
   Прислал секрет в чат — скажи, что он засвечен, и попроси перевыпустить (токен у @BotFather, пароль у хостера).
2. **Ничего не удаляем.** Старые версии скиллов — в `~/.claude/skills_old/`, старый бот и старые расписания — выключаем, не стираем.
3. **Один шаг за раз.** Сделал шаг → показал признак «готово» → записал строку в журнал → только потом дальше.
4. **IP сервера целиком не показываешь** ни в чате, ни в журнале.
5. **Шаги связки — только скриптом `brain_link.py`** по правилам скилла `brain-link` (его `SKILL.md` — главный
   источник). Не правишь сервер руками и в обход скрипта. Этот гайд ничего в правилах скилла не отменяет.
6. **Сбой → протокол сбоя скилла:** строка в `reference/troubleshooting.md` → не больше одной автоматической
   попытки → стоп → `brain_link.py report` → человек отправляет файл отчёта в чат потока. Обходы не изобретай.
7. **Человек не работает в терминале.** Все команды выполняешь ты сам. Исключение ровно одно — `put-token claude`
   (токен подписки): секрет не должен проходить через тебя. Пароль root `keys` берёт из файла доступа сам
   (Этап 5), запасной вход на время `lockdown` держит скрипт — терминал человеку для них не нужен.
   - Человек открывает **новую вкладку** терминала VS Code: только меню «Терминал → Новый терминал» (или Ctrl+Shift+`,
     на Mac ⌃⇧`). Не Ctrl+` — он может вернуть в окно, где работаешь ты, и пароль уйдёт в чат. Скажи прямо:
     «в новой вкладке, не там, где я». Windows: стрелка ˅ рядом с «+» → PowerShell (команды для Git Bash там не сработают).
   - Строку для вставки положи в буфер обмена (Mac `pbcopy`, Windows `clip`) и скажи «вставь Cmd/Ctrl+V и Enter».
     Вывод этой вкладки ты не читаешь.
   - Запасной путь `keys` — только если скрипт сам вернул поле `command`: нет `PASSWORD` в файле доступа (сначала
     попроси вписать), `key_install` = `askpass_failed`, `password_auth_disabled`, `push_failed` или
     `host_key_replaced` (здесь сначала сверка `--fingerprint`). Человек вставляет команду так же, в новой вкладке,
     пароль root вводит сам. Строку с IP в чат не печатай — только в буфер.
   - Четвёртый случай — только в варианте B и только по желанию: команду `sudo brain-admin remove-private`
     (удалить личное с сервера) человек вводит так же, после своего «да».
   - Пароль-фразу на ключ (`ssh-keygen -p`) сейчас не предлагай.
   Отдельную программу «Терминал» человек не открывает.
8. **Никакого ручного подключения к серверу.** Не предлагай человеку подключать VS Code к серверу (Remote-SSH,
   кнопка `><` слева внизу), заходить по ssh в отдельном окне или руками править ssh-настройки. Связь компьютера
   и сервера ставит и чинит только `brain_link.py` и его `reference/troubleshooting.md`. Исключение одно — `put-token
   claude` из правила 7. В VNC-консоль хостера человека не отправляй. Отдельное окно Remote-SSH открывает чужую историю Claude — человек
   теряет диалог установки. Человек уже в таком окне — попроси закрыть его и вернуться в окно на компьютере.
9. **Сделанное не переделываем.** Каждый этап после Этапа 2 начинается с проверки по карте «Где ты сейчас»
   (и по `next_step` из `detect`): шаг уже ✅ — пропусти его, запиши в журнал `… · пропущен: уже сделано` и иди дальше.
   Спрашивай человека только о том, что в карте ⏳ или ❔.
10. **Скрипты скиллов — с предупреждением.** Перед первым запуском пробника и `brain_link.py` скажи одной-двумя
    строками, что это за скрипт (пробник — «только читает настройки компьютера, ничего не меняет»; `brain_link.py` —
    «настраивает связь с твоим сервером по шагам скилла; `detect` только смотрит»), и спроси: «Запускаю?». После «да» —
    запускай. Claude Code всё равно заблокировал запуск — не обходи: не переписывай скрипт в команды, не копируй его
    содержимое, не меняй режим разрешений. Скажи: «Защита Claude Code просит подтверждения — нажми «Разрешить» в окне
    запроса». Не получилось — стоп, напиши в журнал и попроси человека отправить скриншот в чат потока.

## Режим разрешений

Первым делом проверь режим. Действие заблокировано без окна подтверждения — значит, сессия в авто-режиме:
попроси человека переключить режим внизу чата на «Manual» и написать «дальше». Не предлагай `/permissions`,
правила разрешений и правку настроек — только этот переключатель и кнопку «Разрешить».
Не входи в режим плана и не предлагай план на одобрение: при одобрении плана Claude Code сам возвращает режим в Auto.
Установка скиллов заблокирована и окна нет даже в Manual → запасной путь: человек сам копирует в Finder (Cmd+Shift+G)
или Проводнике три папки из `<источник>` в `~/.claude/skills/` (Windows: `%USERPROFILE%\.claude\skills`), ты проверяешь версии.

## Журнал установки

Файл `~/.config/brain/install_journal.md` (Windows: `%USERPROFILE%\.config\brain\install_journal.md`).
Без секретов и без IP. После каждого шага — строка: `ДАТА ВРЕМЯ · этап · шаг · ✅/❌/пропущен · что дальше`.

**Начало работы:** журнал уже есть → прочитай его, скажи человеку «мы остановились на …». Если с последней записи
прошло больше суток или журнал вёлся по старому гайду (другие номера этапов) — всё равно пройди Этапы 1–2:
свежие скиллы и новая карта «Где ты сейчас» покажут, что изменилось; потом продолжай с первого ⏳.
Журнала нет → создай его и начни с Этапа 1.

## Этап 1. Скиллы: поставить или обновить

Ставишь три скилла: «Пробник» (`ikigai-preflight`), «Связку» (`brain-link`) и «Аудит второго мозга»
(`second-brain-audit`). Архив кита — это файлы, а не программа: **ничего скачанного не запускаешь**
(защита Claude Code справедливо блокирует «скачать и сразу выполнить»). Распаковываешь встроенным модулем Python
и сам раскладываешь скиллы. Ниже `py -3` — для Windows (Git Bash), `python3` — для Mac. `<метка>` — дата-время, например `20261008-1700`.

**Пропуск:** все три скилла уже стоят и у `brain-link` `kit_version: 2.1`, а у человека нет свежего архива от
куратора → спроси «обновить до последней версии с GitHub? (1–2 минуты)». «Нет» → строка в журнал, Этап 2.

**Вариант 0 — архив уже у человека.** Если человек прислал или сказал, что скачал архив `Ikigai_Svyazka_Kit_*.zip`,
найди его: `~/Downloads/`, `~/Downloads/Telegram Desktop/` (Windows: `%USERPROFILE%\Downloads\…` — так же).
Нашёлся → **скачивание пропусти**: проверь `head -c 2 <архив>` = `PK` и переходи сразу к шагу 3, распаковывая этот
архив. Внутри него папка `ikigai-ai-skills-main` — это и есть `<unpacked_to>`.

1. **Скачать** (одна команда, Mac и Windows одинаково):
   `cd ~/Downloads && curl -fL --max-time 120 -o ikigai-kit.zip https://github.com/alexandrkuznetsovofficial-web/ikigai-ai-skills/archive/refs/heads/main.zip`
2. **Проверить, что это архив:** `head -c 2 ikigai-kit.zip` → должно быть `PK`. Иначе — запасной путь ниже.
3. **Распаковать в новую папку** (старые распаковки не трогаешь):
   `python3 -m zipfile -e <архив> ~/Downloads/ikigai-kit-<метка>` (Windows: `py -3 -m zipfile -e …`).
   Запомни полный путь: `<unpacked_to>` = `~/Downloads/ikigai-kit-<метка>/ikigai-ai-skills-main` (понадобится на Этапах 2, 5, 7 и 8),
   `<источник>` = тот же путь (откуда берёшь скиллы в шаге 5).
4. **Проверить версию:** `grep -m1 kit_version <unpacked_to>/brain-link/SKILL.md` → `kit_version: 2.1`.
5. **Поставить три скилла, ничего не удаляя.** Для каждого имени из трёх:
   - **сначала проверь**, что `<источник>/<имя>/SKILL.md` существует. Нет — стоп, ничего не переноси;
   - уже есть `~/.claude/skills/<имя>` → `mkdir -p ~/.claude/skills_old && mv ~/.claude/skills/<имя> ~/.claude/skills_old/<имя>-<метка>`;
   - копия без служебных папок:
     `python3 -c "import shutil,sys;shutil.copytree(sys.argv[1],sys.argv[2],ignore=shutil.ignore_patterns('ci','tests','__pycache__'))" <источник>/<имя> ~/.claude/skills/<имя>`
     (Windows: `py -3 -c …` — на Windows `python3` часто открывает Microsoft Store);
   - для `brain-link` ещё `cp <unpacked_to>/KIT_CONVENTIONS.md ~/.claude/skills/brain-link/`.
6. **Сверка остальных скиллов:** для каждой папки в `~/.claude/skills/`, у которой есть такая же папка в `<unpacked_to>`,
   сравни строку `kit_version`. Старее — назови человеку («их можно обновить потом выпускным паком»), сейчас не трогай.

**Запасной путь** (GitHub не открылся или пришёл не архив): попроси человека скачать в кабинете
(https://ikigai-community.com/cabinet/academy/skills) «Пробник», «Связку» и «Аудит второго мозга» в «Загрузки» и сказать
«готово». Распакуй их тем же `python3 -m zipfile -e` в `~/Downloads/ikigai-cabinet-<метка>` (Safari мог распаковать сам —
тогда в «Загрузках» уже папки `ikigai-preflight`, `brain-link`, `second-brain-audit`). `<источник>` для шага 5 — папка,
где лежат эти три папки. `<unpacked_to>` — новая папка `~/Downloads/ikigai-kit-<метка>/ikigai-ai-skills-main`: скачай
в неё с витрины `https://ikigai-community.com/aipotok/skills/start/` `KIT_CONVENTIONS.md` и три гайда по тем же путям —
`novoselie-server-kit/audit/server_access.example`, `meeting-2-3/auto-commit-backup.md`, `SETUP_MORNING_BRIEF.md`
(на витрине они лежат плоско: `start/server_access.example`, `start/auto-commit-backup.md`, `start/SETUP_MORNING_BRIEF.md`).
После скачивания проверь, что первая строка — не `<!DOCTYPE` (витрина на несуществующий файл отдаёт веб-страницу).

**Признак «готово»:** в `~/.claude/skills/` есть `ikigai-preflight`, `brain-link` (`kit_version: 2.1`) и `second-brain-audit`;
старые версии — в `~/.claude/skills_old/`. Скажи человеку одной строкой, откуда взят кит (архив, GitHub или кабинет).

## Этап 2. Диагностика: где ты сейчас

Только чтение, ничего не меняем и не чиним. Цель — одна таблица «Где ты сейчас». Файл доступа ради диагностики
**не заполняй**: сначала карта, потом подготовка.

**2.1. Пробник** — запусти **заново, даже если профиль уже есть** (старый может не знать про ssh и Python):
Mac `bash ~/.claude/skills/ikigai-preflight/scripts/probe.sh`; Windows — по `SKILL.md` пробника (`probe.ps1`).
**Признак «готово»:** в `~/.claude/ikigai_env.json` есть поля `os_branch`, `workspace`, `ssh`, `ssh_keygen`, `python_version`.
Нет профиля и пробник не нашёл мозг — спроси человека, где папка с `CLAUDE.md` и `memory/`.

**2.2. `brain_link.py detect`** (команда запуска — в `SKILL.md` скилла `brain-link`). Он ничего не меняет.
- **Код 4 «нет файла доступа» / «не вписан SERVER_IP» — это нормально:** сервер считается «не подключён»,
  строки сервера в карте — ❔ «проверим после файла доступа». Не заполняй файл сейчас.
- Код 0 — бери из JSON только эти поля:
  - `access` — какие строки файла доступа заполнены (значения секретов там уже замаскированы, IP — тоже);
  - `keys.admin_key`, `keys.known_hosts`, `ssh_ok` — вход по ключу;
  - `server` (есть, только если `ssh_ok`): `HARDENED`, `CLAUDE`, `CLAUDE_BOT`, `TOKEN_CLAUDE`, `TOKEN_BOT`, `BOT`,
    `LOCKDOWN`, `HEARTBEAT`, а признаки старой схемы — `MEMFILES`, `LEGACY_CRON`, `OLD_BOTS`;
  - `local`: `sync_initialized`, `schedule`, `verify_green`, `lockdown`, `legacy_mirrors`;
  - `branch` (A / B / C / D / ?), `next_step`, `warnings`.

**2.3. Осмотр компьютера** (только факты):
| Что | Как проверить (Mac / Windows через Git Bash) |
|---|---|
| Бэкап — авто-коммиты | `git -C <workspace> log -1 --format=%cr` и есть ли расписание авто-коммитов (как в гайде `<unpacked_to>/meeting-2-3/auto-commit-backup.md`) |
| Брифинг на компьютере | команды аудита из Шага 1 гайда `<unpacked_to>/SETUP_MORNING_BRIEF.md`: launchd `com.ikigai.morning-brief`, строка в `crontab -l`, задачи Windows `Ikigai morning-brief` и старая `IkigaiMorningBrief` |
| Старая схема на компьютере | `local.legacy_mirrors` из detect (ночное зеркало «истина на сервере») |
| Файл доступа | есть ли `~/.config/brain/server_access` — только факт; заполненность — счётчиком из правила 1 |

**2.4. Карта «Где ты сейчас».** Покажи человеку **одну** таблицу. Статусы: ✅ сделано · ⏳ не сделано ·
❔ проверим на шаге (detect этого не видит) · — не применимо. Правила заполнения:

| Строка | ✅, если… | Иначе |
|---|---|---|
| Сервер арендован | в `access` есть `SERVER_IP` | ❔ спросим (Этап 4) |
| Бот создан у @BotFather | в `access` есть `BOT_TOKEN` или `server.TOKEN_BOT` = 1 / `unknown` | ❔ спросим |
| Свой id (@userinfobot) | в `access` есть `USER_ID` | ❔ спросим |
| Подписка Claude Pro/Max | `server.TOKEN_CLAUDE` = 1 / `unknown` | ❔ спросим |
| Файл доступа | detect код 0 и в `access` есть `SERVER_IP`, `USER_ID`, `BOT_TOKEN`; `PASSWORD` нужен, только пока `keys` ⏳ | ⏳ |
| `keys` | `keys.admin_key`, `keys.known_hosts` и `ssh_ok` — все true | ⏳ |
| `harden` | `server.HARDENED` = 1 | ⏳; нет `server` — ❔ после keys |
| `claude` | `server.CLAUDE` = 1 и `server.CLAUDE_BOT` ≠ 0 | ⏳ / ❔ после keys |
| `put-token claude` | `server.TOKEN_CLAUDE` ≠ 0 (`unknown` — после lockdown brain не видит токен; detect считает сделанным) | ⏳ / ❔ после keys |
| `put-token bot` | `server.TOKEN_BOT` ≠ 0 | ⏳ / ❔ после keys |
| `init` / `adopt` | `local.sync_initialized` | ⏳ (вариант B → `adopt`, иначе `init`) |
| `schedule` | `local.schedule` | ⏳ |
| `bot` | `server.BOT` = active | ⏳ / ❔ после keys |
| `verify` | `local.verify_green` | ⏳ |
| `lockdown` | `server.LOCKDOWN` = 1 (или `local.lockdown`) | ⏳ / ❔ после keys |
| Бэкапы на компьютере | последний авто-коммит моложе суток и расписание стоит | ⏳ |
