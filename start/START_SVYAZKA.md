# Связка Икигай: сервер + бот в Telegram, пошагово

> **Для человека.** Этот файл ведёт Claude Code от твоего компьютера до работающей связки. Созвон не нужен:
> Claude сам осмотрит компьютер, скачает актуальные скиллы, проведёт по каждому шагу и в конце покажет итог.
> Заложи 1,5–2 часа. Можно с перерывами: Claude ведёт журнал и продолжит с того же места.
>
> **Что получится в конце:**
> - сервер защищён: вход только по ключу, вход по паролю закрыт;
> - скиллы «Пробник» и «Связка» обновлены до актуальной версии;
> - память сама ездит между компьютером и сервером каждые 5 минут;
> - бэкапы: история версий на компьютере, копия на сервере, корзина на 30 дней;
> - бот в Telegram отвечает только тебе и по твоей памяти, утром в 08:00 присылает брифинг.
>
> **Главное правило:** пароли и токены никогда не пишешь в чат Claude. Только в блокнот, который Claude тебе
> откроет, или в своё окно терминала, когда тебя об этом попросят.

## 🔴 Железные правила для Claude (действуют на всех этапах)

1. **Пароли и токены — только через блокнот или скрытый ввод.** Никогда не проси их в чат и не выводи на экран.
   Секреты живут в файле доступа: ты создаёшь его, открываешь человеку в блокноте
   (Mac: `open -e <файл>`, Windows: `notepad <файл> &` — с `&`, чтобы команда не ждала закрытия блокнота), человек вписывает значения сам, сохраняет и закрывает.
   Заполненность проверяешь только счётчиком, не показывая значение:
   `grep -c '^BOT_TOKEN=.' <файл>` (1 — заполнено, 0 — пусто). Файл целиком не открываешь и не читаешь.
   Прислал секрет в чат — скажи, что он засвечен, и попроси перевыпустить (токен у @BotFather, пароль у хостера).
2. **Ничего не удаляем.** Старые версии — в `_old`, старый бот и старые расписания — выключаем, не стираем.
3. **Один шаг за раз.** Сделал шаг → показал признак «готово» → записал строку в журнал → только потом дальше.
4. **IP сервера целиком не показываешь** ни в чате, ни в журнале.
5. **Шаги связки — только скриптом `brain_link.py`** по правилам скилла `brain-link` (его `SKILL.md` — главный
   источник). Не правишь сервер руками и в обход скрипта. Этот гайд ничего в правилах скилла не отменяет.
6. **Сбой → протокол сбоя скилла:** строка в `reference/troubleshooting.md` → не больше одной автоматической
   попытки → стоп → `brain_link.py report` → человек отправляет файл отчёта в чат потока. Обходы не изобретай.

## Этап 5. Файл доступа — через блокнот

1. Файла `~/.config/brain/server_access` нет → создай его из шаблона
   `<unpacked_to>/novoselie-server-kit/audit/server_access.example`: папка `~/.config/brain` с правами 700, файл 600.
   Файл уже есть → не перезаписывай. Проверь счётчиком, есть ли в нём строки `SERVER_IP=` и `USER_ID=`
   (`grep -c '^SERVER_IP=' <файл>`). Нет — это старый формат (`IP=`, `LOGIN=`, `PORT=`, `CLAUDE_TOKEN=`): допиши в конец файла
   пустые строки нового шаблона и попроси человека в блокноте перенести значения в новые ключи, а строку
   `CLAUDE_TOKEN` стереть (токен подписки здесь больше не хранится).
2. Открой файл человеку в блокноте (Mac: `open -e ~/.config/brain/server_access`; Windows:
   `notepad "$USERPROFILE\.config\brain\server_access" &`) и скажи: «Впиши в каждой строке после знака "=": IP сервера, пароль root,
   токен бота и свой id. SERVER_USER и SERVER_PORT не трогай. Сохрани (Cmd+S / Ctrl+S) и закрой блокнот».
3. Проверь заполненность счётчиками, не показывая значений:
   `for k in SERVER_IP PASSWORD BOT_TOKEN USER_ID; do printf "%s " $k; grep -c "^$k=." ~/.config/brain/server_access; done`
   Где 0 — снова открой блокнот и назови, какое поле пустое.

## Этап 6. Связка: шаги скилла brain-link

Дальше ведёт скилл `brain-link`: прочитай его `SKILL.md` целиком и иди по таблице «Шаги». Для каждого шага —
«что сейчас будет» до, признак «готово» после, строка в журнале. Где действует сам человек:

| Шаг | Что говоришь человеку |
|---|---|
| `detect` | «Смотрю компьютер и сервер». Назови ветку: A — чистый сервер, B — сервер по старой схеме (переведём, ничего не удаляя), C — связка уже стоит (только проверим), D — сменился сервер |
| `keys` | «Сверяем отпечаток сервера, чтобы никто не подменил его по дороге». Первый `keys` выдаёт `vnc_command`: человек выполняет её в VNC-консоли и присылает строку `SHA256:…` (это не секрет). Ты сравниваешь её с `fingerprints` и запускаешь `keys --fingerprint SHA256:…`. Только после этого появится `command`: человек вводит её в **своём** окне терминала (Mac — Терминал, Windows — **PowerShell**, не Git Bash) и на вопрос пароля вставляет пароль root из блокнота. Символы при вводе не видны — так и должно быть |
| `harden` | «Защищаю сервер: отдельный пользователь, файрвол, защита от перебора паролей, автообновления». 5–10 минут |
| `claude` | «Ставлю Claude Code на сервер. Платный API-ключ не нужен» |
| `put-token claude` | Человек **сам** в своём терминале (Mac — Терминал, Windows — **PowerShell**) запускает команду из колонки «человек сам» в `SKILL.md`: откроется вход в Claude, потом скрытое поле для токена. Ты вывод не читаешь. После — попроси выключить доплату сверх подписки в настройках Claude |
| `put-token bot` | Токен бота берётся из файла доступа, человеку ничего вводить не нужно |
| `init` / `adopt` | Сначала отчёт: сколько файлов уедет, сколько приедет, есть ли конфликты. Дальше — только после «да» |
| `schedule` | «Включаю синк: раз в 5 минут память будет сверяться с сервером». Mac пишет «Operation not permitted» → по `SKILL.md`: «Полный доступ к диску» для python3 |
| `bot` | Спроси: «Хочешь, чтобы бот понимал голосовые?» Да → `bot --voice`. Голос ставится только до lockdown |
| `verify` | Перед запуском: «Как только запущу проверку, напиши боту "запомни тест связки"». Проверка ждёт до 6 минут. Пункт (з) «чужому бот не отвечает» — попроси знакомого написать боту; некому — честно отметь «не проверено» |
| `lockdown` | Только если в `verify` все автоматические проверки ✅ и самопроверка (и) — PASS. Пункт (з) «чужому не отвечает» с отметкой «не проверено» lockdown не блокирует. Пройди чек-лист: открыто второе окно с сервером, VNC работает, пароль root в менеджере паролей. «Да» дважды. Затем `lockdown --drop-password` — строка пароля уйдёт из файла доступа (копия .bak рядом) |

Самопроверка в `verify` упёрлась в лимит подписки → lockdown не делай, запиши в журнал «verify завтра» и переходи
к Этапу 7. Завтра человек говорит «продолжи установку связки по журналу».

## Этап 7. Бэкапы: три слоя

Объясни человеку: (1) **история версий на компьютере** — авто-коммиты каждые 30 минут, память никуда не уходит;
(2) **копия на сервере** — её держит синк; (3) **корзина** — удалённое на сервере 30 дней лежит в `~/.brain-trash/`,
при конфликте рядом появляется копия `.conflict-…`.

Слой 1 проверь: `git -C <workspace> log -1 --format=%cr` и расписание авто-коммитов.
Нет или последний снимок старше суток → выполни гайд `<unpacked_to>/meeting-2-3/auto-commit-backup.md`,
шаги 0–6 и 8, **только для компьютера** (Mac / Windows). Пропусти: **Шаг 7 (GitHub)** — память в GitHub не
отправляется никогда; в **Шаге 5** — блок «Linux / VPS-сервер» и заметку про ночное зеркало сервер → компьютер
(сервером управляет только `brain_link.py`). Если гайд предлагает удалить файл с доступами GitHub — не удаляй,
а переименуй в `<имя>.old`.
**Признак «готово»:** последний коммит моложе 30 минут, расписание стоит.
