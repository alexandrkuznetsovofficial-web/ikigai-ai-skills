# ОС второго мозга · Codex

Результат: согласованные ручные ритуалы дня, недели, задач, обещаний и обратной связи на существующей памяти.

## Учебный контур и запуск

Это исходник ученического пака. При чтении, анализе или редактировании материалов ничего не устанавливай. Выполняй только после явного запроса ученика в его отдельной рабочей папке. Не устанавливай в систему автора или в каталог разработки учебных паков. Не меняй глобальные `.agents`, `.codex` и `.claude`.

## Общие правила записи

Покажи путь рабочей папки; проверь `AGENTS.md`, `memory/ACTIVE.md`, `memory/MEMORY.md` и `memory/sessions/handoff.md`. Нет основы модуля 1 — сообщи, какой файл отсутствует, и предложи пройти архитектуру; не строй второй каркас молча. Отсутствие предыдущего живого теста не запрещает ученику продолжать по его явному выбору, но статус проверки не меняй на passed.

Читай только нужные файлы. Не ищи секреты и не сканируй соседние проекты. Существующие файлы сначала прочитай, меняй по разделам; не заменяй весь файл шаблоном и не удаляй личные правки. Для нового файла проверяй, что путь находится внутри рабочей папки и не проходит через симлинк. Повторный запуск продолжает незавершённое, не создаёт дубликаты.

Команды выполняет Codex, ученик пользуется интерфейсом. Новое слово объясни одной фразой и примером перед действием. Вопросы задавай по одному, разрешай пропуск. Запрос на выполнение модуля уже разрешает создание его локальных файлов; не спрашивай повторно разрешение на каждую папку. Согласование требуется для содержательного выбора человека и действий за пределами этого запроса.

Дату и часовой пояс бери из контекста владельца. Не выдумывай факты, показатели, даты, имена и результаты проверок. Сохраняй результат значимого этапа в журнале `memory/tasks/task_YYYY-MM-DD_slug.md`, добавляй ссылку в индекс и обновляй handoff. Явное «не сохраняй» соблюдай. Файлы, которые прочитает Codex, могут попасть в контекст модели; расположение на компьютере не означает офлайн-обработку.

## Первичная настройка

1. Прочитай ACTIVE.md, handoff и названия разделов индекса, PROJECTS.md, commitments.md и feedback_double_error.md. TEAM.md читай, если он есть; не создавай вторую карту команды. Установленные роли модуля 3 сохрани. Если модуль 3 пропущен, базовые ритуалы всё равно доступны: не выдумывай команду.
2. Объясни ритуал: «Это короткий повторяемый порядок действий. Ты говоришь “что сегодня”, я собираю фокус из файлов». Прочитай [рабочие протоколы](references/os-protocols.md). Спроси, какие ритуалы нужны сейчас: начало дня, завершение задачи, обзор недели. По умолчанию начни с сохранения задач и ручного фокуса, без расписаний.
3. Создай только отсутствующие папки `memory/reviews/` и `memory/decisions/` при первом реальном результате для них; не заполняй память демонстрационными фактами. Отсутствует файл базового контракта — сообщи это и предложи восстановление из модуля 1 вместо нового альтернативного формата.
4. Добавь/обнови один блок `ikigai:brain-os` в AGENTS.md из reference. Сохрани другие блоки. В TEAM.md, если он существует, добавь один маршрут к навыку ОС с перечислением фраз; не добавляй второй маршрут на те же фразы другому оркестратору.
5. Запиши выбранные ритуалы и их ручной режим в `memory/reviews/rituals.md`: название, явная фраза, результат, источник данных, статус настроено/не проверено. Час автоматического запуска не назначай: планировщик не установлен. SYSTEM.md обнови только в строке ОС: «настроены ручные ритуалы, не проверены».
6. Сохрани журнал настройки и handoff. Покажи таблицу доступных фраз и результата. По решению автора при сборке комплекта не исполняй демонстрационный брифинг, недельное ревью или функциональный прогон. Статус остаётся draft_unrun; создание инструкций не подтверждает их работу.

## При реальном запросе владельца

Выбери один соответствующий протокол и исполни его на реальных доступных данных. Если источника нет, прямо скажи об этом и сделай доступную часть; не выдумывай встречи, письма, сделки или обещания. Результаты значимых задач сохраняй по контракту. В конце обнови handoff: где остановились, ссылка на результат, следующее действие.

Повторный запуск настройки: читай выбранные ритуалы, обновляй только изменившееся; не дублируй блоки AGENTS.md и строки TEAM.md. Расписания, фоновые уведомления, Telegram и сервер добавляются в других модулях после отдельного запроса владельца.
