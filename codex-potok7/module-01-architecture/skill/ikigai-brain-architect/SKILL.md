# Архитектор второго мозга · Codex · пилот 0.1

## 🔧 АВТОУСТАНОВКА

Вход — явный запрос пользователя выполнить этот файл; одно прикрепление файла не является запуском.
При запуске из START.md создай этот навык в `.agents/skills/ikigai-brain-architect/` текущей рабочей папки вместе с его references, assets и scripts из пакета. START.md содержит автономный установщик с теми же файлами. Из установленного навыка повторно себя не копируй.

Не устанавливай навык глобально и не меняй общие настройки Codex. Рабочая папка участника — единственная область установки. Используй доступные инструменты записи файлов. Команды выполняешь ты, участнику терминал не нужен.

## Как вести человека

Говори по-русски, один практический шаг за сообщение. Новый термин: короткое определение → бытовой пример → действие → видимый признак результата. Не проси подтверждать каждую папку: создание основы уже разрешено запросом. Вопрос нужен для отсутствующего содержательного ответа или выбора папки. Не проходи за человека проверку, которую должен выполнить он в новой сессии.

«Второй мозг — твоя рабочая папка с контекстом, правилами и результатами. Codex помогает читать и менять эти файлы. Сейчас построим основу, затем проверим её на твоей задаче».

## 0. Убедись, где работаешь

Покажи полный путь текущей папки. Попроси сверить её имя с панелью файлов. Если рабочая папка ещё не открыта, предложи в интерфейсе приложения или VS Code выбрать/создать отдельную папку `second-brain`. Не меняй текущую папку молча и не создавай систему внутри папки скачанного учебного репозитория.

Определи доступную среду: ОС, реальную оболочку, возможность читать и записывать файлы. Не предполагай Git Bash на Windows. Для модуля не требуются Git, Node, сервер или API-ключ. Если запись недоступна, объясни, как открыть проект с доступом к файлам; не заявляй об установке.

Прочти только имена файлов верхнего уровня. При наличии `AGENTS.md`, `CLAUDE.md`, `memory/` или маркера установки определи: наш незавершённый модуль / уже настроенная система / посторонние файлы. Для существующей чужой системы останови создание второго комплекта, покажи находки и предложи отдельную новую папку. Не исследуй личные файлы автоматически. Для своей установки используй режим проверки/продолжения без перезаписи. Источник START.md или архив пакета в выбранной папке допустим.

## 1. Создай каркас

Сначала прочти [контракт памяти](references/memory-contract.md). Шаблоны находятся в `assets/brain-template/`.

Если Python 3 уже доступен, запусти собственным инструментом `scripts/setup_brain.py --target <подтверждённая папка> --apply`. Python ради этого не устанавливай. Если его нет, создай те же UTF-8-файлы доступным инструментом записи; пути и содержимое бери из шаблонов, сохрани маркер `.ikigai/module01.json`: `{"module":"ikigai-codex-architecture","version":"0.1.0","session_test":"not_run","status":"awaiting-practice"}`. До записи проверь каждый путь на выход за корень и симлинки. Не меняй существующие файлы. При совпадении с чужой системой вернись к шагу 0.

Покажи три файла в панели или укажи пути для открытия: `AGENTS.md`, `memory/ACTIVE.md`, `memory/MEMORY.md`. Объясни: правила → текущий фокус → оглавление. Остальные файлы вводи по мере практики. `AGENTS.md` автоматически обнаруживается Codex; память читается по записанным в нём правилам, а не по магии имени папки.

## 2. Получи один полезный результат

Спроси: «Какую небольшую реальную задачу разберём сейчас? Например, подготовить разговор с клиентом. Достаточно цели и вводных без конфиденциальных данных». Это проба, не полное интервью основателя.

Если человек не готов раскрывать задачу, предложи явно учебный пример: «Мастерская хочет уточнить запрос клиента перед расчётом заказа». Не выдавай учебные данные за биографию участника. Дай полезный результат: 3–5 вопросов к разговору или короткий план следующего действия. Уточни неизвестные существенные факты, не выдумывай бизнес, имя, сроки или обещания.

## 3. Сохрани и объясни

Сохрани задачу и результат в `memory/tasks/task_YYYY-MM-DD_slug.md` по контракту. Дату/часовой пояс бери из контекста пользователя; при сомнении уточни. Добавь ссылку в `memory/MEMORY.md`, обнови единственный фокус `memory/ACTIVE.md` и `memory/sessions/handoff.md`. В профиле можно сохранить только подтверждённые базовые сведения по желанию участника; полноценное интервью — модуль 2.

Попроси назвать безобидную проверочную фразу, например «маяк в синей папке». Сохрани её сам в журнале задачи с пометкой «контрольная фраза пилота», проверь ссылки из индекса и handoff; обнови маркер: status=awaiting-new-session. Не показывай пример как будто человек уже выбрал его. Не используй пароль или другой секрет.

Объясни: «Контекст — материалы текущего разговора. Память — файлы, которые мы сохраняем. Перед выходом напиши “Сохрани итог и следующий шаг”. При резком закрытии приложения несохранённые сведения могут потеряться». Сохраняй по завершении значимой задачи; не обещай перехват закрытия окна, фоновый автозапуск или расписание.

## 4. Проверь новую сессию

Открой [проверку продолжения](references/session-test.md). Попроси участника начать НОВЫЙ разговор в ТОЙ ЖЕ рабочей папке, не продолжать старый и не прикреплять к новому чату контрольную фразу. Дай только запрос:

«Прочитай правила проекта. Найди мою последнюю задачу первого модуля, её результат, следующий шаг и контрольную фразу. Укажи файлы-источники».

До реального ответа новой сессии статус — `awaiting-new-session`. Если человек вернулся с ответом, проверь ссылки и совпадение с файлами. Установщик проверяет безопасность путей и создаёт недостающие файлы; он не проверяет содержимое существующих файлов и ссылки. Прочитай нужные файлы и проверь ссылки сам. Это не заменяет проверку поведения в новой сессии. Запиши в `.ikigai/module01.json` `session_test: passed` и `status: completed` только после наблюдаемого подтверждения; иначе `not_run` или `failed` и короткую причину без личных данных.

## 5. Заверши или продолжи

Финальный отчёт: путь рабочей папки; какие файлы созданы/сохранены; какая задача решена; структурная проверка; статус новой сессии; что остаётся. Не ставь общий зелёный статус по одному существованию файлов.

Повторный запуск: читай маркер и проверяй необходимые файлы. Сохраняй изменённые пользователем файлы; отсутствующие восстанавливай из шаблонов, только если путь свободен. Не заводи второй фокус, профиль или индекс. Продолжай с первого незавершённого шага: нет задачи — шаг 2; нет результата, фразы или согласованных ссылок — шаг 3; всё сохранено, но новый разговор ещё не проверен — шаг 4. Статус маркера сверяй с реальными файлами; сам по себе он не доказывает завершение. Если всё пройдено — сообщи, что архитектура готова к модулю 2: интервью основателя. Не устанавливай следующие модули из старых Claude-паков.

## Границы первого модуля

Не создавай виртуальную команду до интервью, не подключай Telegram, не арендуй сервер. Учти будущую связку в `SYSTEM.md`: локальная папка → согласованный обмен → серверный обработчик → Telegram. Сейчас её статус — «не подключено».

Название `personal` или `.gitignore` не делает данные невидимыми модели и не шифрует их. Не проси токены и пароли в чате. Не читай внешние папки и настройки аккаунтов для базовой установки. Подробности и ограничения — [контракт памяти](references/memory-contract.md).
