# Контракт памяти · Codex · 0.1

Это единый набор путей для модулей потока. Меняя контракт в будущем, обновляй зависимые модули вместе.

| Путь в рабочей папке | Назначение | Когда читать/обновлять |
|---|---|---|
| `AGENTS.md` | Короткие постоянные правила | Codex обнаруживает в области проекта; изменения проверять новой сессией |
| `SYSTEM.md` | Карта системы, границы локальной/серверной частей | При настройке и подключениях |
| `memory/ACTIVE.md` | Единственный текущий фокус | Начало работы и смена фокуса; ориентир до 20 строк |
| `memory/MEMORY.md` | Индекс, ссылки на источники | Искать нужное; после появления нового значимого результата |
| `memory/user_profile.md` | Подтверждённые сведения владельца | По задаче; полноценно заполняется модулем 2 |
| `memory/PROJECTS.md` | Цели проектов, сроки и статусы | По проектной задаче; даты только подтверждённые |
| `memory/commitments.md` | Обещания владельца | При явном обязательстве; open/done/dropped, историю сохранять |
| `memory/tasks/task_YYYY-MM-DD_slug.md` | Запрос, результат и следующий шаг | По завершении значимой задачи |
| `memory/sessions/handoff.md` | Передача работы между разговорами | Один актуальный указатель на фокус, журнал и следующий шаг |
| `memory/feedback_double_error.md` | Практические правила из повторных исправлений | После повторения ошибки предложить узкое правило |
| `memory/decisions/` | Решения и основания | Только при содержательном решении; без внутренних рассуждений модели |
| `memory/insights/`, `memory/archive/` | Выводы и завершённые материалы | По необходимости, без массового чтения |
| `.ikigai/module01.json` | Версия и статус проверки модуля | Установка, повтор, пилот |

Пример журнала задачи:

```markdown
# Подготовить разговор с клиентом
Дата: подтверждённая дата участника
Статус: open
## Запрос
Что попросил владелец; учебный пример явно помечен.
## Результат
Практический текст или относительная ссылка на созданный файл.
## Решения и основания
Краткое объяснение выбора, подтверждённые факты и открытые вопросы.
## Следующий шаг
Действие и исполнитель; срок только если согласован.
```

В индекс — одна строка со ссылкой, а не копия полного журнала. В фокус — только незавершённое. Закрытые задачи остаются в журнале; при переносе в архив обновляются ссылки. При повторном сохранении обновляй ту же задачу, не создавай бесконечные дубли. Для двух разных задач за день используй разные slug; совпавшее имя не перезаписывай.

## Контекст и расход

Корневой инструктаж — ориентир до 8 КБ UTF-8; это бюджет нашего модуля, не заявленный лимит продукта. На старте читай фокус и указатель передачи; индекс — для поиска, остальные материалы — по задаче. Не загружай всю память, все навыки и транскрипции сразу. Индекс или фокус разросся — предложи сжатие с сохранением ссылок. Не заявляй точные оставшиеся токены подписки без показаний интерфейса.

## Доступ и приватность

Файлы, которые Codex читает, попадают в контекст модели. Локальное расположение и имя папки не означают офлайн-обработку. `.gitignore` помогает исключать новые файлы из Git, но не скрывает их от Codex и не удаляет уже опубликованное. Не помещай секреты в инструкции, профиль, журналы или контрольную фразу.

Этот модуль не создаёт Git-репозиторий участника и ничего из его памяти не публикует. Подключение удалённых хранилищ требует отдельного выбора состава данных. Будущая серверная синхронизация не копирует всю папку: её правила и проверка конфликтов проектируются в серверном модуле.

Применять PARA и стадии заметок будем после появления содержимого. PARA — способ разделять проекты, постоянные области, справочные материалы и архив. В первом модуле не требуем от новичка учить разметку для создания пустой заметки.
