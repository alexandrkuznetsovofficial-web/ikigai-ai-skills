# Контракт команды Codex

Единственная карта — `TEAM.md` в корне рабочей папки ученика. Проектные навыки — `.agents/skills/<name>/SKILL.md`. Не создавать копию карты внутри навыка, memory/ai-team.md или глобальных каталогов.

```markdown
# Моя AI-команда
Обновлено: дата владельца
Оркестратор: выбранное имя / без имени
Режим: ассистент / операционный руководитель / управляющий партнёр
## Исполнители
| Роль | ЦКП | Когда звать | Навык | Статус |
|---|---|---|---|---|
## Наставники
| Область совета | Метод | Когда полезен | Ограничение |
|---|---|---|---|
## Агенты с отдельным выполнением
Не настроены, если не создан и не проверен конкретный механизм Codex.
## Очередь найма
Роль, причина, что должно случиться для установки. Это не установленная команда.
```

ЦКП — ценный конечный продукт: конкретный результат роли. Например, не «помогать продавать», а «черновик предложения с исходными данными, ценой только из подтверждённого источника и вопросами к клиенту». Навык — инструкция, агент — отдельное выполнение; наличие SKILL.md не означает независимый процесс.

## Обязательная форма создаваемого навыка роли

```markdown
---
name: lowercase-role-name
description: Точная задача роли и 2–3 естественных запроса, по которым её выбирать.
---
# Название роли
## ЦКП
Проверяемый итог и критерии качества.
## Нужные вводные
Файлы/ответы. Если их нет — что уточнить, что можно сделать с пометкой.
## Порядок
1. Прочитай только релевантные вводные и установи цель.
2. Отдели факты от гипотез, уточни существенное неизвестное.
3. Выполни конкретные операции этой роли (здесь автор роли пишет реальные шаги под задачу).
4. Проверь результат по критериям ЦКП, покажи ошибки/ограничения.
5. Сохрани полезный результат и ссылку в журнал; следующий шаг.
## Границы
Какие внешние действия не разрешает одно создание черновика; когда нужна другая роль.
```

Шаблон — форма, а не готовый навык. Создавая роль, замени общие слова конкретной процедурой по реальным задачам владельца. Не оставляй фразу «здесь автор роли пишет» в установленном файле.

## Как подобрать первый состав

Сначала выбрать 3–5 полезных исполнителей под профиль, не устанавливать 30 ролей. Примеры состава являются кандидатами, не универсальным наймом:
- Эксперт/консультант: подготовка клиентского разговора → коммерческий черновик → редактор материалов.
- Сервисная команда: описание запроса клиента → план исполнения → проверка результата.
- Продукт на ранней стадии: исследование клиентской проблемы → план интервью → синтез наблюдений.
Если реальных задач только одна-две, не выдумывай пять: предложи три компактные роли с ясными границами либо более короткий состав по решению владельца.

Наставники консультируют по рамке (например, поиск ограничения, первые принципы, противоречия); не имитируй конкретного человека как источник подлинного совета. Метод не является фактами о бизнесе. Оркестратор приносит вопрос на совет, решение владельца выше рекомендаций модели.

## Блок маршрутизации

```markdown
<!-- ikigai:team-routing:start -->
## Команда
Карта команды: `TEAM.md`. Для составной задачи сначала прочитай карту, выбери установленный навык по ЦКП и нужным вводным. Не читай все навыки сразу. Рекомендованная роль ещё не считается установленной. Если подходит несколько, объясни выбор; нет подходящей — выполни доступную часть и предложи создание роли. Наставники дают совет, исполнители создают результат.
<!-- ikigai:team-routing:end -->
```

Добавить один блок в AGENTS.md, обновлять по маркерам. Не ослаблять разрешения и не добавлять автоматические хуки. Обнаружение навыков и маршрутизация сейчас не прогоняются; отмечать configured_unverified, а не verified.
