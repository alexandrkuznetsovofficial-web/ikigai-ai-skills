# Границы минимального моста

Код — учебный черновик без запуска. Это ограниченный текстовый backend, а не проверенный production-сервис и не перенос всего Claude brain-link.

## Что реализовано в исходниках

- Long polling Telegram Bot API; один процесс, SQLite-очередь до восьми запросов. Модельные запросы обрабатываются последовательно, до двух новых вопросов в минуту. Сервис сохраняет offset и ID запросов.
- Доступ только при совпадении заранее заданного numeric owner ID, private chat и chat ID. У владельца не должно быть общего аккаунта; username не используется как замок.
- Текст до 6000 знаков. Файлы, голос и группы пропускаются. Ответ обрезается до 10000 знаков и отправляется частями до 3000.
- Codex вызывается как список аргументов без shell. Таймаут 180 секунд; процессная группа останавливается при превышении. Нет автоматического повторного платного запроса после сбоя. Если ответ потерян при доставке, владелец решает, повторять ли вопрос.
- Отдельные CODEX_HOME, рабочая папка и минимальный env без токена Telegram. `--ignore-user-config`/`--ignore-rules`; read-only sandbox; отключены shell_tool, unified_exec, plugins, remote_plugin, multi_agent, skill_search; web_search disabled. Совместимость флагов проверяется на установленной версии перед запуском. Несовместимость = остановка, не обход ограничений.
- Модель видит только заранее выбранные plain MD-выжимки из approved.json через stdin. Обычный запрос не читает живую локальную папку и не пишет память.
- `/save текст` пишет отдельную заметку с ID обновления: повтор одного update не создаёт второй файл. Заметка ещё не импортирована на компьютер. Очередь хранит текст до обработки; после завершения/ошибки текст очищается, метаданные остаются. При аварийном перезапуске начатая работа помечается interrupted и не повторяется автоматически.
- В журнале только события, без запроса, ответа, URLs токена и stderr CLI.

## Что этот режим не гарантирует

Sandbox read-only сам по себе не является доказательством отсутствия всех каналов чтения/доступа. Именно поэтому инструменты выключены, модель не получает служебных секретов в stdin/env, каталоги разделены и не используются внешние интеграции. До боевого применения нужен отдельный аудит фактической версии CLI и сервиса. Не ослабляй sandbox и не включай MCP ради «чтобы заработало».

В коде нет голосового ввода, подтверждений удалённых действий, ответов от специалистов, постоянного диалога со всем контекстом, двухстороннего синка и автоматического импорта inbox. Если ученик выбирает эти функции — это отдельное расширение с собственными разрешениями и тестами, а не зелёная галочка текущего модуля.
