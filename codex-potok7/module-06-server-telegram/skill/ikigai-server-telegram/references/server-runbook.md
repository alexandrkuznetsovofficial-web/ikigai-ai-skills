# Пошаговая установка серверной части

Этот runbook исполняет агент в разрешённой среде ученика; команды ниже — технические действия агента, не домашнее задание «вводить терминал». Состояние: draft_unrun. Предварительно: первый модуль работает, выбран сервер ученика, подтверждены бюджет и состав удалённых данных. Потребуется Linux с systemd, Python 3.9+, исходящий HTTPS к Telegram и OpenAI. Входящий HTTP-порт боту не нужен: используется long polling.

## Размещение

| Путь | Владелец/назначение |
|---|---|
| `/srv/ikigai/app/telegram_bridge.py` | Код сервиса, запись только администратору |
| `/srv/ikigai/approved/` | Утверждённый снимок, сервис только читает |
| `/srv/ikigai/state/` | Очередь, временные ответы и inbox; доступ только сервису |
| `/srv/ikigai/codex-home/` | Отдельная авторизация Codex; доступ только сервису |
| `/etc/ikigai/bridge.env` | Несекретные параметры, 0600 |
| `/etc/ikigai/bot.token` | Единственное значение токена бота, 0600 |
| `/etc/systemd/system/ikigai-telegram.service` | Шаблон systemd; заполнить после сверки путей |

1. Агент определяет ОС и проверяет занятые службы/порты без чтения чужих секретов. Подключение — SSH по ключу с проверкой fingerprint. Нельзя заменять существующие службы только по похожему имени.
2. Администратор создаёт системного пользователя `brain` без sudo и каталоги по таблице. Пример технического действия: `useradd --system --home-dir /srv/ikigai --shell /usr/sbin/nologin brain`; существующего пользователя сначала проверить, не переопределять. Каталоги state/codex-home 0700, код и approved доступны на чтение, но недоступны сервису на запись. Если права расходятся — исправлять конкретные пути, не рекурсивно весь сервер.
3. Codex CLI устанавливается из официального источника, доступный бинарник кладётся в root-managed путь. Записать фактическую версию и полный путь. Не использовать пакет автора, его API-ключ или подписку. Если бинарник находится в закрытой домашней папке root, service его не увидит: выбрать доступное место, не ослаблять ProtectHome.
4. Для авторизации запустить официальный login от имени сервиса с `CODEX_HOME=/srv/ikigai/codex-home`. Человек завершает вход в своём браузере. В документированной headless-ветке — `codex login --device-auth`, если доступно аккаунту. Код подтверждения не пересылать в общий чат. Не открывать auth.json агенту и не копировать его в паспорт. Недоступная авторизация = остановка. Подписка не обещает безлимитную круглосуточную нагрузку; API требует отдельного выбора оплаты.
5. Проверить через help, что CLI поддерживает флаги в telegram_bridge.py. Прочитать список features, не делать тихий fallback к полным правам. Изолированный worker не должен иметь родительские AGENTS.md, установленные навыки, MCP, плагины и пользовательские правила. Отдельный сервисный аккаунт не использовать для обычной разработки. В CODEX_HOME не хранить bot.token.
6. Человек создаёт бота в BotFather и вводит токен в локальный защищённый редактор файла bot.token. Агент не выводит содержимое. Владелец ID фиксируется заранее с его подтверждением, затем заполняется bridge.env. Не сохранять входящий текст в установочные логи.
7. Создать пустой approved.json либо передать явно утверждённые MD-выжимки из export_approved.py. Проверить контрольные суммы переданных файлов доступным инструментом, без печати содержимого в общий чат.
8. Скопировать app и assets service. `User` и `Group` должны совпадать с выбранной непривилегированной учётной записью. Не включать службу до заполнения параметров и отдельного входа Codex. Пример действий агента после выбора ученика: `systemctl daemon-reload`, `systemctl enable --now ikigai-telegram.service`. Это реальные изменения сервера; не выполнять их при подготовке материалов.
9. Статус службы и последние сообщения journal показывать без секретов и текстов запросов. Публичные скриншоты не должны содержать IP, токен или auth-файлы. Код логирует только коды событий.
10. Отключение: остановить конкретную собственную службу, сохранить inbox и паспорт. Отзыв токена — в BotFather, отзыв авторизации Codex — официальным способом. При передаче сервера другому человеку учётные данные отзываются; файлы личной памяти не передаются автоматически.

## Различия компьютеров

| Клиент | Действие человека | Действие агента |
|---|---|---|
| Mac | Открыть свой проект, подтвердить официальный вход | Определить доступность SSH; не предполагать Homebrew |
| Windows | Открыть свой проект, при отсутствии OpenSSH включить компонент через настройки Windows | Использовать доступный OpenSSH и реальную оболочку; не предполагать Git Bash |
| Linux-сервер | Выбрать бюджет/провайдера, подтвердить доступы | Установка отдельной службы по согласованному плану |

Ни одна строка не означает, что сейчас существует соединение или служба. Факт запуска записывается только после действительного действия ученика.
