# Обмен V1: согласованный снимок и отдельный inbox

Компьютер остаётся местом редактирования основной памяти. Сервер отвечает по выбранной копии, а не зеркалу всей папки. Этот контракт умышленно не обещает двустороннюю синхронизацию каждые несколько минут.

## Компьютер → сервер

1. Ученик выбирает небольшой набор сведений. Агент готовит краткие отдельные MD-выжимки без токенов и лишних личных данных.
2. Агент запускает export_approved.py в режиме плана с явными `--file`. Скрипт не выбирает файлы сам и не гарантирует обнаружение любого секрета. Человек подтверждает состав до передачи.
3. `--apply` создаёт новую папку снимка вне второго мозга, до 20 файлов и 32000 байт. Существующий снимок не заменяется. Поддерживаются только portable plain MD; personal/private/secrets/sessions исключены.
4. На сервере подготовить новый каталог approved-<версия> отдельно от активного. Сверить список и контрольные суммы. Только затем, остановив собственную службу, переключить согласованный активный каталог и запустить её. Старый снимок оставить для отката. При неизвестных файлах в целевом каталоге остановиться, не удалять их.
5. Записать версию снимка и дату в паспорт. Автоматического удаления локальных/серверных файлов нет. Полный rsync всей памяти и --delete не использовать.

Пример технического действия агента: `python3 export_approved.py --source <папка-ученика> --dest <новый-снимок-вне-папки> --file memory/reference_bot_context.md`; затем тот же план с --apply после выбранного состава. Участнику команду вводить не надо.

## Сервер → компьютер

`/save` сохраняет заметки только в state/inbox сервера. По явному запросу «забери входящие сервера» агент скачивает их в отдельную staging-папку. Каждый файл содержит update_id; перед импортом проверить, нет ли уже этого ID в локальном memory/inbox. Есть отличающееся содержимое с тем же ID — сохранить обе версии в staging и показать конфликт. Нет — добавить заметку в memory/inbox, затем разобрать по задачам/выводам и добавить индекс. На сервере до подтверждённого импорта не удалять.

Не давай модели на сервере одновременно писать в локальные ACTIVE.md, профиль и проекты. Пока компьютер выключен, локальная память не меняется. Статус «сохранено на сервере» нельзя называть «уже синхронизировано».

Резервная копия — независимая версия для восстановления; снимок для бота с неполным контекстом её не заменяет. Модуль 7 закрывает отдельное резервирование основной памяти и входящих сервера.
