# Сервер и Telegram · черновик без прогона

## 🔧 АВТОУСТАНОВКА

Исполняй только явный запрос ученика выполнить этот модуль в ЕГО отдельной папке второго мозга. Чтение исходников, редактирование, сборка или обсуждение материалов не разрешают установку в систему автора. START.md содержит полный payload этого навыка. Сохрани его файлы в `.agents/skills/ikigai-server-telegram/` средствами записи Codex. Существующие файлы не заменяй; при отличиях покажи конкретный план обновления. Не устанавливай глобально. Проверяй рабочую папку по `AGENTS.md`, `SYSTEM.md`, контракту памяти и состоянию предыдущих модулей.

После локального сохранения создай `.ikigai/module06.json` с module=ikigai-server-telegram, version=0.1.0, status=draft_unrun, phase=prepared, checks=not_run; это ещё не действующий сервер. В общий SYSTEM.md добавь ссылку на `memory/integrations/server-telegram.md`, сохранив другие разделы. Если записи запрещены, сообщи о недоступности, не изображай установку.

## Результат и границы

Этот пакет создаёт конкретный минимальный серверный вход: личное текстовое сообщение → проверка владельца → ограниченная очередь → Codex CLI без инструментов, с согласованным контекстом → текстовый ответ. `/save текст` детерминированно сохраняет входящую заметку в отдельную серверную папку. Обычный вопрос не изменяет второй мозг. Голос, файлы, группы, почта, удалённые команды и полноценное исполнение задач команды в этой версии не поддерживаются. Не представляй режим вопрос-ответ как полностью автономного оркестратора.

Код составлен, но не запускался. По просьбе автора сборка модулей выполнена без прогонов. При установке ученику явно сообщи это; фактические проверки после его запуска описаны как действия, а не уже полученный успех.

## 1. Выбери контур

Объясни «сервер» как отдельный постоянно доступный компьютер, «SSH» как защищённый доступ к нему, «бот» как интерфейс сообщений. Узнай: нужен ли доступ при выключенном ноутбуке, какой контекст допустимо вынести, часовой пояс, кто владелец и бюджет сервера. Начни с минимального текстового сценария. Не выбирай тариф и не арендуй платный ресурс без выбора человека. Сервер должен принадлежать ученику; инфраструктура автора и имена его узлов не используются.

Прочитай [runbook](references/server-runbook.md), затем [контракт обмена](references/sync-contract.md). Покажи схему и список компонентов до изменений. Сервер Linux с systemd — поддерживаемый проектом вариант; Mac/Windows — клиент. Другую серверную ОС не выдавай как проверенную.

## 2. Подготовь доступ и авторизацию

Используй SSH доступными инструментами Codex; участнику не требуется набирать команды. Начальный ключ сервера сверь через доверенный канал хостера, не выключай host-key checking. Не проси пароль кабинета, root-пароль или токен в чате. Секреты вводит человек в приватном редакторе/официальном окне; агент проверяет существование и права, а не печатает значения. Существующие службы и firewall не перестраивай вслепую.

Создай отдельного непривилегированного пользователя сервиса, приложение и каталоги по runbook. Установку Codex выполняй по актуальной официальной инструкции и сверь `codex exec --help` установленной версии. Для выделенного CODEX_HOME выполните отдельную официальную авторизацию; вход в приложение на ноутбуке её не заменяет. При наличии device-code login человек подтверждает его в своём браузере. Не копируй весь домашний `.codex`, подключения и навыки автора/ученика на сервер. API-ключ не является обязательным: выбери доступный способ входа, объясни разницу подписки и отдельно оплачиваемого API. Отсутствие доступного способа входа — `blocked_auth`, а не повод обходить его.

## 3. Свяжи конкретного владельца

Человек создаёт собственного бота через официальный BotFather и лично сохраняет токен в `/etc/ikigai/bot.token` с правами 0600, владельцем сервиса. В конфиге хранится только путь к этому файлу. Подтверди числовой Telegram user ID владельца через доверенный способ: сообщение с его аккаунта собственному боту и приватный просмотр соответствующего `from.id`/`chat.id`, сверка человеком. Не назначай владельцем первого написавшего. Не используй username как основной идентификатор. Запиши подтверждённый ID в bridge.env. Сервер принимает только private chat, где оба ID совпадают с заранее заданным владельцем.

## 4. Подготовь контекст и приложение

Создай вручную проверенные краткие MD-выжимки, явно выбранные человеком. `scripts/export_approved.py` сначала показывает план; `--apply` создаёт новый отдельный снимок. Сверь состав и отсутствие секретов перед передачей. Не копируй весь `memory/`, AGENTS.md или историю чатов на сервер. Передай только утверждённый снимок, скрипт `telegram_bridge.py` и конфиг. Сохрани версии/пути в паспорте, но не секреты.

Модель получает текст выбранных файлов через stdin; исполняемые инструменты, плагины, общий конфиг и web search выключены. Флаги зависят от CLI: если версия их не поддерживает, остановись и согласуй совместимое обновление, не убирай ограничения молча. Прочитай [границы реализации](references/bridge-design.md).

## 5. Развёртывание по выбранному плану

Покажи конкретные пути, пользователя, service unit и расходы. Выполни необходимые установки/копирование только на подтверждённом сервере ученика. Шаблоны assets/ требуют заполнения путей и ID, их нельзя включать со значениями REPLACE. Служба работает не от root, с отдельным CODEX_HOME. Сначала выбранные одноразовые проверки доступа, затем включение службы. Существующий webhook/бот не выключать автоматически: выбор long polling и остановка старого процесса — отдельное понятное решение ученика.

## 6. Проверки после реального запуска ученика

Сценарии: владелец получает ответ; другой аккаунт и группа не получают доступ; `/save` создаёт серверную заметку; обычный вопрос ничего в памяти не меняет; превышение очереди/timeout даёт понятный статус; перезапуск не делает автоматический повтор уже начатого модельного запроса; токен не попадает в журнал. Эти проверки пока НЕ пройдены. Если ученик просит пока только подготовку файлов, остановись на `prepared`, ничего не подключай и не тестируй.

## 7. Сохрани паспорт

Заполни `memory/integrations/server-telegram.md` по assets/server-passport.md без секретов. Укажи способ авторизации, утверждённые категории данных, известные ограничения и фактическую фазу. Обнови SYSTEM.md, индекс и handoff. Включать расписание синхронизации и резервные копии будем отдельным действием в модуле 7; не обещай их по факту запуска бота.
