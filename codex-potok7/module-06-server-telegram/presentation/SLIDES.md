## Слайд 2. Сначала выбираем, зачем нужен сервер

ПОТРЕБНОСТЬ

Ноутбук выключен — Нужен доступ к выбранному контексту с телефона.

Сервер принадлежит тебе — Ты выбираешь бюджет, провайдера и доступы.

Данные выбраны — На сервер уходит утверждённая выжимка.

**Ведущему:** Не выбирать платный ресурс за человека. Сервер — отдельный компьютер, а не папка в приложении. Без доступа подготовка продолжается как схема, не как развёртывание.

## Слайд 3. Сообщение проходит через личный обработчик

СХЕМА V1

Это ограниченный вопрос-ответ, без удалённых действий.

Ты в Telegram — Подтверждённый владелец

Сервер — Очередь и Codex

Ответ — Текст по снимку

**Ведущему:** Раскрой очередь как обработку по одному. Никакой голосовой ввод, файлы, группы и выполнение инструментов в V1 не поддерживаются.

## Слайд 4. Владелец задаётся заранее, а не первым сообщением

ДОСТУП

Numeric user ID — Постоянный числовой ID аккаунта.

Private chat — Только личный разговор с ботом.

Совпадение ID — Сверяются отправитель и чат.

**Ведущему:** Создать собственного бота в официальном BotFather. Не назначать владельцем первого написавшего и не полагаться только на username. Номер подтвердить человеком приватно.

## Слайд 5. Токен не становится контекстом модели

СЕКРЕТЫ

В защищённом месте: bot.token с правами 0600; Отдельная авторизация Codex; Доступ только служебной учётной записи.

В паспорте системы: Пути и версии; Способ входа; Статус и следующий шаг.

**Ведущему:** Токен — секрет управления ботом. Не просить его в чате и не печатать из конфигурации. Отдельный сервисный пользователь и CODEX_HOME; модель получает минимальный env без Telegram token.

## Слайд 6. Вход на ноутбуке не авторизует сервер

ВХОД CODEX

Отдельный CLI — На сервере устанавливается собственный Codex.

Официальный вход — Человек подтверждает доступ в своём браузере.

Способ оплаты — Подписка и API — разные варианты.

**Ведущему:** Прочитаны официальные auth/non-interactive docs. Device-code flow зависит от доступа аккаунта. API не делать обязательным и не включать автоматически при ошибке подписки. При blocked_auth остановиться.

## Слайд 7. Выбираем сведения, а не копируем весь мозг

КОНТЕКСТ

До 20 plain MD-файлов и 32000 байт в текущем exporter.

Выжимка — Нужные подтверждённые факты

Согласование — Состав и отсутствие секретов

Снимок — Новая отдельная версия

**Ведущему:** Снимок — ограниченная копия для ответов, не резервная копия всей системы. Exporter имеет plan/apply. Не копировать весь memory, auth и AGENTS на сервер.

## Слайд 8. Вопрос и сохранение выполняются по-разному

ВОЗМОЖНОСТИ

Обычный текст: Модель отвечает по снимку; Инструменты выключены; Локальная память не меняется.

/save текст: Детерминированная запись; Входящие только сервера; Импорт на компьютер отдельно.

**Ведущему:** Не обещать сохранение из обычного ответа. /save — собственная команда кода, не разрешение модели менять файлы. При повторе update_id заметка не дублируется.

## Слайд 9. Первая версия имеет понятные ограничения

ГРАНИЦЫ

Только текст — Голос, файлы и группы отсутствуют.

Без инструментов — Нет писем, команд и внешних действий.

Без двустороннего sync — Компьютер и сервер не пишут одну память.

**Ведущему:** Это первый реализованный режим, не паритет старого brain-link. Расширения должны стать отдельными задачами. Не скрывать ограничения за словом «оркестратор».

## Слайд 10. Служба работает под отдельным пользователем

РАЗВЁРТЫВАНИЕ

SSH — Защищённый доступ с проверкой ключа сервера.

Systemd service — Процесс Linux с остановкой и перезапуском.

Раздельные каталоги — Код, снимок, очередь и авторизация.

**Ведущему:** Команды выполняет агент, человек выбирает доступы и подтверждает официальные окна. Не выключать чужую службу по похожему имени. Шаблоны требуют реальных путей; сейчас не включены.

## Слайд 11. Очередь и timeout делают поведение предсказуемым

ОГРАНИЧЕНИЯ НАГРУЗКИ

До двух вопросов в минуту — Не бесконечные автоматические повторы.

Очередь до восьми — Обработка по одному запросу.

До 180 секунд — Превышение времени даёт ошибку.

**Ведущему:** Это заданные параметры черновика, а не измеренные показатели производительности. Не заявлять протестированную надёжность. После аварии запрос автоматически не повторяется.

## Слайд 12. Входящие приезжают через отдельный импорт

ОБМЕН

До импорта «сохранено на сервере» не означает «есть на компьютере».

Серверный inbox — Заметки с update_id

Staging — Сверка дублей и конфликтов

Память компьютера — Разбор и индекс

**Ведущему:** Главная копия на компьютере. При конфликте сохранить обе версии, показать владельцу. Входящие не удалять до подтверждённого переноса. Полного rsync --delete нет.
