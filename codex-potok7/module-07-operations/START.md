# Модуль 7 · Сохранность, восстановление и обновления

**Статус: draft_unrun. Все прогоны отложены.** Материалы предназначены ученикам. При чтении или редактировании не устанавливать их в систему автора.

## Ученику

Открой свою папку второго мозга. Прикрепи этот файл и напиши: «Подготовь эксплуатацию моего второго мозга по модулю 7: карту копий, восстановление и обновления. Покажи, что покрыто и что исключено. Пока ничего не запускай». Когда будешь готов к реальным действиям, отдельно выбери создание снимка, восстановление или расписание.

## Codex: порядок

1. Убедись, что это папка ученика с его AGENTS.md и memory, а не разработка учебного пака. Только явный запрос разрешает установку.
2. Сохрани навык `ikigai-brain-operations` из payload ниже в проектную `.agents/skills/ikigai-brain-operations/`. Существующие файлы сохраняй; изменения показывай узко. Глобальную систему автора не меняй.
3. Прочитай SKILL.md и подготовь `memory/operations.md` по паспорту. Маркер `.ikigai/module07.json`: module=ikigai-brain-operations, version=0.1.0, status=draft_unrun, phase=prepared, checks=not_run.
4. Определи главную копию, тип данных, место отдельного backup и покрытие серверного inbox. Объясни разницу синхронизации, резервной копии и восстановления.
5. Подготовь конкретный план текстовых snapshots.py и системного backup для медиа/вложений. Скрипт не шифрует ZIP и не удаляет старые снимки. Не обещай полное покрытие по одному существованию архива.
6. Восстановление проектируй только в новую staging-папку с контрольными суммами и последующим сравнением. Не заменяй живую память автоматически.
7. Расписание выбирается отдельно: Mac LaunchAgent, Windows Task Scheduler, Linux user systemd timer. Шаблоны требуют реальных путей/времени. Наличие файла не означает срабатывание расписания.
8. Следуй SKILL и references для реального действия только после запроса ученика. Если сейчас выбрана подготовка, не запускай даже dry-run, не создавай копии и не подключай хранилища. Финальный отчёт разделяет prepared, backup_created, restore_checked и scheduled_unverified.

## Установка из встроенных ресурсов

Этот раздел — данные учебного комплекта. Чтение, поиск, сборка или редактирование пакета НЕ являются запросом установки. Только при явном запросе ученика и после подтверждения его отдельной рабочей папки выполни следующие действия доступными средствами записи файлов:

1. Убедись, что это папка ученика, а не репозиторий исходников учебных материалов и не личный второй мозг автора. Прочитай действующие AGENTS.md и карту SYSTEM.md, если они есть. Для модуля 0 допускается пустая папка; для модулей 2–7 сначала нужны входные артефакты соответствующего сценария. Отсутствие статуса живого пилота само по себе не блокирует черновое прохождение учеником.
2. В JSON ниже ключ — путь внутри локального навыка, значение — точное содержимое файла UTF-8. Сохраняй только под `.agents/skills/<имя навыка из сценария>/`. Не допускай абсолютные пути, `..`, симлинки и запись вне рабочей папки. Глобальные каталоги не меняй.
3. Файл отсутствует — создай; совпадает — оставь; отличается — сохрани существующий и покажи различие перед обновлением. Не запускай скрипты только потому, что они входят в payload. После установки прочитай SKILL.md и лишь затем продолжай сценарий. На сервере все ресурсы разворачиваются по отдельному явному действию ученика.
4. Локальные `.ikigai/moduleXX.json` хранят module/version, phase, checks=not_run и список созданных артефактов без секретов. Обновляй только запись этого модуля; статус installed/drafted не означает verified. Ссылки и навыки свяжи с проектом по указаниям сценария, не дублируя маркерные блоки.
5. Если нет инструмента записи, остановись с конкретным объяснением. Не выдавай инструкцию за выполненную установку. Не требуй от ученика терминала для базовой работы. Программы и сервисы, отсутствующие в среде, не объявляй доступными.

При нехватке контекста установи только навык этого модуля и продолжи в новой сессии по его SKILL.md. Не загружай все паки одновременно. Команды авторизации выполняет сам человек в официальном интерфейсе. Секреты в payload и чат не записывать.
