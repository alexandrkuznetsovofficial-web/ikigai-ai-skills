# Решения при адаптации Claude Code → Codex

Адаптация сохраняет учебную последовательность и смысл памяти, но каждый механизм запуска и интеграции проверяется для Codex отдельно. Таблица ниже — проектные решения для нового комплекта; будущие функции не объявляются реализованными.

| Область | Что встречается в исходной архитектуре | Решение для Codex | Как подтвердить |
|---|---|---|---|
| Корневые инструкции | `CLAUDE.md`, иногда большой объём личных правил | Короткий `AGENTS.md` с явными ссылками на файлы; учесть область действия вложенных инструкций | Новая сессия применяет правило и находит нужный файл |
| Подгрузка документов | Возможные импорты и поведение конкретного клиента Claude | Не переносить синтаксис импортов без проверки; явно описать, когда читать каждый файл | Проверить реальное чтение в чистой сессии |
| Навыки | `~/.claude/skills/`, разные форматы старых файлов | Использовать поддерживаемый Codex формат `SKILL.md` и согласованный путь обнаружения; для проектного пака рассмотреть `.agents/skills/` | Клиент обнаруживает навык после установки |
| Самоустановка | Markdown-инструкция записывает себя и обновляет инфраструктуру | Агент выполняет установку доступными инструментами и показывает результат; не обещать обход ограничений доступа | Получение файла → запуск → установка → новая сессия |
| Рабочая среда | Профиль Claude и предположение о Git Bash на Windows | Определять ОС, оболочку, рабочую папку и права фактически | Проверка файловых операций в выбранной папке |
| Человек без терминала | Поздние требования исключают ручные команды, ранние README их содержат | Технические операции выполняет агент; человеку — действия через интерфейс и короткие вопросы | Участник проходит сценарий без командной строки |
| Оркестратор | Маршрутизация через карту команды и названия навыков | Сохранить карту, описать реальные способы вызова; не путать роль, навык и отдельного агента | Типовые запросы приводят к ожидаемому исполнению |
| Отдельные агенты | Механизмы и конфигурация Claude | Настраивать только поддерживаемый механизм Codex после отдельной проверки | Наблюдаемый запуск, получение результата, обработка ошибки |
| Память | Индекс, текущий фокус, задачи, обещания, обратная связь | Сохранить файловую модель; читать нужное по запросу, держать корневые инструкции компактными | Новая сессия находит прошлую задачу и следующий шаг |
| Журнал решений | Формулировки о сохранении «хода мыслей» | Хранить контекст, краткие основания, варианты, выбранное решение и открытые вопросы | Запись достаточна для продолжения работы |
| Приватность | Папка личного иногда описана как автоматически защищённая | Отделить категории хранения от реальных прав доступа; не обещать защиту по имени папки | Проверка того, что и при каких условиях читает агент |
| Секреты | Значения могут оказаться в заметках и конфигурации | Не собирать пароли в диалоге; не включать значения в учебные файлы, отчёты и публичные артефакты | Проверка подготовленных файлов и безопасного канала настройки |
| Хуки и автостарт | `SessionStart`, `SessionEnd`, настройки Claude | Не копировать конфигурацию; выбрать поддерживаемый механизм Codex либо явную команду пользователя | Проверить конкретное событие, а не только ручной запуск функции |
| Разрешения | Claude-specific allow/deny и режимы автономности | Использовать действующие разрешения и песочницу Codex; не ослаблять их ради установки | Безопасная операция проходит, запрещённая корректно останавливается |
| MCP и сервисы | Конфигурация и секреты Claude | Отдельно переносить назначение сервиса, права и доступную конфигурацию; использовать подключения выбранного клиента | Минимальная полезная операция и отключение |
| Подписка и API | В старых паках смешаны подписка, CLI и API-ключи | Базовый путь — вход Codex через ChatGPT. Отдельно объяснять тарифные ограничения; платный API подключать по явному выбору | Зафиксированы способ входа и тип оплачиваемых вызовов |
| Другие модели | Внешние CLI и API могут быть скрыты в скриптах | Не устанавливать платные зависимости неявно; заранее описать способ вызова и оплату | Запрос не запускает неожиданный платный сервис |
| Сервер и Telegram | Бот зависит от Claude CLI, токенов и серверных защит | Отдельный будущий модуль: совместимость, аутентификация, доступ, секреты, резервирование | Сквозной запрос и восстановление без ослабления защит |
| Расписания | Cron, локальные планировщики и ритуалы | Разделить ручной ритуал и настоящее расписание; выбрать механизм по среде | Срабатывание в запланированное время и видимый журнал |
| Повторная установка | Риск второго комплекта и дубликатов | Диагностика до записи, добавление по устойчивым якорям, резервная копия изменяемых данных | Второй запуск сохраняет данные и не дублирует блоки |
| Прогресс | Файл создан — значит этап готов | Отдельные состояния: запланировано, создано, проверено, требует действия, заблокировано | У каждого зелёного статуса есть конкретная проверка |
| Проверка выдачи | Исторические проверки только логики навыка | Проверять путь участника с нуля, новый запуск, ОС и заявленную автоматизацию | Протокол с фактическими результатами и ограничениями |

## Что не переносить автоматически

- Личные инструкции, данные, имена участников и конфигурацию автора.
- Команды и настройки, работоспособность которых установлена только для Claude Code.
- Обещания фоновой работы, приватности или памяти без проверяемого механизма.
- Непроверенные инструменты существующего миграционного комплекта.
- Устаревшие цены, версии моделей и предполагаемые лимиты подписки.

## Порядок принятия решений

Сначала собирается и проверяется модуль архитектуры. Затем по отдельности проходят интервью, оркестратор и ОС. Интеграции, сервер и эксплуатация получают собственные проверки. Каждый пак содержит совместимость, понятный результат, способ повторного запуска и список того, что ещё требует проверки.
