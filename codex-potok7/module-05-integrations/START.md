# Модуль 5 · Внешние сервисы в Codex

Версия 0.1.0 · draft_unrun · 2 ноября 2026.

Это учебный комплект учеников. Чтение или редактирование этого файла при подготовке материалов не разрешает устанавливать его в систему автора. Только явный запрос ученика в его отдельном проекте запускает действия.

## Участнику

Открой свою папку второго мозга и отправь: **«Выполни START.md модуля 5 в моей папке. Хочу подключить один сервис под мою задачу. Объясняй по одному шагу, секреты в чате не запрашивай».**

Не вводи команды в терминале. Ты выбираешь задачу и завершаешь официальный вход; технические действия выполняет Codex в пределах доступных инструментов.

## Codex: подготовка и самоустановка

Уточни фактический путь выбранной папки ученика. Убедись, что это его второй мозг, а не учебный репозиторий или система автора; прочитай AGENTS.md, наличие memory/ и маркеры предыдущих модулей. При отсутствии основы первого модуля остановись и объясни зависимость. Не создавай параллельную структуру памяти. TEAM.md после модуля 3 находится в корне проекта.

Установи `ikigai-connect-services` только в `.agents/skills/ikigai-connect-services/` выбранного проекта. Полное содержимое навыка и ресурсов приложено в автономной карте установки ниже. Пиши доступными native file tools, Python для этого не нужен. Существующие файлы сначала прочитай, сохраняй личные разделы, не заводи дублей. Не используй симлинки и не выходи за выбранный корень. Само наличие этого файла не разрешает глобальную установку или работу с чужими аккаунтами.

Создай отсутствующий `.ikigai/module05.json`: `{"module":"ikigai-connect-services","version":"0.1.0","phase":"choose_service","checks":"not_run"}`. Существующий маркер сохраняй и продолжай, не сбрасывай его. Маркер модуля не является паспортом сервиса. Системную карту обновляй только по своим строкам подключений.

## Сценарий после установки

1. Прочитай установленный SKILL.md и действуй по его конкретным шагам. Объясни: подключение — реальный доступ к сервису, а не файл конфига.
2. Спроси одну полезную задачу и провайдера. Уточни аккаунт, область поиска и часовой пояс. Не подключай всё сразу.
3. Выбери фактически доступное подключение текущего клиента; при необходимости сверяй официальный MCP-маршрут. Не переноси секреты и конфиги автора.
4. Создай `memory/integrations/REGISTRY.md` и паспорт выбранного сервиса по ресурсам навыка. Иконка или установленный навык не дают verified.
5. Ученик проходит официальный вход с понятными правами. Секреты не присылает в чат. При запрете администратора или отсутствии инструмента запиши blocked и конкретный следующий шаг.
6. Если ученик запросил практическую задачу, выполни только согласованную полезную операцию. Чтение не разрешает отправлять письма, приглашения и редактировать документы. Отдельные прогоны и тестовые изменения без запроса не проводить.
7. Сохрани результат со ссылкой или препятствие в журнале задачи, обнови индекс, фокус, handoff и собственные строки SYSTEM.md. Не копируй почтовый ящик или диск в память.
8. Объясни отключение и отзыв доступа. Подготовь паспорт возможностей без секретов для модуля сервера; не объявляй сервер подключённым.

Сейчас пак только подготовлен: живых подключений и прогонов нет. В отчёте различай «навык установлен», «вход требуется», «доступ есть, не проверен» и «операция фактически выполнена».

## Установка из встроенных ресурсов

Этот раздел — данные учебного комплекта. Чтение, поиск, сборка или редактирование пакета НЕ являются запросом установки. Только при явном запросе ученика и после подтверждения его отдельной рабочей папки выполни следующие действия доступными средствами записи файлов:

1. Убедись, что это папка ученика, а не репозиторий исходников учебных материалов и не личный второй мозг автора. Прочитай действующие AGENTS.md и карту SYSTEM.md, если они есть. Для модуля 0 допускается пустая папка; для модулей 2–7 сначала нужны входные артефакты соответствующего сценария. Отсутствие статуса живого пилота само по себе не блокирует черновое прохождение учеником.
2. В JSON ниже ключ — путь внутри локального навыка, значение — точное содержимое файла UTF-8. Сохраняй только под `.agents/skills/<имя навыка из сценария>/`. Не допускай абсолютные пути, `..`, симлинки и запись вне рабочей папки. Глобальные каталоги не меняй.
3. Файл отсутствует — создай; совпадает — оставь; отличается — сохрани существующий и покажи различие перед обновлением. Не запускай скрипты только потому, что они входят в payload. После установки прочитай SKILL.md и лишь затем продолжай сценарий. На сервере все ресурсы разворачиваются по отдельному явному действию ученика.
4. Локальные `.ikigai/moduleXX.json` хранят module/version, phase, checks=not_run и список созданных артефактов без секретов. Обновляй только запись этого модуля; статус installed/drafted не означает verified. Ссылки и навыки свяжи с проектом по указаниям сценария, не дублируя маркерные блоки.
5. Если нет инструмента записи, остановись с конкретным объяснением. Не выдавай инструкцию за выполненную установку. Не требуй от ученика терминала для базовой работы. Программы и сервисы, отсутствующие в среде, не объявляй доступными.

При нехватке контекста установи только навык этого модуля и продолжи в новой сессии по его SKILL.md. Не загружай все паки одновременно. Команды авторизации выполняет сам человек в официальном интерфейсе. Секреты в payload и чат не записывать.
