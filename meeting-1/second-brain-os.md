# SECOND BRAIN OS v2.0
## Режим ежедневной работы второго мозга
### Второй мозг — Тиаго Форте (CODE, PARA); вычислительная рамка — Андрей Карпати (контекст = оперативная память модели); LLM Wiki — опция справочника знаний с меткой `para: resource`. Плюс опыт основателей AI-Потока Икигай.

> Что изменилось в v2.0. Установку с нуля этот скилл больше не делает: её ведёт `second-brain-architect`,
> чтобы у всех была одна структура. Фокус живёт только в `memory/ACTIVE.md`. Ассистента зовут так, как
> назвал его ты, — своего «Тима» скилл не создаёт. Участники со структурой прежней версии не ломаются:
> всё читается и по старым путям, а привести систему к одному виду помогает `memory-upgrade`.

## ПЕРВЫМ ДЕЛОМ — ОЦЕНКА СОСТОЯНИЯ

### А0. Профиль компьютера
Прочитай `~/.claude/ikigai_env.json`. Нет файла или он старше 30 дней — запусти пробник
`bash ~/.claude/skills/ikigai-preflight/scripts/probe.sh`; пробника нет — определи систему сам.
Поле `os_branch` (`mac` / `windows` / `linux`) определяет колонку команд. На Windows команды ты выполняешь
через Git Bash, а человеку не показываешь `chmod`, `bash`, `~`, `brew`, `launchctl`, `open -a`.

### А1. Что за система перед тобой
Смотри рабочую папку (поле `workspace` профиля, иначе текущую). Ничего не создавай, пока не определил режим.

| Что нашёл | Режим | Что делаешь |
|---|---|---|
| Нет ни `CLAUDE.md`, ни `memory/` | установки нет | **Не устанавливаешь сам.** Скажи: «Сначала поставим структуру — скажи „настрой мне второй мозг“, это скилл `second-brain-architect`. После установки я возьму ежедневную работу». Архитектора нет — он в репозитории `ikigai-ai-skills`, `meeting-1/second-brain-architect.md` |
| Есть `CLAUDE.md` и `memory/`, но нет `memory/commitments.md`, или фокус лежит в корневом `ACTIVE.md`, или в `CLAUDE.md` нет раздела «Правило двойной ошибки» | прежняя раскладка | Работаешь (режим OPERATION), один раз за сессию говоришь: «Твоя система собрана по прежней версии. Довести до нового стандарта, ничего не ломая, — „обнови мой второй мозг“ (скилл `memory-upgrade`)». Недостающие файлы **сам не создаёшь** — второго комплекта быть не должно |
| Всё из контракта на месте | kit 2.0 | режим OPERATION |

Сообщи человеку, что нашёл и в каком режиме работаешь.

### Где что лежит (контракт памяти kit 2.0)

| Путь | Что | Ты |
|---|---|---|
| `CLAUDE.md` | правила системы, 4 слоя, «Правило двойной ошибки» | читаешь; правишь только с согласия |
| `memory/ACTIVE.md` | фокус — **единственное место** | читаешь и пишешь |
| `ACTIVE.md` в корне | фокус прежней версии | **только запасной путь чтения**: читаешь, если нет `memory/ACTIVE.md`; не пишешь и второй не заводишь |
| `memory/MEMORY.md` | индекс, раздел «Оперативное» | одна строка на задачу. Если индекс прежней версии лежит в корне (`MEMORY.md`) — пишешь туда, второй не заводишь |
| `memory/tasks/` | журналы задач `task_ГГГГ-ММ-ДД_тема.md` | пишешь в конце каждой значимой сессии |
| `memory/commitments.md` | журнал обещаний | предлагаешь строку, пишешь после «да» |
| `memory/PROJECTS.md` | проекты: цель и срок | предлагаешь строку; срок пишет человек |
| `memory/feedback_*.md` | правила из повторных правок | пишешь по правилу двойной ошибки |
| `memory/insights/`, `memory/reasoning/` | инсайты, ход мыслей | пишешь по делу |
| `memory/personal/` | личное | **никогда не в облако**, в общие документы и наружу |
| `memory/archive/`, `memory/distill/` | завершённое, итоги недели | ведёт `weekly-distill`; ты не удаляешь ничего |

Если нет `memory/ACTIVE.md`, а есть только корневой `ACTIVE.md`: изменения фокуса не записывай в новый файл —
скажи человеку, что поменять в корневом, или предложи `memory-upgrade`. Два живых файла фокуса расходятся,
и брифинг начинает врать.

**Шапка новой заметки** — всегда, с первой записи:
```
---
name: <имя файла без .md>
description: <одна строка — что внутри>
para: project | area | resource | archive
para_source: rule
stage: seed
stage_source: rule
---
```
Поля `para:` и `stage:` ищи и с отступом — Claude при записи памяти может перенести их внутрь `metadata:`.
Есть поле — второе не ставь. Чужие значения `stage:` не трогай. Имена файлов — только латиница.

## ЛИЧНЫЙ АССИСТЕНТ-ОРКЕСТРАТОР (по желанию)

**Своего «Тима» с готовым именем этот скилл не создаёт.** У участника ассистент может уже быть — с именем,
которое он дал сам (`CLAUDE.md`, слой «Кто я»: «Ассистента зовут …»; скилл в `~/.claude/skills/` с
«оркестратор», «chief of staff» или «операционный директор» в описании). Есть — работай с ним, второго не делай.

Ассистента нет, а человек хочет:
1. Спроси: «Как назовёшь ассистента? Любое имя или просто „ассистент“». Имя в тексте — его; папка — латиницей.
2. Создай `~/.claude/skills/<имя-латиницей>/SKILL.md` по **единому шаблону `templates/main_agent.md`**
   (репозиторий `ikigai-ai-skills`, папка `templates/`; Windows: `C:\Users\<имя>\.claude\skills\<имя-латиницей>\SKILL.md`).
   Своего шаблона в этом скилле нет — так у всех участников один и тот же агент. Пака под рукой нет — попроси человека
   скачать `templates/main_agent.md`; по памяти не восстанавливай. Файл уже есть — не затирай, покажи разницу.
3. Агент по шаблону читает `memory/ACTIVE.md`, `memory/user_profile.md`, `memory/PROJECTS.md`, `memory/commitments.md`,
   держит правило двойной ошибки, а брифинг отдаёт скиллу `morning-brief`: триггеров «доброе утро» и «брифинг» в его
   описании нет. Старый агент с этими триггерами — предложи убрать их (после «да»), иначе на «доброе утро» ответят двое.
4. Карту команды и маршрутизацию собирает скилл `orchestrator` (`meeting-2-3/orchestrator.md`) — предложи
   запустить его, когда стоит больше двух специалистов. Карта живёт в одном месте —
   `~/.claude/skills/<папка оркестратора>/TEAM.md`.

## РЕЖИМ ENHANCE — «Чего не хватает»

Если система стоит, но нет каких-то компонентов — предложи, по одному, с оценкой времени:

1. **Нет `memory/commitments.md`, `memory/PROJECTS.md`, раздела «Правило двойной ошибки»** → `memory-upgrade` («обнови мой второй мозг») — он добавит, ничего не трогая
2. **Нет ассистента-оркестратора** → раздел «Личный ассистент-оркестратор» выше (имя — у человека)
3. **Нет Master Prompt `memory/user_profile.md`** → `founder-context-extractor` («начнём сборку контекста»)
4. **Хочется базу знаний по своей области** → «Справочник знаний (LLM Wiki)» ниже, по желанию
5. **В `memory/` больше 50 файлов и нужное теряется** → «Уровень 4 — RAG» в конце файла

Перед каждым предложением: «Хочешь добавить [X]? Займёт [N] минут.»

## АРХИТЕКТУРА ПАМЯТИ — ОБЯЗАТЕЛЬНЫЕ ПРАВИЛА

Ты ОБЯЗАН соблюдать эти правила при каждой сессии:

### Три слоя памяти

| Слой | Файлы | Сохраняется | Как |
|------|-------|-------------|-----|
| **Постоянная** | CLAUDE.md, memory/user_profile.md (Master Prompt + факты о человеке); старые memory/identity.md, memory/company.md — только запасной путь чтения | Автоматически при запуске Claude Code | Обновляй явно, с согласия |
| **Тактическая** | memory/ACTIVE.md, memory/commitments.md, memory/PROJECTS.md, memory/tasks/ | При явном сохранении и в конце сессии | "Сохрани в memory/..." |
| **Оперативная** | Текущий диалог | Теряется при закрытии | Сохраняй важное ПЕРЕД закрытием |

### Триггеры автосохранения
При появлении следующих фраз — НЕМЕДЛЕННО предложи сохранить:
- "всё", "закрываю", "переключаюсь", "стоп", "потом продолжим"
- "запомни это", "зафикси", "важно сохранить"
- Любое нетривиальное решение с обоснованием
- Любой инсайт который звучит как "aha moment"

Формат предложения: "Подожди — это важно сохранить. Записать в [конкретный файл]?"

### Правило конца сессии — журнал задачи пишется всегда
Сессия заканчивается (задача выполнена / пользователь говорит «всё», «закрываю», «стоп»), и в ней была
значимая работа — **журнал задачи пишется без отдельного вопроса**:
1. Создай `memory/tasks/task_ГГГГ-ММ-ДД_тема.md` (тема — латиницей) с шапкой `para: project` или `para: area`,
   `stage: seed`. Пять блоков: запрос · почему важно · что сделали · обратная связь пользователя · итог и что дальше.
2. Добавь одну строку в `memory/MEMORY.md`, раздел «Оперативное»: `[тема](tasks/task_….md) — итог · что дальше`.
3. Изменились приоритеты — обнови `memory/ACTIVE.md` (только его; корневой `ACTIVE.md` — только читать).
4. Прозвучало обещание со сроком — предложи строку в `memory/commitments.md` (см. ниже).
5. Скажи одной строкой, где лежит журнал. Пользователь сказал «не записывай» — не записывай.

Не пишется журнал для: уточняющих вопросов без действий, справок без изменений, уже записанного.
Было нетривиальное решение с альтернативами — дополнительно предложи reasoning log (формат ниже).

### Журнал обещаний — «сделаю к среде»
Пользователь пообещал что-то со сроком («сделаю к среде», «пришлю завтра», «обещал партнёру к пятнице»):
предложи строку в `memory/commitments.md` — **одним вопросом, без нажима**:
> «Записать в журнал обещаний: „прислать КП партнёру“, проверить в ср 15.01?»

После «да» — строка в конец таблицы: `| ГГГГ-ММ-ДД | обязательство | ГГГГ-ММ-ДД проверки | open | источник |`.
Порядок колонок не менять — брифинг читает их с конца строки. Дату проверки посчитай по календарю
(день недели проверь, не по памяти). Сделано — статус `done`, передумал — `dropped`; строки не удалять.
Файла нет — не создавай: предложи `memory-upgrade`.

### Правило двойной ошибки
Пользователь поправил тебя **второй раз в одном и том же** (тот же тип ошибки, та же правка «не так, а вот так»):
1. исправь результат;
2. найди `memory/feedback_*.md` на эту тему — **обнови его**; нет — создай `memory/feedback_<тема>.md`
   (шапка `para: area`, `stage: seed`). Новые файлы на одну тему не плоди;
3. строка в `memory/MEMORY.md` → «Оперативное» и строка в журнал `memory/feedback_double_error.md`
   (`| дата | что поправили дважды | правило | файл |`);
4. скажи одной фразой: «Записал правило: … — в feedback_….md».

Первая правка — просто исправь. Вторая одинаковая — правило. Правило касается чужих файлов, настроек
или скиллов — сначала спроси, потом меняй.

## 🧠 КОНТЕКСТНОЕ ОКНО — КАК НЕ ТЕРЯТЬ ВАЖНОЕ

### Что происходит с памятью Claude

Claude держит в голове весь разговор — но только до определённого объёма.
Когда разговор становится длинным — **Claude автоматически компактирует** (сжимает) старые части диалога.
При закрытии окна — весь оперативный контекст **исчезает безвозвратно**.

**Что это значит для тебя:**
- Если ты объяснял бизнес-контекст 2 часа — при следующем открытии его нет
- Если приняли важное решение — оно пропало если не записали в `memory/`
- Если нашли нестандартное решение — следующий Claude его не знает

**Рамка Карпати:** контекстное окно — это оперативная память модели. Что не записано в файл, исчезает
вместе с окном. Поэтому память — то, что в `memory/`; всё остальное — временное. И поэтому постоянную
загрузку (`CLAUDE.md` + индекс + фокус + Master Prompt) держат в бюджете: ~10 000 токенов, около 5 % окна.

### Три типа того что нужно сохранять

**1. Решение** — что выбрали и почему
→ `memory/tasks/task_YYYY-MM-DD_slug.md`
→ Пиши после каждой завершённой задачи

**2. Рассуждение (reasoning log)** — как пришли к решению, что пробовали, что не сработало
→ `memory/reasoning/reasoning_YYYY-MM-DD_slug.md`
→ Пиши когда задача незавершена или были нетривиальные повороты

**3. Инсайт** — что понял о бизнесе, о клиентах, о себе
→ `memory/insights/insight_YYYY-MM-DD_slug.md`
→ Пиши когда что-то щёлкнуло или пришло неожиданное понимание

### Автоматическая защита (ОБЯЗАТЕЛЬНОЕ правило скилла)

**Триггеры — СРАЗУ предлагать сохранить:**
- Принято важное решение с альтернативами
- Найдено нетривиальное решение ("а что если...")
- Пользователь говорит "всё", "закрываю", "стоп", "переключаюсь"
- Сессия длится > 30 минут и ещё нет ни одного сохранения

**Скрипт предложения:**
> "Подожди — хочу сохранить то что нашли, пока не закрылось окно.
> [Что именно предлагаю сохранить — одна строка]
> Сохранить в `memory/tasks/` или `memory/reasoning/`?"

**Если пользователь говорит "да"** — создаю файл без дополнительных вопросов.
**Если "нет"** — один раз предупреждаю: "Ок. Это потеряется при закрытии."

### Формат reasoning log (5 блоков)

```markdown
# Reasoning: [тема]
Дата: YYYY-MM-DD

## Задача
[что пытались решить]

## Что пробовали
[каждый вариант и его результат — включая неудачные]

## Ключевые умозаключения
[нетривиальные находки, ограничения, "aha moments"]

## Почему выбрали финальный вариант
[обоснование выбора]

## Открытые вопросы
[что осталось невыясненным — с чего продолжить]
```

### Настройка CLAUDE.md для автосохранения

Если в твоём `CLAUDE.md` такого правила ещё нет — предложи добавить (с согласия, в слой «Ссылки на регламенты»):
```markdown
## Правило сохранения контекста

После каждой значимой сессии — журнал в memory/tasks/ и строка в memory/MEMORY.md → «Оперативное».
При завершении сессии ("всё", "закрываю") — предлагать сохранить reasoning если было нетривиальное решение.
Принцип: потеря рассуждения хуже чем потеря результата. Результат виден в коде. Рассуждение — нет.
```

## СПРАВОЧНИК ЗНАНИЙ (LLM Wiki) — ОПЦИЯ

Не обязателен. Подключай, когда человек хочет базу знаний по своей области (рынок, методики, конкуренты),
а не только журнал своих дел. Идея — по мотивам «LLM Wiki»: модель один раз синтезирует сырьё в статьи
и дальше их обновляет. По PARA это **справочник**: у каждой статьи в шапке `para: resource`.

### Принцип (объяснять пользователю при подключении)
> «Вместо того чтобы каждый раз заново читать документы — строим справочник один раз
> и обновляем. Ты кладёшь сырьё в raw/, я синтезирую статьи в memory/wiki/.»

### Подключение (5–10 минут, только с согласия)
1. Создай `memory/wiki/INDEX.md` (шапка `para: resource`, `stage: seed`) и `raw/README.md` — что сюда класть.
2. `raw/` в `.gitignore` **не** пишется: по формуле бэкапа (`KIT_CONVENTIONS.md` §7) локальный git хранит всё,
   чтобы было чем откатиться. В облако сырьё не уйдёт — `raw/` в списке замка `pre-push` скилла `auto-commit-backup`.
   Замка нет — предложи поставить `auto-commit-backup`: сырьё бывает личным.
3. Первый источник — на выбор: экспорт истории ChatGPT (Settings → Data Controls → Export data →
   `conversations.json` → `raw/gpt-history/`) · 20–30 постов канала → `raw/tg-posts/` · презентации и PDF →
   `raw/docs/` · экспорт заметок → `raw/notes/`.
4. Прочитай источник и создай первую статью по протоколу ниже.

### Протокол обработки нового источника
При появлении нового файла в raw/:
1. Прочитай файл
2. Извлеки: ключевые факты, сущности (люди/компании/продукты), инсайты
3. Проверь memory/wiki/ на пересечения с существующими статьями
4. Создай новую статью ИЛИ обнови существующую
5. Добавь перекрёстные ссылки
6. Если новый факт противоречит старому — флагни: "⚠️ ПРОТИВОРЕЧИЕ: [старый факт] vs [новый факт]"
7. Обнови memory/wiki/INDEX.md

- Медицинские данные

## УРОВЕНЬ 4 — RAG: СЕМАНТИЧЕСКИЙ ПОИСК (для тех кто использует систему 30+ дней)

### Когда нужен RAG

Если в `memory/` больше 50 файлов — начинается проблема: Claude не может держать всё в контексте, MEMORY.md растёт, нужные файлы теряются. Это решает **RAG** (Retrieval-Augmented Generation).

**Принцип:** вместо «скормить Claude всё» — хранить всё в векторной базе и давать Claude только 5 файлов по смыслу запроса.

```
БЕЗ RAG:  «Вот все 200 файлов памяти» = 300K токенов
С RAG:    «Вот 5 файлов по теме вопроса» = 5K токенов
Экономия: ×60
```

### Установка (10 минут, один раз)

**Требования:** Python 3.9+, ~500MB диска, Mac и Linux — путь обкатан, Windows — 🧪 по документации

> **Если Python не установлен** (профиль компьютера, поле `python_cmd`, пустой):
> Mac: скачай с python.org — на свежих macOS Python уже есть, отдельно ставить обычно не нужно.
> Windows: Microsoft Store → «Python 3» (ставится без прав администратора и сразу попадает в PATH).
> Команда Python дальше: Mac и Linux — `python3`, Windows — `py -3`.
>
> 🔴 **Windows, честная оговорка.** Библиотека поиска собирается не под все свежие версии Python: если при
> установке вылезло `Microsoft Visual C++ 14.0 or greater is required` — это тупик на час, и он того не стоит.
> Сначала попробуй более обкатанную версию (`py -3.12 -m venv ...`). Не помогло — **уровень 4 пропускаем**,
> он необязательный: система работает и без него, а поиск делает сам Claude по папке `memory/`.
> Скажи это человеку прямо, не оставляй его воевать со сборкой.

```bash
# Mac / Linux:
python3 -m venv ~/brain-rag
~/brain-rag/bin/pip install chromadb

# Windows (Claude Code выполняет через Git Bash):
py -3 -m venv ~/brain-rag
~/brain-rag/Scripts/pip install chromadb
```

Содержимое `second-brain/rag_indexer.py`:

```python
#!/usr/bin/env python3
"""Индексирует все .md файлы в memory/ → ChromaDB. Запускать раз в сутки."""
import chromadb
from chromadb.utils import embedding_functions
import os, glob, json
from datetime import datetime

MEMORY_DIR = "./memory"      # путь к твоей папке памяти
CHROMA_DIR = "./rag_db"      # куда сохранять индекс

def run():
    client = chromadb.PersistentClient(path=CHROMA_DIR)
    ef = embedding_functions.DefaultEmbeddingFunction()

    try:
        client.delete_collection("brain")
    except Exception:
        pass
    col = client.create_collection("brain", embedding_function=ef)

    docs, ids, metas = [], [], []
    for path in glob.glob(f"{MEMORY_DIR}/**/*.md", recursive=True):
        text = open(path, encoding="utf-8", errors="ignore").read()
        if len(text.strip()) < 50:
            continue
        docs.append(text[:2000])   # первые 2К символов файла
        ids.append(path)
        metas.append({"path": path, "name": os.path.basename(path)})

    if docs:
        col.add(documents=docs, ids=ids, metadatas=metas)

    print(json.dumps({"indexed": len(docs), "ts": datetime.now().isoformat()}))

if __name__ == "__main__":
    run()
```

```python
#!/usr/bin/env python3
"""Семантический поиск по памяти. Usage: python3 rag_query.py 'вопрос'"""
import sys, json, chromadb
from chromadb.utils import embedding_functions

CHROMA_DIR = "./rag_db"

def search(query: str, n: int = 5) -> list:
    client = chromadb.PersistentClient(path=CHROMA_DIR)
    ef = embedding_functions.DefaultEmbeddingFunction()
    col = client.get_collection("brain", embedding_function=ef)
    res = col.query(query_texts=[query], n_results=min(n, col.count()),
                    include=["documents", "metadatas", "distances"])
    out = []
    for doc, meta, dist in zip(res["documents"][0], res["metadatas"][0], res["distances"][0]):
        out.append({"file": meta["path"], "score": round((1-dist/2)*100,1),
                    "preview": doc[:300]})
    return out

if __name__ == "__main__":
    query = sys.argv[1] if len(sys.argv) > 1 else ""
    print(json.dumps(search(query), ensure_ascii=False, indent=2))
```

### Запуск

```bash
# Mac / Linux:
~/brain-rag/bin/python3 rag_indexer.py   # первая индексация (~80MB модель, один раз)
~/brain-rag/bin/python3 rag_query.py "что я решал про ценообразование"  # тест

# Windows (Claude Code выполняет через Git Bash — путь с Scripts, не bin):
~/brain-rag/Scripts/python rag_indexer.py
~/brain-rag/Scripts/python rag_query.py "что я решал про ценообразование"
```

Признак, что уровень 4 собран: первая команда напечатала `{"indexed": N, ...}` с N больше нуля, вторая —
список файлов с процентами похожести. Пустой список при непустой `memory/` означает, что индексация не дошла.

Автоматическая индексация раз в сутки. Расписание должно переживать сон компьютера (`KIT_CONVENTIONS.md`, §7):
cron на ноутбуке пропускает ночной запуск, если крышка была закрыта, и не догоняет — поэтому на Mac launchd,
на Windows — Планировщик заданий с запуском при первой возможности.

**Путь к папке мозга — только из профиля.** Прочитай `~/.claude/ikigai_env.json` и возьми поле `workspace`
(на Windows — `workspace_win`). Не подставляй `second-brain` наугад: если папка называется иначе, задача будет
молча падать каждую ночь. `rag_indexer.py` должен лежать в корне этой папки.

**Mac — launchd `com.ikigai.rag-index`** (ты выполняешь сам; `WS` — значение `workspace` из профиля):

```bash
WS="<значение workspace из ~/.claude/ikigai_env.json>"
PL="$HOME/Library/LaunchAgents/com.ikigai.rag-index.plist"
[ -f "$WS/rag_indexer.py" ] || { echo "СТОП: нет rag_indexer.py в $WS"; exit 1; }
[ -f "$PL" ] && echo "УЖЕ СТОИТ — покажи человеку и спроси, перезаписать ли" || {
cat > "$PL" <<PLIST
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0"><dict>
  <key>Label</key><string>com.ikigai.rag-index</string>
  <key>ProgramArguments</key><array>
    <string>$HOME/brain-rag/bin/python3</string><string>rag_indexer.py</string>
  </array>
  <key>WorkingDirectory</key><string>$WS</string>
  <key>StartCalendarInterval</key><dict><key>Hour</key><integer>3</integer><key>Minute</key><integer>0</integer></dict>
  <key>StandardOutPath</key><string>$HOME/rag_index.log</string>
  <key>StandardErrorPath</key><string>$HOME/rag_index.log</string>
</dict></plist>
PLIST
plutil -lint "$PL" && launchctl bootstrap "gui/$(id -u)" "$PL"
}
launchctl kickstart -k "gui/$(id -u)/com.ikigai.rag-index"
```

Признак: через минуту `tail -3 ~/rag_index.log` показывает `{"indexed": N, ...}` с N больше нуля, а
`launchctl print "gui/$(id -u)/com.ikigai.rag-index" | grep -i state` отвечает без ошибки. Если раньше индексация
стояла в cron (`crontab -l | grep rag_indexer`), убери эту строку только после признака — через файл и со сверкой
числа строк (стало ровно на одну меньше), иначе индекс будет пересобираться дважды.

**Windows — задача Планировщика `Ikigai rag-index`.** `crontab` там нет — маковские команды не запускай,
иначе человек увидит поток ошибок. Команды вида `python3 -c "…"` в Git Bash тоже не используй: кавычки и
обратные слеши ломаются. Создай файл `%USERPROFILE%\.claude\rag_index_task.ps1` (в Git Bash —
`~/.claude/rag_index_task.ps1`) с текстом ниже — путь он сам берёт из профиля, ничего не вписывай руками:

```powershell
$cfg = Get-Content (Join-Path $env:USERPROFILE ".claude\ikigai_env.json") -Raw -Encoding UTF8 | ConvertFrom-Json
$ws = $cfg.workspace_win; if (-not $ws) { $ws = $cfg.workspace }
$py = Join-Path $env:USERPROFILE "brain-rag\Scripts\python.exe"
if (-not (Test-Path (Join-Path $ws "rag_indexer.py"))) { Write-Output "STOP: rag_indexer.py not found in $ws"; exit 1 }
if (-not (Test-Path $py)) { Write-Output "STOP: $py not found"; exit 1 }
$action   = New-ScheduledTaskAction -Execute $py -Argument "rag_indexer.py" -WorkingDirectory $ws
$trigger  = New-ScheduledTaskTrigger -Daily -At 3:00
$settings = New-ScheduledTaskSettingsSet -StartWhenAvailable -AllowStartIfOnBatteries -DontStopIfGoingOnBatteries
Register-ScheduledTask -TaskName "Ikigai rag-index" -Action $action -Trigger $trigger -Settings $settings -Force | Out-Null
Start-ScheduledTask -TaskName "Ikigai rag-index"
"StartWhenAvailable=" + (Get-ScheduledTask -TaskName "Ikigai rag-index").Settings.StartWhenAvailable
```

Запуск (ты выполняешь через Git Bash, человеку не показываешь):

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File "$HOME/.claude/rag_index_task.ps1"
```

Признак: в выводе `StartWhenAvailable=True`, а через минуту в папке мозга появилась (или обновилась) папка
`rag_db`. Была старая задача `IkigaiRagIndex` (прошлая версия скилла) — после признака удали её:
`powershell -NoProfile -Command 'Unregister-ScheduledTask -TaskName "IkigaiRagIndex" -Confirm:$false'`.

**Сервер Linux** (не спит) — допустим cron, строка `0 3 * * * cd "<workspace>" && $HOME/brain-rag/bin/python3 rag_indexer.py >> $HOME/rag_index.log 2>&1`;
добавляй через файл и со сверкой числа строк, повторно не добавляй.

### Как использовать с Claude Code

В CLAUDE.md добавить:

```markdown
## RAG — семантический поиск памяти

Перед поиском информации в memory/ — сначала запускай:
Mac/Linux: ~/brain-rag/bin/python3 rag_query.py "<вопрос>"
Windows:   ~/brain-rag/Scripts/python rag_query.py "<вопрос>"

Это вернёт топ-5 файлов по теме. Читай только их, а не всю memory/.
```

### Что это даёт практически

| Без RAG | С RAG |
|---------|-------|
| Claude читает все файлы памяти | Claude читает 5 нужных файлов |
| Контекст: 100–500K токенов | Контекст: 5–25K токенов |
| Теряет нужное при переполнении | Находит семантически похожее |
| При 200 файлах — начинает путаться | При 2000 файлах — работает так же |

**Правило:** начинай настраивать RAG когда MEMORY.md превысил 100 строк или memory/ содержит более 50 файлов.
