# Провайдеры: куда нажимать и где спотыкаются

Настройки сверены 11.09.2026 по официальным справкам сервисов. Интерфейсы меняются — названия
разделов живут дольше кнопок, поэтому ниже путь по разделам, а не по картинкам.

🔎 **Что проверено живьём, а что нет.** Машинно, на реальном ящике и календаре, прогнан только
**Яндекс** (чтение, поиск, создание и удаление события, отправка письма). Gmail, Mail.ru, iCloud,
Google Calendar и Notion расписаны **по официальным справкам, живьём никем не ставились**.
Если ты первый — напиши, что разошлось, и раздел поправят по факту.

## Сводка

Столбец «Сложность»: 1 — пара кликов в настройках ящика, 3 — вход через браузер и консоль
разработчика, 5 — отдельный вечер с порталом регистрации приложений.

| Сервис | Почта | Календарь | Сложность | Главный камень |
|---|---|---|---|---|
| Яндекс | `imap.yandex.ru:993` / `smtp.yandex.ru:465` | CalDAV `caldav.yandex.ru` | 1–2 | два разных пароля; пароль календаря начинает работать через 2–3 часа |
| Gmail | `imap.gmail.com:993` / `smtp.gmail.com:465` | только OAuth, не CalDAV | 1 / 3 | пароль приложения требует двухэтапной аутентификации |
| Mail.ru | `imap.mail.ru:993` / `smtp.mail.ru:465` | CalDAV `calendar.mail.ru` | 1–2 | отдельно включить доступ по IMAP |
| iCloud | `imap.mail.me.com:993` / `smtp.mail.me.com:587` | CalDAV `caldav.icloud.com` | 2–3 | логин для почты и для отправки разный |
| Outlook, Microsoft 365 | вход по паролю отключён | — | 5 | **в пак не входит**, нужен OAuth через Microsoft Graph |

Скрипты знают эти адреса сами — в файле доступов достаточно выбрать `MAIL_PROVIDER`.
Руками адреса вписывают только для `custom`.

## Яндекс

**Пароль приложения:** Яндекс ID (`id.yandex.ru`) → **Безопасность** → «Доступ к вашим данным» →
**Пароли приложений** → «Создать пароль приложения» → выбрать тип → придумать название → Далее.

Нужны **два** пароля с разными типами:
- тип **«Почта»** → в строку `MAIL_PASSWORD`;
- тип **«Календарь»** (в списке типов он рядом с CalDAV) → в строку `CALDAV_PASSWORD`.

**Включить IMAP:** Почта → Настройки → **Почтовые программы** → отметить доступ по IMAP.

Камни:
- пароль показывается **один раз**, потом его не посмотреть — только создать новый;
- Яндекс печатает пароль группами через пробел, **пробелы при вставке убрать**;
- **пароль календаря начинает действовать через 2–3 часа.** Ошибка 401 сразу после создания — норма;
- логин — **полный адрес** с `@`, не имя пользователя;
- у Яндекс 360 для личного аккаунта нет открытого API календаря — работает только CalDAV;
- отдельный пароль на каждое устройство и сервис: так отзыв одного не роняет остальные.

## Gmail

**Пароль приложения:** аккаунт Google → Безопасность → включить **двухэтапную аутентификацию** →
после этого в том же разделе появится **Пароли приложений**. Созданный пароль → `MAIL_PASSWORD`.

Камни:
- без двухэтапной аутентификации пункта просто нет;
- на корпоративных аккаунтах и в «Усиленной защите» пароли приложений недоступны — там только OAuth;
- Google называет пароли приложений «не рекомендуемыми», но для почты они работают:
  отключён был вход по **основному** паролю (март 2025), а не пароли приложений;
- **для календаря Google пароль приложения не подойдёт** — CalDAV у них только по OAuth,
  на обычный пароль отвечает 401. См. раздел ниже.

## Google Calendar (через OAuth)

1. `console.cloud.google.com` → создать проект → включить **Google Calendar API**.
2. APIs & Services → Credentials → Create credentials → **OAuth client ID** → тип **Desktop app** → скачать JSON.
3. **OAuth consent screen → Publish app.** Пока статус Testing, доступ протухает **каждые 7 дней**.
4. Файл положить в `~/.config/mail-calendar-kit/gcal_credentials.json`.
5. `gcal_auth.py init` — откроется браузер; после согласия появится `gcal_token.json`.
6. На сервер копируется **только токен** (`gcal_auth.py where` покажет путь), права 600.

Вход с браузером делается один раз и только на компьютере. На сервере браузера нет.

## Mail.ru

**Пароль:** `id.mail.ru` → **Безопасность** → **Пароли для внешних приложений** → создать.
Альтернативный путь: Настройки → Все настройки → Безопасность → Способы входа.

**Включить доступ:** Настройки → Все настройки → Безопасность → **Внешние сервисы** →
включить «Доступ к почте по IMAP, POP и SMTP».

Камни:
- без включённого доступа вход даёт ошибку даже с верным паролем;
- Mail.ru формально пускает и по обычному паролю, если нет двухфакторной защиты. Так не делаем:
  для бота, работающего круглосуточно, нужен отзываемый пароль приложения.

## iCloud

**Пароль:** `account.apple.com` → **Вход и безопасность** → **Пароли для приложений**
(доступно только при включённой двухфакторной аутентификации).

Камни:
- **логины разные:** для чтения (IMAP) — имя **без** домена, для отправки (SMTP) — полный адрес.
  Скрипт делает это сам, если `MAIL_PROVIDER=icloud`;
- отправка только через порт 587 со STARTTLS, 465 не работает;
- POP не поддерживается вообще;
- у календаря iCloud адрес после входа уезжает на персональный хост вида `pNN-caldav.icloud.com`.
  Скрипт находит его сам — **чужой адрес из интернета не подставлять**, он не подойдёт.

## Корпоративная почта на своём домене

Чаще всего за ней стоит Яндекс 360 или Google Workspace — тогда работают их же настройки.
Если администратор запретил внешние приложения, доступ не получить никакими паролями: это
решается только через него. Спросить стоит так: «нужен доступ по IMAP и пароль приложения
для личного почтового клиента».

## Outlook и Microsoft 365 — почему не в паке

Вход сторонних программ по паролю Microsoft отключила: у рабочих аккаунтов раньше,
у личных `outlook.com` — с 16 сентября 2024 года. Остался только OAuth через Microsoft Graph:
регистрация приложения, права, вход по коду устройства. Это 4–5 экранов портала до первого письма
и отдельный разговор. Календарь и почту в этом паке подключаем у другого сервиса.

## Частые ошибки и что они значат

| Что видно | Что случилось | Что делать |
|---|---|---|
| `код 2`, «IMAP не пустил» | пароль не тот, или IMAP выключен в ящике | пересоздать пароль приложения, включить IMAP |
| `код 2` на календаре Яндекса | пароль ещё не активировался | подождать 2–3 часа |
| `код 2` на iCloud | использован обычный пароль | создать app-specific password |
| «найдено писем: 0», хотя письмо есть | письмо в другой папке | повторить с `--all-folders` |
| SMTP не отвечает, IMAP работает | сеть или провайдер интернета режет исходящую почту | чтение работает; отправку проверить с другой сети или с сервера |
| Google: токен умер через неделю | приложение осталось в статусе Testing | OAuth consent screen → Publish app, повторить `init` |

## Календарь: три уровня доступа

Не спрашивай «какой у тебя календарь» — спрашивай «где ты его смотришь», а дальше разбирайся сам.
Дерево на двадцать секунд и что делать с каждым исходом — `calendar_where_it_lives.md`.

| Уровень | Что даёт | Сколько занять | Кому |
|---|---|---|---|
| **CalDAV с паролем приложения** (`icloud`, `yandex`, `mailru`, `custom`) | читать и ставить встречи | 5 минут | всем, у кого сервис это умеет — а умеют почти все |
| **Ссылка .ics** (`ics_link`) | только читать: день, неделя, свободные окна, поиск | 1 минута | Google без возни с консолью; корпоративные календари; всё редкое |
| **Полный доступ Google** (`google`) | читать и ставить встречи напрямую | 20 минут, 5 экранов консоли | тем, кому мало приглашений и нужна прямая запись |

**Ставить встречи при доступе только на чтение** — через письмо-приглашение:
`cal_cli.py create … --via-email --confirm`. Владелец получает письмо, жмёт «Да», встреча встаёт
в календарь. Работает с Apple, Google, Яндексом, Outlook и корпоративными системами одинаково.

### iCloud — календарь айфона
Это самый частый случай у владельцев айфона и самый удобный: **связывать с Google ничего не нужно**.
Нужен пароль для приложения: `account.apple.com` → «Вход и безопасность» → «Пароли для приложений».
Двухфакторная защита должна быть включена (у большинства включена по умолчанию).
В файл доступов: `CAL_PROVIDER=icloud`, `CALDAV_USER` — адрес Apple ID целиком, `CALDAV_PASSWORD` — этот пароль.

⚠️ Если человек говорит «календарь у меня в айфоне», это ещё не iCloud. Бывает «На iPhone» —
локальный календарь, который не виден снаружи вообще. Проверяется за двадцать секунд, см. дерево.

### Windows
Пак работает одинаково на обеих системах, отличаются только команды: установка через
`setup_venv.ps1`, Python пака лежит в `.venvs\mck\Scripts\python.exe`, права на файл не ставятся.
Нужную колонку команд печатает `kit_check.py system` в полях `setup_script` и `python_cmd`.
