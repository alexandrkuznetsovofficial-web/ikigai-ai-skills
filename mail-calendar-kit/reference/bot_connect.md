# Подключение к личному боту

Бот — это тот же второй мозг, до которого можно дотянуться из телефона. Пак даёт ему инструменты
почты и календаря. Какая ветка нужна, показывает команда:

```
~/.venvs/mck/bin/python ~/.claude/skills/mail-calendar-kit/scripts/kit_check.py bot-detect
```

| Ответ | Что это | Что делаем |
|---|---|---|
| `stack: "B"` | бот-мост поверх Claude Code | ничего не программируем, копируем файлы на сервер |
| `stack: "A"` | бот на библиотеке python-telegram-bot и ключе API | патчим одним скриптом, с бэкапом |
| `stack: "none"` | личного бота ещё нет | пропускаем, возвращаемся после урока про бота |

---

## Ветка B: бот-мост на Claude Code

Такой бот сам умеет запускать команды, поэтому отдельные инструменты ему не нужны — достаточно,
чтобы на сервере лежали скрипты и файл доступов.

1. Создать папки на сервере **до** копирования, иначе `scp` упадёт:
   `ssh -p <ssh-порт> <пользователь>@<адрес> 'mkdir -p ~/.claude/skills ~/.config/mail-calendar-kit && chmod 700 ~/.config/mail-calendar-kit'`
2. Скопировать скилл целиком:
   `scp -P <ssh-порт> -r ~/.claude/skills/mail-calendar-kit <пользователь>@<адрес>:~/.claude/skills/`
3. Скопировать файл доступов и закрыть права:
   `scp -P <ssh-порт> ~/.config/mail-calendar-kit/.env <пользователь>@<адрес>:~/.config/mail-calendar-kit/.env`
   затем по ssh: `chmod 700 ~/.config/mail-calendar-kit && chmod 600 ~/.config/mail-calendar-kit/.env`
4. Поставить окружение на сервере:
   `ssh -p <ssh-порт> <пользователь>@<адрес> bash ~/.claude/skills/mail-calendar-kit/scripts/setup_venv.sh`
5. Проверить:
   `ssh -p <ssh-порт> <пользователь>@<адрес> ~/.venvs/mck/bin/python ~/.claude/skills/mail-calendar-kit/scripts/cal_cli.py today`

**Важно для такого бота:** он выполняет по одной команде за раз. Не склеивай команды через `&&`
и `;`, пиши полные пути — иначе защита моста отклонит вызов.

**Проверка:** сообщение боту «что у меня сегодня в календаре» → в ответе реальные события.

## Ветка A: бот на python-telegram-bot и ключе API

Такой бот не умеет ничего, кроме разговора: у него нет инструментов. Патч добавляет их и цикл,
в котором модель может эти инструменты вызвать.

### Порядок

1. **Показать, что изменится** (ничего не трогает):
   ```
   ~/.venvs/mck/bin/python ~/.claude/skills/mail-calendar-kit/scripts/bot_tools_patch.py \
       --bot-file ~/my-second-brain/bot/main.py --dry-run
   ```
   Покажи человеку поле `diff` и дождись «да».
2. **Применить:**
   ```
   ~/.venvs/mck/bin/python ~/.claude/skills/mail-calendar-kit/scripts/bot_tools_patch.py \
       --bot-file ~/my-second-brain/bot/main.py --apply --bot-env ~/my-second-brain/.env
   ```
   Скрипт сам: делает бэкап `main.py.bak.<дата_время>`, кладёт рядом `kit_tools.py`, заменяет
   функцию ответа, проверяет, что файл компилируется, дописывает три строки в `.env` бота.
   Если после правки файл не компилируется — **сам возвращает бэкап** и ничего не меняет.
3. **Перезапустить бота.** На сервере: `sudo systemctl restart <имя-сервиса>`, затем
   `systemctl is-active <имя-сервиса>` и `journalctl -u <имя-сервиса> -n 20`.
   Имя сервиса подскажет `bot-detect` в поле `services`.
4. **Откат**, если что-то пошло не так:
   ```
   ... bot_tools_patch.py --bot-file <путь> --rollback
   ```

### Когда патч откажется работать

Скрипт не подставляет код вслепую. Он остановится и скажет об этом, если:
- в файле нет функции `ask_claude` — бот переписан, это уже не учебный шаблон;
- функция уже изменена (нет ожидаемой последней строки);
- файл бота не компилировался **ещё до** патча — сначала чинится бот;
- инструменты уже подключены — повторный патч не нужен.

В этих случаях подключай инструменты руками: в коде бота импортируй `kit_tools`, передай
`tools=KIT_TOOLS` в вызов модели и обрабатывай `stop_reason == "tool_use"` через `run_kit_tool`.

### Если бот живёт на сервере

Скопировать туда скилл, файл доступов и окружение (шаги 1–3 из ветки B), а патч применять
**на сервере**, к тому файлу бота, который реально запускается сервисом. Частая ошибка — пропатчить
копию на компьютере и удивляться, что в боте ничего не изменилось.

## Что бот получает

| Инструмент | Что делает |
|---|---|
| `mail_unread`, `mail_search`, `mail_read` | непрочитанное, поиск, чтение письма |
| `mail_send` | письмо: сначала превью, отправка после «да» |
| `cal_today`, `cal_list`, `cal_freeslots`, `cal_find` | день, неделя, свободные окна, поиск события |
| `cal_create` | новая встреча: сначала превью, создание после «да» |
| `cal_move` | перенос встречи на другое время: превью, перенос после «да» |
| `cal_delete` | отмена встречи: в превью видно название и время, удаление после «да» |

Два правила зашиты в сам инструмент, а не в вежливость модели:

1. **Двухфазность.** Первый вызов возвращает превью и ничего не делает. Пока человек не ответил
   «да», письмо не уходит и встреча не создаётся. Ответ «нет» отменяет.
2. **Предохранитель.** Пока в файле доступов `MCK_SEND_ALLOWED=0`, отправка запрещена на уровне
   скрипта. Даже прямая команда ничего не отправит.

Поэтому фразы «письмо отправлено» без подтверждения в этом контуре не бывает: бот физически
не может отправить, не получив «да».

## Windows

`ssh` и `scp` встроены в Windows 10 и 11, команды те же самые. Отличаются только пути:
папка скилла `%USERPROFILE%\.claude\skills\mail-calendar-kit`, Python пака
`%USERPROFILE%\.venvs\mck\Scripts\python.exe`. На сервере, куда копируем, пути всегда
линуксовые — там ничего не меняется.

Если `ssh` в Windows не находится, человек ставит его одним включением компонента:
Параметры → Система → Дополнительные компоненты → «Клиент OpenSSH». Не заставляй его
ставить сторонние программы вроде PuTTY: встроенного клиента достаточно.

## Что бот знает про время

К правилам на каждый запрос подставляется сегодняшняя дата, день недели и часовой пояс владельца.
Без этого «во вторник» и «через неделю» превращаются в угадывание, а год бот начинает спрашивать
у человека. Строку собирает `kit_now_line()`, часовой пояс берётся из файла доступов.

## Как выглядит перенос и отмена со стороны владельца

> — перенеси встречу с Ириной на четверг в три
> — «Перенести „Созвон с Ириной“ со вторника 14:00 на четверг 15:00?»
> — да
> — «Перенесено. Накладок нет.»

Под капотом: бот ищет встречу по названию, берёт её номер, показывает превью и переносит только
после ответа. Перенос устроен как создание копии на новом времени и удаление старой — именно
в таком порядке: если второй шаг сорвётся, останется видимый дубль, а не потерянная встреча.
Повторяющиеся встречи пак переносить отказывается: это меняет всю серию, такое делается руками.
