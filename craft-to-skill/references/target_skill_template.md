# Шаблон целевого скилла

Структура папки, которую `craft-to-skill` создаёт под конкретную работу. Пример — `dossier-maker`.

```
~/.claude/skills/dossier-maker/
├── SKILL.md                       # пошаговая инструкция (до 500 строк)
├── references/
│   ├── golden/                    # эталоны и пары «до → после»
│   │   ├── 01_etalon.pdf
│   │   ├── 01_source/             # исходники эталона
│   │   └── before_after.md
│   ├── facts_sheet_template.md    # лист фактов
│   ├── rules.md                   # правила: правило · почему · пример
│   ├── frozen.md                  # утверждённое, не трогаем
│   ├── stats.md                   # принято сразу / поправлено / переписано
│   └── layout/                    # утверждённый шаблон вёрстки (html/css, docx или шаблон редактора)
└── scripts/
    └── check_document.py          # машинная проверка перед показом

~/.claude/agents/dossier-checker.md # проверяющий с чистым контекстом
```

## Каркас SKILL.md целевого скилла

```markdown
---
name: dossier-maker
description: Собирает досье для клиента по моему протоколу: лист фактов → текст → вёрстка по утверждённому шаблону → проверка → показ. Используй, когда звучит «сделай досье», «досье для клиента», «собери досье по [имя/объект]», «новая версия досье».
metadata:
  version: "1.0"
---

# Досье по моему протоколу

Перед началом прочитай `references/rules.md` и `references/frozen.md`.

## Шаг 1. Лист фактов
Заполни `references/facts_sheet_template.md` по исходникам. Всё, чего нет в исходниках, отметь «[уточнить]». Покажи лист и жди «да».

## Шаг 2. Текст
[шаги из реверс-инжиниринга: разделы по порядку, объём, голос — со ссылками на эталоны в golden/]

## Шаг 3. Вёрстка
Только в шаблоне `references/layout/`. Шаблон не меняй. [правила фото, шрифтов, колонтитула]

## Шаг 4. Проверка перед показом
1. `python3 scripts/check_document.py <файл>` — должен пройти без ошибок.
2. Agent `dossier-checker` — должен дать ОК.
3. Имя файла с номером версии: `dossier_<объект>_v03.pdf`.
4. К результату — «что изменилось» и «что проверено».

## Шаг 5. После правок
Каждую правку запиши в `references/rules.md` по формату из craft-to-skill. Повтор ошибки → строка в `check_document.py`.
```

## frozen.md — формат

```markdown
# Утверждено — не трогать без прямой просьбы

| Что | Где | Утверждено | Кем |
|---|---|---|---|
| Колонтитул | все страницы | дд.мм | владелец |
| Текст раздела «О регионе» | стр. 4–5 | дд.мм | владелец |
```

## facts_sheet_template.md — формат

```markdown
# Лист фактов — [объект / клиент]

| Факт | Значение | Источник | Подтверждено |
|---|---|---|---|
| Площадь | 120 м² | выписка, стр. 2 | ✅ |
| Год постройки | [уточнить] | — | ⏳ |
```
В текст попадают только строки с ✅.

## scripts/check_document.py — что проверять
Попроси агента написать скрипт под формат результата (для PDF подойдут `pypdf` или `pdfplumber`). Типовые проверки:
- число страниц в ожидаемом диапазоне;
- все шрифты из разрешённого списка, нет подменённых;
- минимальный кегль не меньше заданного, исключения — колонтитул и карта;
- текст не выходит за поля страницы;
- все фразы из `frozen.md` на месте, ни одно утверждённое слово не пропало;
- нет «[уточнить]» в финальной версии.
Скрипт выводит список нарушений и завершается с ошибкой, если они есть.
