# Протокол сбоя brain-link (kit 2.3)

Таблица для Claude участника. Читается после **каждого** шага `brain_link.py` и каждого `brain_sync.py`.

**Алгоритм (обязателен):**
1. Прочитай JSON шага: `exit_code`, `human`, `next_step`, `warnings`, `checks`.
2. Код 0 и нет `warnings` → дальше по `next_step`.
3. Иначе найди строку ниже: сначала по точному признаку в `human` / `warnings` / журнале (колонка «признак»),
   потом по коду. Совпало несколько — бери первую сверху.
4. Колонка «авто» — **не больше одной** автоматической попытки на строку за сеанс. Прочерк — авто нет.
5. Не помогло, строки нет или в колонке «стоп» стоит «сразу» → стоп: `brain_link.py report`, путь к файлу
   отдай человеку со словами из колонки «сказать» и предложи переслать файл куратору в чат потока.
6. Никогда: не ставь `ANTHROPIC_API_KEY`, не отключай проверку ключа сервера, не правь сервер руками
   в обход скрипта, не проси токены и пароли в чат, не проси пароль от личного кабинета хостера.
7. «Одна попытка» — про повтор **того же шага**. Другие допустимые пути к той же цели (починить окружение по этой
   таблице, другой источник кита, `command`, независимые этапы гайда, пока ждём) CTO пробует до `report` — см. его
   раздел «Установка и апгрейд связки». VNC-консоль хостера — только аварийный вход после lockdown (строки E3, K1).

Формат строк постоянный (`| id | признак | причина | авто | сказать | стоп |`) — таблицу читают и люди, и Claude.

## Коды выхода

`brain_link.py`: 0 ок · 1 ошибка · 2 нужно действие человека · 3 стоп-точка · 4 конфигурация.
`brain_sync.py`: 0 ок · 1 конфигурация · 2 нужно действие (доступ, ключ) · 3 стоп-точка (массовое удаление,
пауза, отчёт без `--yes`) · 4 сеть / сервер. `brain_link.py` переводит коды синка в свои (1→4, 4→1).

## Что всегда кладём в отчёт куратору

`brain_link.py report` пишет `~/brain-link-report-ГГГГ-ММ-ДД_ЧЧММ.txt`: версии, ОС, возможности компьютера и сервера,
`detect`, последние 200 строк журнала синка и бота, `sync_status`, `selfcheck.json`, `safe_mode`, ufw и fail2ban.
Токены, пароли, IP (кроме 127.* и 169.254.*), значения приманок и путь домашней папки замаскированы,
`USER_ID` — частично. Отчёт можно пересылать в чат потока как есть.

## Как `keys` передаёт пароль root (SSH_ASKPASS)

Пароль живёт только в файле доступа (`~/.config/brain/server_access`, 0600) — и только до первого успешного `keys`:
положив ключ, `keys` сам убирает строку `PASSWORD` (копии `.bak` с паролем не остаётся).

На время одного запуска ssh `keys` создаёт во временной папке системы папку `brain-askpass-*` (0700), одноразовый
случайный нонс и помощник: Mac/Linux — `askpass.sh`, Windows — `askpass.cmd` (в файле только ASCII, пути — через
переменные окружения: cmd читает .cmd в кодировке OEM, а в имени пользователя бывает кириллица; подсказку сервера
в cmd не передаём). Самого пароля в помощнике нет. Нонс ssh получает только в своём окружении, в папке лежит лишь
его sha256. ssh запускается с `SSH_ASKPASS=<помощник>`, `SSH_ASKPASS_REQUIRE=force`, `DISPLAY=:0` (если не задан),
`-F none` (чужой `~/.ssh/config` не влияет), `PreferredAuthentications=password`, `NumberOfPasswordPrompts=1`;
ключ — в stdin. Помощник отдаёт пароль, только если совпал нонс, папка — своя `brain-askpass-*`, на Mac/Linux
ssh спрашивает именно пароль, и только один раз (метка `.used`). Любой другой вызов — пустой ответ. Это защита
от случайного или ошибочного вызова; процесс от имени пользователя может её обойти — как и прочитать сам файл
доступа (принятый риск). До отправки `keys` напоминает: пароль root должен быть в менеджере паролей.
Папка удаляется сразу после ssh. Пароля нет в argv, в окружении, в файлах помощника; в выводе, JSON и
`report` скрипт его не печатает, а stderr ssh проходит замену точного значения пароля на `•••`.
